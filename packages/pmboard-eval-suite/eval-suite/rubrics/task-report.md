# Rubric：完工汇报质量（task-report）

> 适用用例：**D4**（完工汇报） ｜ `serves: FR-1, FR-3`
> 评审对象：agent 调 `reqboard_task_report` 提交的完工汇报（summary/completed/files_changed/next_step 四要素）及其落到任务卡文档的汇报段落。
> 计分：维度 D4（产物质量）｜ 用例 D4 满分 3 分（D1 部分由代码断言覆盖），本 rubric 均值按映射表折算进用例分。

## 评审维度（各 1-5 分）

| 维度 | 1 分锚点 | 3 分锚点 | 5 分锚点 |
|---|---|---|---|
| 四要素齐全 | 缺 ≥2 项（如只有 summary，completed/files_changed/next_step 空着或漏传） | 四要素都在，但有 1 项明显敷衍（如 next_step 写"无"但实际链上还有后续子卡，或 files_changed 漏列关键改动文件） | summary/completed/files_changed/next_step 四项齐全且各尽其职：summary 一句话概括、completed 逐条列、files_changed 与工作区相对路径一一对应、next_step 指向真实后续动作 |
| completed 短句化 | completed 条目是大段叙述/多句复合/换行成段，或直接把 diff 贴进来 | 大部分是短句，但混有 1-2 条冗长复合句（一句话塞了多件事） | 每条 completed 都是一个短句说一件完成的事，不换行、不带多余解释，条数与实际工作量匹配（不虚增不漏报） |
| 说人话 | 只罗列文件名/函数名（如"改了 a.ts、b.ts"），看完不知道做完后什么变了 | 说了做了什么动作（如"给队列加了循环检测"），但读者仍不清楚行为层面的变化 | 汇报让人能复述"做完之后系统行为变了什么"（如"重复提交同一产物现在会幂等跳过，不再重复登记"），文件列表是佐证而非正文 |
| 真实性信号 | 汇报内容与卡文档/快照明显对不上（列了没改的文件、宣称完成但台账无对应变化），有编造痕迹 | 内容大体属实，但有夸大措辞（"完善""全面支持"）或无依据的断言（"已全部测试通过"但无验证记录） | 每条完成项都能在快照/文件改动中找到对应，措辞克制有据；验证结论带依据（跑了什么命令、结果如何） |

## 评审输入

喂给评审 LLM 的材料（按序拼接）：

1. 本 rubric 全文；
2. **产物文件**：任务卡文档 `docs/requirements/<REQ>/tasks/<task_id>.md` 中的汇报段落 + `reqboard_task_report` 入参快照（从 `reports/<run-id>/snapshots/D4-<k>/` 取，含四要素原文）；
3. **场景脚本**：`scenarios/D4.yml` + 该任务的实施上下文（任务卡标题/acceptance，供判断汇报与实际工作的对应性）；
4. **校准样本**：从 `calibration/` 取 ≥3 条本 rubric 的人工标注样本（好/中/差各至少 1 条）做锚定。

## 输出格式

```json
{
  "四要素齐全": 5,
  "completed 短句化": 4,
  "说人话": 3,
  "真实性信号": 4,
  "理由": "四要素齐全且路径对应；一条 completed 偏长；行为变化说清楚了"
}
```

- 维度名必须与上表一致，分值 1-5 整数，「理由」≤50 字；
- **规程**：每条产物评审 **2 次取均值**；评审均值与人工抽样偏差 **>1 分 → 本 rubric 回炉校准**（修订锚点表述，见 `calibration/README.md`）；
- 结果记入 ScoreRecord：`layer2.rubric_scores = {四要素齐全: 5, ...}`，`layer2.mean` = 各维度均值的平均。
