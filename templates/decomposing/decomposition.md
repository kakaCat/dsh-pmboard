- 一个任务只干一件事，标题动词开头。
- **落点** = 覆盖对照里出现过的编号 + 具体文件路径——不许写"相关模块"。
- **原型锚点 / 关联 D-x 两列（UI 需求必填，其余写「—」）**：
  - **原型锚点**（UI 卡必填）：形态 `prototypes/<name>.html#FR-N`，路径必须与 `prototypes/INDEX.md`
    的**权威行**一致（指向 `superseded` 版本 = 拒）。锚点是页面内区块的定位符，**不写进「覆盖条款」列**——
    贴锚点不等于覆盖了那条 FR。
  - **关联 D-x**：该卡承接的裁定编号（如 `D-1`、`D-4`），原文取自 `requirement.md` 的
    「讨论与裁定记录（D-x）」——**按编号取原话，不概括、不重写**。
  - 为什么 UI 卡必填：原型锚点缺了，实施就回到"凭印象画界面"；覆盖度会按卡点名（缺卡不静默）。
- **UI 卡的验收标准必须至少一条可失败的原型对照判据**：结构断言（区块存在 / 顺序 / 层级）+
  几何量硬判据（写明窗口宽与状态，量原型自身渲染）+ 对照截图（含差异说明）。
  只写"与原型一致"不算判据——不可证伪，等于没写。
- 工作量口径：S = 半天内 / M = 1~2 天 / L = 3 天以上。**L 不许直接落卡，先再拆**。
  要写得更硬的，可在 tasks[] 的 `footprint` 里声明三个可数确定量（`files` 要改的文件数 /
  `anchors` 验收锚点数 / `chars` 改动量）——超容量软门禁按它算「一轮装不装得下」，文档里这一列
  只给人看。`footprint.files` 不得小于「落点」列点到的路径数（声明缩水会被拒）。
- **依赖理由（`dep_reasons`，零交集边才要）**：`依赖` 列写了上游、但两端「落点」列的文件
  **零交集**时，门禁会点名「疑似伪依赖」（可并行的卡被串成链 = 白等一整轮）。确需串行的，
  在 tasks[] 该卡的 `dep_reasons` 里写一句语义理由：`dep_reasons: { "t2": "t2 重建队列文件，
  t4 读它，虽无同名文件但有时序约束" }`（键 = 上游计划 key）。写了理由就不再点名。
  注意：本列与 tasks[] 的 `depends_on` 都要写且一致——**落库只认 depends_on**，本列是人读的。
- 验收标准可证伪：跑什么命令、看到什么输出算过。
- **子卡段（可选，2026-09-28 起）**：落卡后每张卡会自动展开 2~4 段子卡（研发/联调/复核/测试）。
  - 不填 = 按**阶段**列兜底：doc → 研发+复核；test → 研发+复核+测试（验证卡无新接口，不落联调）；
    review → 复核；merge → 研发+复核；analysis → 取数+分析+复核；
    其余相位（implement / ui / data…）按**需求分类**的默认模板（feature/refactor = 研发→联调→复核→测试）。
  - 要精确控制：在 tasks 里写 `stages: ["dev","review"]`（**覆盖**默认，受控枚举、非空、去重）；
    或写 `skipIntegration: true` + `skip_integration_reason: "<一句话>"`（本卡无接口可联调 → 不落联调段）。
    **理由必填**（缺了整份计划被拒）：砍联调段是减法，批的人要能复核依据——写清"为什么这张卡没有
    接口面、靠什么判断"（例：「纯文档卡，无运行时接口」「本卡只加内部函数，没有调用方」
    「只改 CI 脚本，不进 HTTP 边界」）。段序口径：复核在前、测试在后。
  - 为什么要写：同一需求里所有卡默认吃同一套段，一张"零调用方"的新增卡会白跑联调段。
    （实测 2026-09-28：6 张联调卡 19.2 min 零文件产出 ≈ 该需求有效执行时间的 34%。）

## 覆盖完整性规则

1. **每行三格不许空**：接口 / 页面模块 / 用例任一为 0 → **不批准**，除非该行是纯文档条款
   （写 "—" + 一句话理由，如"纯 CI 脚本无运行时接口"——括号注、阶段豁免不算理由）：
   - 缺接口/页面模块 → 回退 design 补设计文档；或回 requirement 砍/改条款；
   - 缺测试用例 → 回退 design 补 test-cases.md；
   - 缺接收任务 → 本计划补任务（不许先批后补）。
2. **反向也要查**：设计文档/用例表里的编号在覆盖对照没人认领 = 超范围设计——
   删掉，或回 requirement 补条款。
3. 每个 FR-x 必须有人接——孤儿条款看板标红；任务卡 requirement_refs 悬空引用会被拒。
