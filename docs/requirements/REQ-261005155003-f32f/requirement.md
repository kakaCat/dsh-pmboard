# 需求说明（REQ-261005155003-f32f 需求详情页 UI 优化：可访问性达标 + 视觉语言收敛）

> 本文档面向：产品、开发、测试、用户——**写给人看，不是写给代码看**。
> 本次**不改信息架构、不改取数、不改写路径**：页面结构与数据契约冻结，只优化「看得见、看得清、
> 摸得着」的那一层（图形、对比度、焦点、目标尺寸、动效、字阶节奏）。

## TL;DR

- **这是什么**：对看板「需求详情页」（常驻头部 + 状态带 + 六个同级 Tab）做一次**视觉与可访问性**优化。
- **为什么现在做**：页面上一轮（REQ-261004222448-292a）已经把**信息架构**做对了，但**呈现层**还停在那里：
  全仓样式里 `:focus-visible` 命中数 **0**、`report` 分片里 `transition` 命中数 **0**、
  `prefers-reduced-motion` 命中数 **0**；Tab 图标是 emoji（跨平台字型不一致、不受颜色令牌控制）；
  三级文字色 `#9aa0a6` 在白底上实测约 **2.6:1**（低于 4.5:1）却用于真文字。
  这些都不是"审美偏好"，是**可判定的缺陷**（对着 [ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 的规则逐条比对得出）。
- **做完得到什么**：键盘能走完全流程且看得见焦点；弱视/深色主题下文字读得出；小控件点得中；
  图标风格统一、跟着主题变色；Tab 有自己的语义与方向键；动效有节奏且尊重"减少动态效果"；
  三档文字色阶与 4/8 间距栅格收敛成一套可复述的规则——**且首屏预算不回退**（Tab 栏仍在首屏内）。

## 产品定义

**一句话**：这次不重做页面，而是把页面的**外观层**提到与信息架构相称的水准——
**看得清（对比度与字阶）、走得通（键盘与焦点）、点得中（目标尺寸）、翻得动（语义与方向键）、
不刺眼（动效与减少动态效果）**。

**为什么要用「规范」而不是「我觉得好看」**：外观改动最容易变成各人各说。本次的全部改动逐条挂在
[ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)（MIT，本仓 `skills/ui-ux-pro-max/` 已 vendored）的
**可判定规则**上——对比度 4.5:1 / 非文本 3:1 / 目标 ≥24×24 CSS px / 焦点环可见 / 禁止 emoji 当结构图标 /
动效要有令牌并尊重 reduced-motion / 字号要有模数。**规则能查表，分歧就能收敛**。

### FR-1: 结构图标改内联 SVG

**功能描述**：详情页里**承担结构语义**的图标（Tab 栏六个：汇报/文档/DAG/对话/Token/提示词）从 emoji 换成
**内联 SVG**，落在一个新模块 `src/client/icons.ts`（唯一图标源）：

1. **图标族单一**：一套线性图标，统一 `viewBox="0 0 16 16"` / `stroke-width="1.5"` / `stroke="currentColor"` /
   `fill="none"`（线宽与网格是全族常量，不是每个图标各写一套）；
2. **尺寸走令牌**：图标尺寸只允许 `--pm-icon: 14px`（Tab 栏）与 `--pm-icon-sm: 12px`（行内）两档，不出现第三种；
3. **颜色跟随文字**：`currentColor` —— 选中态由 `.dsh-pm-tab.active` 的颜色决定，图标不需要自己的配色规则；
4. **可访问性**：图标旁**总有可见文字**（Tab 名）→ 一律 `aria-hidden="true"`；不出现"只有图标没有名字"的控件；
5. **不引入新依赖、不引入网络资源**：SVG 以字符串常量内联（与全仓"纯字符串渲染"一致），不装图标库、不用 icon font。

**为什么**：emoji 的字型由系统决定（本机是彩色 emoji，别的机器可能是黑白字形），**不受 `color` 与主题令牌控制**，
也无法与线条风格统一；规范里"禁止 emoji 当结构图标"正是这一段（`skills/ui-ux-pro-max/references/pro-rules.md`
§Icons & Visual Elements「No Emoji as Structural Icons」）。

**范围限定（按实际代码点清，避免"顺手改错东西"）**：

- **要改**：① Tab 栏六个图标（`report-tabs.ts` 的 `TAB_ICONS`）；② 面板内**重复 Tab 图标**的结构标记
  （`panels/prompts.ts:282` 的 `🧱 A · 固定系统提示词`——它顶着 Tab 的图标，Tab 换 SVG 后必须一起换或去掉）。
- **不改**：所有**状态符号**（`✅ 成功` / `✅ 通过` / `✅ 无缺口` / `⚠️` 这类）——它们是"颜色之外的第二判据"，
  正是 FR-8 要的东西；换掉它们反而破坏 FR-8，且牵动多处既有断言。
- **不改**：看板其它页面（卡片徽标 `PM_TOOL_BADGE` = `📋 PM · `、toolviews 卡片图标、
  卡面 `🪙 1.2M` 徽章）——它们是**别的页面**的图标，属「边界」第 3 条排除范围。

**验收锚点**：
- `grep -rn "📋\|📄\|🕸\|💬\|🪙\|🧱" src/client/views/report-tabs.ts src/client/views/panels/` 在**结构位**上归零
  （装饰性正文里的 emoji 不受此判据约束，由实现注释逐处列明）；
- 渲染产物中每个 Tab 含且仅含 1 个 `<svg ... aria-hidden="true"`；
- 探针实测：Tab 栏内 `<svg>` 的 `width/height` 均等于 14px（±1）。

### FR-2: 键盘焦点可见

**功能描述**：详情页所有可聚焦元素（按钮、Tab、胶囊、链接式按钮、输入框、`summary`）在**键盘聚焦**时
显示统一焦点环：

1. `:focus-visible` 生效（鼠标点击**不**留焦点环；`focus-visible` 不可用的回退是 `:focus` 但需去环于鼠标路径）；
2. 形态与宿主配方一致：宿主自己的写法是
   `outline: var(--dsw-focus-ring-width) solid var(--dsw-focus-ring-color, var(--dsw-alias-state-business-primary)); outline-offset: -2px`
   ——本页取 **2px 实线 + 2px 偏移**，颜色用岛内**文字级主色** `--pm-accent-text`（白底 5.72:1；不引宿主的
   `--dsw-alias-state-business-primary`，它在宿主深色下是浅蓝 `#7aaaff`，白岛上对比不足）；
3. **不被裁切、不被遮挡**：焦点环在溢出容器边缘不被 `overflow` 吃掉，也不被粘性元素盖住；
4. **宿主两套主题下同判**：焦点环颜色与背景对比 ≥3:1（浅色岛上取 `--pm-accent-text` = 5.72:1）；
5. **偏移分两档（照宿主口径）**：**面状控件**（Tab、卡片、整块面板）用 `outline-offset: -2px`（内偏移，
   不撑出额外方框、不挤动相邻元素）；**小控件**（按钮、胶囊、输入框）用 `+2px`（外偏移，环更清楚）。
   原型出图里 Tab 上那个方框是焦点环的**演示**（`data-proto-focus="1"`），**不是默认外观**——
   默认只有蓝色文字 + 蓝色下划线。

**为什么**：全仓 `:focus-visible` 命中数为 0 —— 键盘用户完全看不到焦点落点（WCAG 2.4.7 焦点可见；
规范 §1 Accessibility「Focus States」/「Focus Appearance」）。

**验收锚点**：
- `grep -rc "focus-visible" src/client/styles/` ≥ 1 且覆盖 FR-2 声明的全部控件类；
- 探针新增断言：对清单里的每个控件 `el.focus()` 后取计算样式，`outlineWidth ≥ 2px` 且 `outlineColor`
  与背景对比度 ≥3:1（浅/深两套各跑一次）。

### FR-3: Tab 栏语义与键盘

**功能描述**：六个 Tab 从"一排普通按钮"升级为**标准 Tab 组件语义**：

1. 容器：`role="tablist"` + `aria-label`（如「需求详情分区」）；
2. 每项：`role="tab"` + `aria-selected="true|false"` + `aria-controls="<面板 id>"`；面板容器 `role="tabpanel"` +
   `aria-labelledby="<tab id>"`；
3. **roving tabindex**：选中项 `tabindex="0"`，其余 `tabindex="-1"`（Tab 键在页面里只停一次，这一组内部用方向键走）；
4. 键盘：`←/→` 切换相邻、`Home/End` 跳首尾；切换即触发**既有** `data-action="switch-tab"` 通道（不新造写路径）；
5. **对既有行为零回退**：懒加载与"未激活面板不在 DOM 里"的纪律不变——`aria-controls` 指向的面板在未激活时
   不在 DOM 中，故 `aria-controls` 用**稳定 id**（`panel-<key>`）声明，面板挂载时再带上同 id。

**为什么**：读屏用户现在听到的是"按钮"而不是"选项卡 3 / 6，已选中"；键盘也没有方向键路径。
仓内已有先例（`src/client/views/board.ts` 的视图切换用了 `role="tablist"/role="tab"`），本次是**对齐**而不是发明。

**验收锚点**：
- 渲染产物含 `role="tablist"`、每项含 `role="tab"` 与 `aria-selected`，选中项恰 1 个 `aria-selected="true"`；
- 探针驱动键盘：`focus` 到第一个 tab → `ArrowRight` → 焦点与 `aria-selected` 同时前移一格、面板切换；
- 未激活面板仍**不在 DOM**（沿用既有 A4 断言，不许因加了 ARIA 而整块渲染）。
- **已知耦合（实施时必须处理）**：既有断言按**属性顺序**做子串匹配——
  `tests/report-shell.test.ts:138` 匹配 `'class="dsh-pm-tab active" data-action="switch-tab" data-tab="trunk"'`。
  新增的 `role`/`aria-*`/`tabindex`/`id` 必须**追加在既有属性之后**（保住子串），或同步改该断言；
  二选一，实施汇报里必须写明选了哪个。

### FR-5: 交互目标尺寸

**功能描述**：详情页内全部可点击/可聚焦目标（含视觉上小但可点的）满足：

1. **≥24×24 CSS px**（WCAG 2.2 SC 2.5.8 Target Size (Minimum)，AA）——含窗口跳转胶囊、评论框提交按钮、
   行内"打开/查看"链接、Tab、动作按钮、`summary`；
2. 相邻目标之间 **≥8px** 间距（避免误触）；
3. **手段不设限但结果要真**：可以是加大内边距（视觉变大），也可以是**扩大命中区**（伪元素/hit-area 包裹），
   但判据量的是**命中区**而不是视觉框——不允许"视觉小、命中区也小"；
4. **不得以改变布局为代价**：加高不能让首屏预算破线（见 FR-7 的 `tabsTop ≤ 713`）。

**为什么**：小控件在触屏/触控板与运动障碍用户手里点不中；规范把"目标尺寸最小 24×24 CSS px"列为可判定项。

### FR-6: 交互反馈与动效令牌

**功能描述**：

1. 交互反馈**不是瞬变**：hover / active / focus 的颜色与边框变化用统一过渡（时长与缓动取自令牌，
   区间 **80–150ms**；不出现"每个控件一个时长"）；
2. 过渡**只动颜色/边框/透明度**，不动几何（不改宽高、不位移）——避免布局抖动；
3. **令牌单点**：时长与缓动在详情页根节点上以 `--pm-dur-*` / `--pm-ease` 定义，规则里不写裸数字；
4. **尊重"减少动态效果"**：`@media (prefers-reduced-motion: reduce)` 下取消非必要过渡与动画，
   **终态直接可读**（不是"变慢"，是不动）；
5. 过渡不得影响既有硬判据（几何量在动效前后一致）。

**为什么**：`report` 分片 `transition` 与 `prefers-reduced-motion` 命中数都为 0 —— 反馈瞬变、且对运动敏感
用户没有任何让步。规范 §7 Animation「Duration Timing」/「Reduced Motion」/「Motion Sensitivity」。

**验收锚点**：
- 静态：`report.ts` 分片里 `transition` 的时长取值全部来自 `var(--pm-dur`（无裸 ms 字面量）；
- 静态：分片含 `@media (prefers-reduced-motion: reduce)` 分支；
- 探针：模拟 reduced-motion 后取计算样式，`transitionDuration` 为 `0s`。

### FR-8: 状态不靠颜色单一表达

**功能描述**：所有**承载状态/严重度**的视觉，在颜色之外至少再给一种可辨标记：

1. 阶段条（`.dsh-pm-progress-dots`）：完成/当前/未开始除颜色外，用**形状或文字**区分
   （完成 = `✓` 前缀、当前 = `▸` 前缀、未开始不带；原型已实测 `completed=✓ / current=▸`）；
2. 缺口严重度（`GAP_DOT` 的 🔴/🟡/⚪）：除颜色外带**文本标记** `!!` / `!` / `·`；
   **并且把 emoji 圆点换成不依赖字体的圆形**（CSS 或 `aria-hidden` 的 SVG）——emoji 的
   字形/明度由系统字体决定，正是 FR-1 要除掉的那类不可控资产；颜色仍承载严重度（不违反"不只用颜色"，
   因为文本标记本身独立可读）；
3. 验收结论（pass/rework/pending）：除颜色外带**字形符号**（✓/↺/…）——符号是文字级元素，
   读屏能读（配 `aria-label` 或可见文字），不引入"颜色即信息"；
4. 已达标的部分（状态芯片本身**已有文字**）不动，不为了统一而制造改动；
5. **这些标记必须是真实内容，不能只是 CSS 伪元素**：`::before` 的内容**读屏不保证读到**
   （原型用 `::before` 受"同一份标本、只换 CSS 层"的约束）——实施阶段必须落成
   **真实文本节点**或 **`aria-hidden="true"` 的 SVG + 可访问名**。这条是硬约束，写进验收。

**为什么**：规范 §1「Color Only」（High）：不要只用颜色传达信息；现状缺口/结论/阶段条都以颜色为主。

**验收锚点**：
- 静态：阶段条三态与结论三态各自带非颜色标记（探针断言：对应元素内存在文本或 `svg` 子节点）；
- 探针：把详情页强制灰度（注入滤镜）后截图，**人工评审**：三态仍可区分（截图落 `evidence/`）。

### FR-9: 操作条动作布局（动作独占一行 · 身份行分行 · 窗口靠左）

**功能描述**：详情页常驻头部的操作条（`.dsh-pm-rh-bar`）里，动作按下面的规则摆：

1. **动作不拉伸**：动作区是弹性流而不是等宽栅格——按钮宽度就是内容宽度，不再被拉成"第 i/N 列"；
2. **按序紧挨**：非破坏性动作按 `actions[]` 顺序紧跟「本阶段操作」标签排（间距 `--s3` = 12px）；
3. ~~**破坏性动作推行尾**（用 `margin-left:auto` 推到动作区行尾）~~ —— **本项已被 D-7 修订**：

### FR-12: 视觉层级（"层次感"做成可测的）

**功能描述**：人给的**核心**反馈是「现在没有层次感，每个模块不够有层次」（D-7）。现版三条硬伤都有实测值：

| 硬伤 | 现版实测 | 为什么这是硬伤 |
|---|---|---|
| 字号对比太弱 | 页标题 20 ÷ 正文 13 = **1.54×** | 层级至少 1.8× 才有"标题感"；1.5× 读起来是"同一级里的两种字号" |
| 模块标题与正文**同号** | 模块标题 13/600 vs 正文 13/400 | 只有**字重**单通道 → 扫读时分不出"这是新模块" |
| 模块间距 ≈ 模块内间距 | 模块间 20px ÷ 模块内 12–16px = **1.25×** | 分组靠间距比（要 ≥3×）；1.25× 等于没有分组 |
