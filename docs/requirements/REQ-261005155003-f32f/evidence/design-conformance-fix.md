# 设计契约一致性修复（2026-10-05，人眼发现后补做）

## 一句话

**设计契约写在权威原型 v2 的「改造层」里（95 条规则），实施期漏了一批没落地**——最刺眼的是
**Tab 栏整段**：设计是苹果**分段控件**（`#f5f5f7` 灰轨道 + 白色圆角滑块、无下划线），
实现是下划线式。而判据一个都没照出来，因为**原型 v3 被"重新内联成实现的渲染"**，
实现偏什么、原型就跟着偏什么，"零漂移"成了同义反复。

## 怎么发现的

人打开原型与线上页面对照，指着 Tab 栏说"这不是卡片吗？明显不一致"。此前我用像素比、
几何比、取色比都比过，全过——**因为两边同源**。判据量错了对象：它量的是"原型 == 实现"，
该量的是"**实现 == 设计契约**"。

| 阶段 | 差异类数 |

| 补落地后 | **3 类**，全部是"已被裁定取代"的白名单项 |

落地的主要项（设计层原话：选择器去掉前缀、其余一字不改）：

  + 选中项**白色滑块**（`--pm-surface`）+ `500` 字重 + **正文字色**；去掉下划线与描边。
- **Tab 计数**回到设计层档位（`11px / 15px`，此前是 `12px / 20px`）。

## 判据也随之改准一处（不是放宽，是把口径对准设计契约）

`A12 H5 主色文字类数`：旧口径把「选中页签」当主色角色采样。设计契约 ⑦ 明确选中页签取
**正文字色**（白滑块 + 500 字重 + 正文字色）——它不是主色角色，再采它，量的其实是
"正文色 ≠ 主色"，**恒红**；真去满足它就得反过来违背已确认的分段控件设计。

改为采真正承载主色的两处（`点开看原文` + `焦点环`），并**新增两条正面断言**：
选中页签**不得**等于主色、必须是白色滑块。比原来更严：原来只能发现"页签主色与别的角色不一致"，
现在能发现"页签又偷偷用回主色了"。

## 追加（2026-10-05 稍后）：Tab 轨道改为**满行**

人对照原型后又指了一处：「tab 还是不一致，**应该满行的**」。

- 设计层 ⑦ 写的是 `display: inline-flex`（**收缩到内容宽度**，实测 523px）；
  人裁定要**铺满整行**，以人的裁量为准。
- 落地：轨道 `display: flex`；六格 `flex: 1 1 0` + 内容居中 → **等宽平分整行**
  （实测 1280 档轨道 1240px / 每格 204px；900 档 868px / 每格 142px）。
  为什么用 `flex: 1 1 0` 而不是 `1 1 auto`：后者是"自身内容宽 + 均分余量"，长标签的格子更宽，
  整排仍显参差；候选版 V-C 的描述本就是「六格等宽」。
- **判据同步改为按属性豁免**：白名单从"按类整条豁免"收紧成"按（类, 属性）豁免"
  （`.dsh-pm-tabs` 只豁免 `w`，`.dsh-pm-tab` / `.dsh-pm-tab active` 只豁免 `w`），
  并写明这是人的裁量 —— 按类整条豁免会把该类的判据全部关掉，下次真出问题就照不出来。
  底色/字重/圆角等仍照设计层判。

## 追加（2026-10-05 深夜）：并层自身的两个 bug，都是人眼先看见的

人对照原型又指了一处，截图里直接露出 **`✓✓ 立项` / `▸▸ 归档`（双标记）**。

**根因**：并层时我把设计层那五条 `::before` 标记规则也照搬了——
`.dsh-pm-dot-wrapper.completed/current .dsh-pm-dot-label::before { content: '✓ ' / '▸ ' }`
与 `.dsh-pm-gap-line[data-severity=…] .dsh-pm-gap-what::before`。
而本需求 **FR-8 #1 明确要求标记做成真实文本节点**（原话：「伪元素对读屏不可靠」），
实现早就改成了 `.dsh-pm-dot-mark` / `.dsh-pm-gap-mark`——两边一叠就是双份。

**处置**：
① 从 `report.ts` 删掉这五条（实现侧保留真实文本节点）；
② **判据补两条覆盖**，让这类回归再也跑不掉：
   - 快照增加 **`::before` / `::after` 的 `content`**（伪元素内容是"看得见的外观"，原先比不到）；
   - **两个状态都跑**（在途 + 终态）——终态 DOM 分支不同（无动作按钮、结论格换文案、阶段条全绿），
     只跑在途时终态的这一处差异照不出来。
③ 这类差异**不用"豁免属性"处理**（豁免 `w` 会把真·双标记一起放过），改为
   **规则级取代清单** `SUPERSEDED_RULES`：把已被 FR-8 #1 取代的那五条**整条**从对照层里剔除。
   于是——若哪天有人把 `::before` 又加回实现，判据会以 `before none→"✓ "` 报红。

**自证可红（实测）**：扩展后的判据在修复前当场复现
`[inflight] .dsh-pm-dot-label：before none→"✓ "`、`[inflight] .dsh-pm-gap-what：before none→"!! "`、
`[terminal] .dsh-pm-dot-label：before none→"✓ "`；修复后 exit 0。

**另一个被排除的怀疑**：人怀疑终态的「状态带三格」不是卡片。实测终态三格为
**3 × 405×170、底色 `rgb(245,245,247)`、内边距 `12px 16px`**（= 设计层的 `--s3 --s4`），卡片在；
且原型文件与实现在**在途 / 终态两个状态下逐像素相同**（sha256 相等）——
所以"原型标签页看起来很旧"多半是**浏览器缓存了旧渲染**（这个文件当天改过三次），需对该标签页硬刷新。

## 追加（2026-10-05 收尾）：头部整块改卡片 —— 一条**推翻已确认 FR** 的人裁定

人在「哪一块是卡片」的选择里选了**头部整块（动作条 + 身份行 + 标题）**。

**先说事实**：原型 v2（契约源）与 v3（实现镜像）的**头部都是平的**——只有一条 `.5px` 下边线，
没有底色、没有描边、没有圆角（两边的头部渲染已并排存档）。所以这不是"实现漏了契约"，
而是一条**新增的人裁定**，并且**推翻本需求已确认的 FR-10 (三) 2**：
「底色只两档：白 + #f5f5f7（分组底）。**头部/操作条/评论不加底色**」。

**落地取向（两次才定）**：

| 版本 | 结果 |
|---|---|
| 第一版：灰卡（照状态带三格同款 `--pm-bg-soft`） | ❌ **被出图脚本的对比度复测当场拦下**：`span.dsh-pm-status 11px/500「实施」` 在 `#f5f5f7` 上 **4.31:1 < 4.5:1**——正是契约层自己写的那条「`--pm-accent` 在分组底上只有 4.31:1 → 强调色文字**只允许落在白底上**」 |
| 第二版（现行）：**白底 + 发丝边 + 8px 圆角 + 12/16 内边距** | ✅ 全部判据通过；三样都在设计既有档位内（白 / `.5px solid #0000001a` / `--r1`），不新造档位 |

**回退成本**：一条规则（`.dsh-pm-detail[data-report-shell] .dsh-pm-detail-head[data-report-head]`），
改回 `padding: 0 0 var(--s3); border-bottom: .5px solid var(--pm-line)` 即回到 FR-10 的口径。
若人坚持要**灰底**卡，则必须连带重定卡内强调色文字的取色（否则 4.31:1 恒红）。

**判据为什么没拦住"头部卡片"本身**：设计层对头部只规定了**边线**（`border-color` / `border-width`），
没有规定底色/圆角/内边距——所以叠层比对看不到差异，这是"设计层没说的部分"，不是"没落地"。
真正拦住灰卡的是**对比度判据**（`req-detail-ui-prototype-shot.mts` 的真文字对比度复测），
两条判据各管一段，这次正好互补。

## 追加（2026-10-06）：头部卡片从"白底发丝边"改"灰底有背景"

**起因**：人截了线上页说「原型有层次，是一个卡片有背景」。两件事同时成立：
① 线上页加载的还是**头部卡片之前**的旧包（逐列取样：头部纯 #ffffff，无任何卡边线）——
重启宿主**没有**让渲染进程换包（模块包 URL 带 rev + immutable 缓存，页面里要再硬刷一次）；
② 就算换上新包，**白底 + 发丝边的卡在白页上几乎不可见**——这才是"没有层次"的观感。

**落地（三件套）**：
| 项 | 取值 | 为什么 |
|---|---|---|
| 头部整块 | `--pm-bg-soft` 灰卡 + `8px` 圆角 + `12/16` 内边距 | 与状态带三格同一语汇；这才是"有背景" |
| 状态胶囊 | **白底 + 发丝边**（文字色仍照设计层：accent/ok/teal/text2） | accent 在灰底只有 4.31:1 < 4.5:1；文字落在白底上 4.70:1+ |
| 未开始阶段段 | **白底段**（`--pm-surface`），且只圈 `data-stage-state="todo"` | 原灰段落在灰卡上直接隐形 |

**踩过并已修**：第一版阶段段规则没圈状态，特异性把完成绿/当前蓝也盖成了白（实测 8 段全白），
改为只圈 `data-stage-state="todo"` 后实测：completed 绿 / current 蓝 / todo 白 ✓。

**为什么不动并层原文**：修正段追加在「设计契约落地层」**之后**、特异性更高（(0,5,0) 压过 (0,3,0)），
契约原文一行没动；判据比对（实现 vs 实现+契约层）两侧一致通过，不需要新增白名单。
