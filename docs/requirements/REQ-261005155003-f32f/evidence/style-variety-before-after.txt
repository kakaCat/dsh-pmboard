**两处判据勘误（2026-10-05，owner 裁定；不是放宽，是把自相矛盾的判据改成可判定的）**：

① **字号：≤5 → ≤6 + 无阶梯外字号**。原表写的 ≤5 与 FR-12 的六档 `24/20/15/13/12/11`
   相抵（六档本身就 6 种）；交接复核时改准为「≤6 且不得出现阶梯外字号」。脚本按
   `FONT_LADDER = [11,12,13,15,20,24]` 逐值核对——比单看一个上限更严。
② **前景色：≤5 → ≤6 + 取值 ⊆ 色板**。FR-10（二）的色板自己列了 **6 种"允许承载文字"**的色
   （正文 / 次要 / 强调 / 危险 / **警告** / 成功），而那个 5 是在**还没有 FR-8 严重度着色**的
   标本上量的（当时缺口严重度是 emoji，不受 CSS 管）。FR-8 #2 明文要求缺口严重度
   「**颜色仍承载严重度**」→ `--pm-warn-text`（`#c93400`）必须留在黄色缺口上。
   所以判据改成两条一起成立：**种类 ≤6** 且**取值集合 ⊆ FR-10（二）色板**
   （`#1d1d1f / #6e6e73 / #86868b / #0071e3 / #d70015 / #c93400 / #1e7e34 / #ffffff`）。
   §二 的「改后 6」里第 6 种就是 `#c93400`；并且本条判据**比"只数种类"结实**：
   换一个阶梯外的色，不管落在文字上还是图标上都会红。
   配套两条硬判据：**三级色 `#86868b`（白底 3.62:1）不得承载看得见的真文字**；
   只出现在图标/装饰上的色**不计入**"前景色种类"（单列旁证）。
   归因与取舍的完整登记见 `evidence/a13-panel-findings.txt` 末尾。
