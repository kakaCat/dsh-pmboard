## UC-1 键盘与读屏用户走完「看阶段 → 切 Tab → 读缺口 → 点动作」 `serves: FR-1, FR-2, FR-3, FR-5, FR-8`

- **用例角色**：键盘 / 读屏用户（`requirement.md`「用户与角色」表第 1 行；现状全仓
  `:focus-visible` 命中数 **0**，`grep -rc "focus-visible" src/client/styles/` 无一行非零）。
- **前置条件**：详情页已挂载（`report` 已取到，`buildReportShell` 已产出四段）；全程不用鼠标；
  需求处于在途状态（`data-head-state="inflight"`）。
- **交互流程**：
  1. `Tab` 进入页面，焦点按 DOM 序落到「← 看板」→ 主操作 → …；**每一次聚焦都看得见环**——
     面状控件（Tab / 卡片 / 整块面板）`outline-offset: -2px`，小控件（按钮 / 胶囊 / 输入框）`+2px`，
     颜色 `--pm-accent-text`（= `--pm-accent`，白底 4.70:1，≥3:1）。
  2. `Tab` 在 Tab 栏**只停一次**（roving tabindex：选中项 `tabindex="0"`、其余 `-1`）→
     `←/→` 在六项间移动、`Home/End` 跳首尾；焦点与 `aria-selected` **同时**前移一格，面板随之切换
     （走既有 `data-action="switch-tab"`，不新造写路径）。
  3. 读屏在 Tab 栏听到「选项卡 1 / 6，汇报，已选中」；Tab 图标是 `aria-hidden` 的装饰性 SVG，不被念出
     （图标旁总有可见文字「汇报 / 文档 / DAG / 对话 / Token / 提示词」，不出现"只有图标没有名字"的控件）。
  4. 读「缺口」格：每条缺口除圆点颜色外带**文本标记**（`!!` / `!` / `·`）；阶段条完成 / 当前带
     `✓` / `▸` 前缀；验收结论带字形符号（`✓` / `↺` / `…`）——标记是**真实内容**，不是 `::before`。
  5. 目标尺寸：窗口胶囊与行内「点开看原文 →」的**命中区** ≥24×24 CSS px
     （基线实测 203.1×**20.5** / 71.2×**19.3**，`evidence/targets-and-fonts-baseline.txt`），相邻 ≥8px。
  6. 用 `Tab` 走到某动作按钮 → `Enter` 触发既有写路径（`move-req` / `plan-approve` / `verify-pass` …，
     通道与语义一字不改）。
- **异常流**：
  - **未激活面板不在 DOM** → `aria-controls` 指向的 id 暂时无对应节点：允许（面板挂载时带上同 id，
    见 `frontend.md`「状态管理」的稳定 id 约定）；**不许**为了 ARIA 把六个面板全渲染（会破既有 A4 断言）。
  - 焦点落在溢出容器边缘被 `overflow` 裁掉、或被粘性元素盖住 → 判缺陷（FR-2 ③）；修法是调整裁剪与层级，
    **不是**把环去掉。
  - 某控件在键盘路径下不出环 → 判缺陷：`grep -rc "focus-visible" src/client/styles/` 必须 ≥1，
    且覆盖 FR-2 清单里的全部控件类（`.dsh-pm-btn` / `.dsh-pm-tab` / `.dsh-pm-window` / `.dsh-pm-input` /
    `.dsh-pm-trunk-open` / `details.dsh-pm-fold > summary`）。
  - 某个目标仍 <24×24 → 探针打印「选择器 + 实测宽高」并以退出码 1 结束；例外**只许**"正文内联链接"
    （WCAG inline 例外），且写进断言代码、逐条给理由。
- **后置条件**：焦点、`aria-selected`、当前面板三者一致；页面滚动位置不因聚焦而跳动；
  六个 Tab 仍在首屏内（`tabsTop ≤ 713`）。
- **完成标志**：`npx tsx scripts/req-report-probe.mts` 的新增断言组退出码 0（焦点环 / 目标尺寸 /
  Tab 键盘前移 / 阶段条与结论的非颜色标记），每条打印实测值。

## UC-2 弱视 / 深色主题用户在低对比环境读同一页 `serves: FR-4, FR-8, FR-10, FR-12`

- **用例角色**：弱视 / 深色主题用户（`requirement.md`「用户与角色」表第 2 行）。
- **前置条件**：宿主在 `<html>` / `<body>` 上挂 `[data-ds-dark-theme]`；或屏幕对比度低、缩放 200%。
- **交互流程**：
  1. 页面**不跟随**宿主主题翻转：详情页是**浅色岛**（白底 + 深字），宿主浅 / 深两套下**同一副长相**；
     `--pm-text3` 不再引宿主的 `--dsw-alias-label-tertiary`（宿主深色时它是 `#adb2b8`，白底只剩 2.13:1）。
  2. **真文字**承载色只有两档，且都 ≥4.5:1：正文 `--pm-text: #1d1d1f` 16.9:1、次要 / 元信息 / 计数
     `--pm-text2: #6e6e73` 5.07:1；第三档 `--pm-text3: #86868b`（3.62:1）**只许非文本**
     （图标 / 装饰线 / 未激活描边）——它低于 4.5:1，**禁止承载真文字**。
  3. 主色**一个值**：`--pm-accent: #0071e3`（4.70:1，对文字与面**同时**达标）。
     面级用它（进度条 / 左边色条 / 边框 / 下划线 / 图标 / 焦点环），文字级槽位 `--pm-accent-text`
     保留、值 = `var(--pm-accent)`（选中 Tab / 链接 / 人名 / 行内「点开看原文 →」）；
     主按钮（白字压主色底）底色也用同一值（白字 4.70:1 ≥4.5）。**两级不必分**——FR-4 表里的
     `#2f5fd0`（5.72:1）与"面/文字两级"是 **D-5 之前**的取值，FR-10（D-5 之后）把强调色定成唯一
     `#0071e3`，且 FR-7 明写"取值以 FR-10 为准"（口径裁定见 `interfaces.md` 与 `frontend.md`）。
  4. 状态不靠颜色单一表达：阶段条 / 缺口严重度 / 验收结论各带图形或文本标记（同 UC-1 第 4 步）。
  5. 说明文字与计数不再用 9.5px：最小**真文字** 11px（基线最小 9.5px 的三处：
     `src/client/styles/report.ts:438` / `:644` / `:721`）。
- **异常流**：
  - `[data-ds-dark-theme]` 的覆盖块仍影响详情页 → **判失败**（浅色岛不该被宿主主题翻转）。
    机械证据：原型 `?theme=dark&v=next` 与浅色档出图 sha256 相同（K8 已声明**不许**拿 `?v=current` 当对照组）。
  - 某处仍保留 12% 同色浅底芯片 → 必须启用已备好的 tint 级令牌
    （`--pm-ok-text-tint #1e7d34` 4.55:1、`--pm-teal-text-tint #0d7789` 4.52:1、
    `--pm-danger-text #c7303e` 4.52:1）并重新实测——**不许靠"底色没了"默认过关**。
  - 非文本 3:1 的划线按"**是否承载信息 / 是不是识别该控件的唯一凭据**"判，不按元素类型判：
    纯装饰 hairline（现 `--pm-line` 1.25:1，另一档 `--pm-line-soft` 1.13:1 本次**删除**、统一到一档）
    与未开始阶段的进度段（1.24:1）
    **逐条豁免登记**；口径与宿主一致（宿主自己就是 `--dsw-alias-border-l1 #0000000a` 1.04:1 ～
    `l4 #00000029` 1.45:1），理由落 `frontend.md`「样式与主题」并存档。
- **后置条件**：两套宿主主题下详情页长相一致且全部达标；报表覆盖**组合背景**（芯片浅底 + 文字）
  与**反白关系**（白字压主色底），不只算"深字压白底"。
- **完成标志**：对比度脚本（新增，落 `scripts/`，读 `report.ts` 的令牌声明而不是复制值）退出码 0；
  `grep` 断言 `report.ts` 不再引用 `--dsw-alias-label-tertiary` 与四个不存在的令牌名
  （`--dsw-text-primary` / `-text-secondary` / `--dsw-accent` / `--dsw-bg-primary`）。

## UC-3 人（验收者 / PM）先扫层级，再判「行有没有弄错」 `serves: FR-1, FR-7, FR-9, FR-10, FR-12, FR-13`

- **用例角色**：人 = 验收者 / PM（`requirement.md`「用户与角色」表第 3 行）；反馈原话是 D-7
  「核心问题现在没有层次感，每个模块不够有层次」与 D-8「这里行弄错了，按钮和 id 不应该是一行的，
  窗口可以放到左边」。
- **前置条件**：需求在途（`implementing`）；1280 档视口（出图脚本口径 `--window-size=W,800`，
  实测视口高 713）。
- **交互流程**：
  1. 一眼看头部：**第一行 = 动作行**（「← 看板」/「提交验收」/破坏性动作，整行独占、左对齐，
     **不与身份行同排**）；**第二行 = 身份行**（`REQ-id · 阶段 · 分类 · 难度 · 停留/更新时间`），
     窗口按钮组落在身份行**靠左**位置（在「创建于 …」左侧），「创建于 …」仍在行尾右侧。
  2. 扫层级：页标题 24/600 ÷ 正文 13/400 = **1.85×**（判据 ≥1.8）；模块之间 36px ÷ 模块之内 8–12px
     **≥3**；模块标题 15/600 与正文 13/400 **字号与字重都不同**（双通道，不许只靠字重）。
  3. 状态带三格三档字号、两两差 ≥2px（标签 11 / 主值 20 / 细节 12）。
  4. 全页**主色文字 ≤1 类**；胶囊只剩"状态 + 可点"两类（基线 17 个 → 实测 1）；圆角 ≤2 档；边线色 ≤2 档
     （同一标本 1280 在途态七项复测表，见 `evidence/style-variety-before-after.txt`）。
  5. 破坏性动作仍排**最后一个**，与其前一个动作留 **≥24px** 明确空隙（或 1px 竖分隔线 + 两侧各 12px）；
     「需人工确认」紧随其后。**不追求把空白填满**——规范要的是"被分开"。
  6. 详情页**没有**评论输入框；「最近评论 N 条（新的在下）」只读列表仍在（读得到"人说过什么"）。
  7. 操作条**没有**「本阶段操作」；主操作后果不常驻（悬停 `title` 可见全文，读屏经 `aria-describedby`
     指向的 `sr-only` 节点可读）；行尾标是「需人工确认」。
- **异常流**：
  - 动作行与身份行同排，或身份行跑到动作行之上 → 破 D-8：断言 ①`actionRowTop < identityRowTop`、
    ②两行 `top` 差 **≥8px** 报红（原型实测 44 < 77，差 33px）。
  - 窗口组跑到「创建于 …」右侧 → 破 D-8：断言 ③`windowLeft < createdAtLeft` 报红
    （原型实测 516 < 1142）。
  - 1 / 2 / 3 个动作三个变体下，主操作左缘或破坏性动作右缘**不同** → 判"位置随动作数量漂移"报红
    （改前就是"第 i 列决定位置，N 变则位置变"）。
  - 终态（`archived` / `canceled` / `done`）：只留「← 看板」，不渲染动作条 / 窗口跳转 / 评论输入框——
    **不留假出口**；评论**列表**仍渲染（只读不等于看不见）。
  - 某个模块只靠一条 hairline 分隔、没有 36px 间距 → 判不达标：每个模块**必须同时**具备
    "36px 模块间距"与"标题行"两个边界信号。
- **后置条件**：人给出"层次感"与"行有没有弄错"的裁决；before/after 成对图落 `evidence/`
  （`ui-before-*` / `ui-after-*`，同宽同状态）。
- **完成标志**：出图脚本打印七项多样性复测表（任一项超上限即退出码非 0）+ H1～H5 全过 +
  D-8 三条几何断言全过。

## UC-4 运动敏感用户与低反馈环境 `serves: FR-6`

- **用例角色**：运动敏感用户（系统开启「减少动态效果」）。
- **前置条件**：`prefers-reduced-motion: reduce` 生效。
- **交互流程**：
  1. hover / active / focus 的颜色与边框变化**不是瞬变**：统一过渡，时长与缓动取自详情页根上的
     `--pm-dur-*` / `--pm-ease`（区间 **80–150ms**），不出现"每个控件一个时长"。
  2. 过渡**只动** `color` / `background-color` / `border-color` / `opacity` / `box-shadow`，**不动几何**
     （不改宽高、不位移）——避免布局抖动。
  3. reduced-motion 下取消非必要过渡与动画，**终态直接可读**（不是"变慢"，是不动）。
- **异常流**：
  - 规则里出现裸 `ms` 字面量 → 静态断言失败（时长必须写成 `var(--pm-dur`）。
  - 过渡动了几何 → 判失败（几何量在动效前后必须一致，且不得影响 `tabsTop` 等既有硬判据）。
  - **本机量不到"非 reduce 下不是瞬变"**：本机 headless Chrome 的 `prefers-reduced-motion` 恒为 reduce
    （`--force-prefers-reduced-motion=no-preference` 压不住）→ 判据拆开：
    FR-6 ④ 用**计算样式**断言（`transitionDuration` 为 `0s`），FR-6 ①②③（共享令牌 / 无裸 ms /
    只动颜色不动几何）用 **CSS 文本静态**断言；脚本里写明哪条量到了、哪条只是读出来的。
    **不放宽阈值。**
- **后置条件**：动效有节奏且尊重系统设置；`report` 分片的 `transition` 与 `prefers-reduced-motion`
  命中数不再为 0（基线两条都是 0）。
- **完成标志**：`grep` 断言 + 探针计算样式断言同时绿。

## UC-6 动作数量变化与终态只读（位置不漂移的现场） `serves: FR-9, FR-11, FR-13`

- **用例角色**：实施窗口 agent（构造标本变体）+ 人（读结果）。
- **前置条件**：同一份标本数据，注入 1 / 2 / 3 个动作各渲一次（变体做法由 `test-cases.md` 定，
  探针侧实现）；另跑一次终态标本。
- **交互流程**：
  1. 三个变体各量一次：主操作 `offsetLeft`、破坏性动作右缘、动作按钮 `offsetTop` 取值集合。
  2. 判据：主操作左缘**恒等于动作组左端**；破坏性动作恒在**最后一个**且与前一个动作间距固定；
     1 / 2 / 3 个动作下这两处位置**逐个相同**；动作按钮在同一行内 `offsetTop` **只有一个取值**。
  3. 终态标本：只渲染「← 看板」+ 一句「终态只读：已归档 / 已取消，无可执行动作」，
     评论列表仍在、评论输入框不在。
- **异常流**：
  - N 变则位置变 → 判红（这是 FR-9 的**要害**："位置由第 i 列决定"必须消失）。
  - 操作条整块高 >72px，或 `tabsTop >713` → 判红（非功能需求：只许更好）；
    删掉分组标签后操作条会更矮（基线 60px），首屏预算只会更宽裕。
  - **口径提示（留痕纪律）**：FR-9 原文第 3 / 5 项与历史实测表里的「破坏性动作推行尾
    `margin-left:auto`、`markerLeft - dangerRight === 12`」是 **D-4 时期**的机制，已被
    **D-7**（动作组移到卡片左上）与 **D-8**（动作独占一行 + 身份行另起一行 + 窗口靠左）取代：
    验收以 FR-9 第 7 项 + D-8 三条判据 + 动作仍同一行 + 整块高 ≤72px 为准；
    `markerLeft - dangerRight` **不再作为 D-8 之后的判据**（D-8 之后动作行不再以行尾为界）。
- **后置条件**：FR-9 的位置不变量成立；FR-11 的文案收敛不改变动作几何（主操作左移 ~76px 后判据仍成立）。
- **完成标志**：变体断言三次取值相同 + 终态断言（无 `.dsh-pm-comment-form`、无 `add-comment`、
  无动作条、评论只读行仍在）。
