FR-1 结构图标改内联 SVGP0

做了什么
Tab 栏六个结构图标从 emoji 换成内联 SVG（单一图标族）： viewBox="0 0 16 16"、fill="none"、stroke="currentColor"、 stroke-width="1.5"、圆角端点；尺寸只走 --pm-icon:14px（行内用 --pm-icon-sm:12px）， 不出现第三种；一律 aria-hidden="true"（图标旁总有可见文字）。 因为 currentColor，选中态图标跟着 Tab 文字一起变蓝 （.dsh-pm-tab.active{color:var(--pm-accent-text)}）——改前是"蓝字配琥珀色 📋"。 六个语义：汇报=清单/段落 · 文档=纸页 · DAG=节点网络 · 对话=气泡 · Token=圆环硬币 · 提示词=>_ 终端提示符。 正文里的 emoji（💡 / 🤖 / 🔴 / ✅ …）是内容，一个字都没动。
规范出处
references/pro-rules.md §Icons & Visual Elements： 「No Emoji as Structural Icons」（emoji 依赖字型、跨平台不一致、不受设计令牌控制）、 「Consistent Icon Sizing」（尺寸必须是令牌）、「Stroke Consistency」（同层线宽一致 1.5px）、 「Icon Contrast」（有意义的图标与相邻色 ≥3:1）、「Contextual Semantics」（旁有可见文字 → 对辅助技术隐藏）。 references/quick-reference.md §4 no-emoji-icons / icon-style-consistent、 §1 icon-context。
看哪一处
六个图标：.dsh-pm-tabs[data-report-tabs] .dsh-pm-tab .dsh-pm-tab-icon svg； 选中态跟色：.dsh-pm-tab.active .dsh-pm-tab-icon svg（描边取自 currentColor）。 对照：把 URL 的 v=next 改成 v=current，同位置就是六个 emoji。
怎么验证
出图脚本断言：每个 Tab 内恰有 1 个 svg[aria-hidden="true"]，且 getBoundingClientRect() 为 14×14（±1）；页内实测值见下方 proto-geometry 的 tabIconSvgW/H。键盘走一遍六个 Tab，看图标颜色是否跟着文字变。

FR-2 键盘焦点可见P0

做了什么
详情页内所有可聚焦元素（按钮 / Tab / 窗口胶囊 / 链接式按钮 / 输入框 / summary）统一 :focus-visible 焦点环：outline: var(--pm-ring-w) solid var(--pm-accent) + outline-offset: var(--pm-ring-offset)，即 2px 实线 + 2px 偏移； FR-10 ⑨ 另加苹果式 halo box-shadow: 0 0 0 3px rgba(0,113,227,.25)， 面状控件（Tab / 折叠条）用 -2px 内偏移、小控件 +2px 外偏移。 颜色用唯一强调色 #0071e3（白底 4.70:1 ≥3:1；FR-10 把主色从"面/文字两级"合成一个， 不用宿主的 --dsw-alias-state-business-primary——它在宿主深色下是浅蓝 #7aaaff， 白岛上对比不足（浅色岛口径的必然推论）。鼠标点击不留环（:focus-visible 语义），键盘一定可见。 原型为便于截图，另给第一个 Tab 挂了一个同款样式的模拟焦点态（data-proto-focus="1"）—— 真实实现只留 :focus-visible 那一份（原型里那条也在，键盘过来同样出环）。
规范出处
quick-reference.md §1：focus-states（交互元素要有可见焦点环，2–4px）、 focus-appearance（焦点指示器与相邻色 ≥3:1，「看得见」还不够）、 focus-not-obscured（WCAG 2.2 AA：粘性 UI / 覆盖层不得遮住被聚焦控件）； pro-rules.md §Interaction「Accessibility focus」。 需求文档 FR-2 亦与宿主配方对齐（宿主是 outline + outline-offset，本页取 2px + 2px）。
看哪一处
规则：.dsh-pm-detail[data-report-shell] :is(a[href],button,input,textarea,select,summary,[tabindex]):focus-visible； 截图里那一个：.dsh-pm-tab[data-proto-focus="1"]（第一个 Tab「汇报」外圈蓝环）。
怎么验证
键盘按 Tab / Shift+Tab 走十个控件，看环是否出现、是否被裁（壳左右内边距 20px > 2px 偏移， 且 outline 不参与布局、不产生滚动溢出）；?v=current 下同一次走查只剩浏览器默认环（对照）。

FR-3 Tab 栏语义与键盘P0

做了什么
Tab 栏补标准 Tab 组件语义：容器 role="tablist" + aria-label； 每项 role="tab" + aria-selected="true|false" + aria-controls="panel-<key>" + id="tab-<key>" + roving tabindex（选中 0、其余 -1）；面板 role="tabpanel" + aria-labelledby="tab-trunk" + id="panel-trunk"。 只加属性：data-* 面板契约与 DOM 结构一字未动， 未激活的面板照旧不在 DOM 里（aria-controls 用稳定 id 声明，面板挂载时再带上同 id）。
规范出处
quick-reference.md §1 aria-labels / keyboard-nav（Tab 顺序与视觉顺序一致、 完整键盘可达）；pro-rules.md §Interaction「Semantic native controls」（优先带语义的原生控件）； WAI-ARIA Tabs 模式（tablist/tab/tabpanel + 方向键）。仓内先例：src/client/views/board.ts 的视图切换已经这么写，本次是对齐不是发明。
看哪一处
.dsh-pm-tabs[role="tablist"] · .dsh-pm-tab[role="tab"][aria-selected] · [role="tabpanel"][aria-labelledby="tab-trunk"]（当前只有 trunk 面板在 DOM）。
怎么验证
DevTools 的 Accessibility 面板读 role / selected / controls；或 document.querySelectorAll('[role=tab][aria-selected=true]').length === 1； ?v=current 下这些属性不存在（对照）。方向键的行为（←/→/Home/End 切 Tab） 由实施阶段接既有 data-action="switch-tab" 通道完成，原型不含写路径。

FR-4 浅色岛令牌口径 + 文字对比度达标P0

做了什么
① 令牌自持：整组 --pm-* 全部取浅色原值，不引任何宿主主题变量 （改前 --pm-text/-text2/-accent/-surface 引的 --dsw-text-primary 等四个名字 在 DSH 里根本不存在 → 回退值恒生效；而 --pm-text3 引的 --dsw-alias-label-tertiary 存在，宿主深色下是 #adb2b8， 白底上只剩 2.13:1 —— 这就是 K2「白岛 + 深色主题浅灰字」的现场）。 ② 主色分两级（FR-10 已把这两级合成一个苹果系统蓝 #0071e3：白底 4.70:1，当字当底都达标；旧值 --pm-accent(#4a7dff) 当"面"、 --pm-accent-text(#2f5fd0) 当"字"——下面几张表的"改后"列因此是 FR-4 那一轮的记录，当前值以 FR-10 区块为准）。 ③ 移除"半个主题"残留：删掉 [data-ds-dark-theme] .dsh-pm-detail[data-report-shell] 那组覆盖—— 它把岛内语义前景色翻成暗色主题值（白底上 --pm-danger 从 4.53:1 掉到 3.54:1）。 原型不能"删"上游 CSS，只能用同特异性 + 后置把它按回浅色原值（这就是"移除"的等价物； 真实实施是整块删除）。怎么亲眼看这件事：开 ?theme=dark&v=current ——状态带三格的小标题变成 2.13:1 的浅灰；再切 ?theme=dark&v=next ——同一副长相且达标。
规范出处
quick-reference.md §1 color-contrast（正文 ≥4.5:1，大字 ≥3:1）、 §6 contrast-readability、color-accessible-pairs（前景/背景对必须实测）、 color-semantic（用语义令牌而不是散落裸色值）； pro-rules.md §Light/Dark Mode Contrast「Text contrast (light) ≥4.5:1」、 「Border and divider visibility」、「State contrast parity」（两套主题下互动状态同样可分）、 「Scrim and modal legibility」（要量合成结果，不能只量纯底）。 WCAG 2.1 SC 1.4.3（文字 4.5:1）/ SC 1.4.11（非文本 3:1）。
看哪一处
令牌：.dsh-pm-detail[data-report-shell] 上的 --pm-* 组； 文字级主色的三处落点：.dsh-pm-tab.active、.dsh-pm-evidence、 .dsh-pm-comment-who[data-actor="human"]；状态芯片文字：.dsh-pm-status； 三级灰的两个落点：.dsh-pm-stat-label（真文字，用 --pm-text3）与 .dsh-pm-stat 的左边色条（非文本，用 --pm-text4）。
怎么验证
