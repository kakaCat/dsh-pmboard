# REQ-261001110934-3766 代码知识库：让 Agent 少 token 快速理解项目（含归档/回档）

> 档位：**重档**（新增知识层子系统 + 多个未定决策点；本需求由轻档**单向升级**而来）· 类型：feature

## TL;DR

本插件已经会把「一个想法」推到「归档」，但**归档之后知识就死了**：需求目录越堆越多（11 个目录 / 8.9 万字符最大一个），
归档索引只有一份**格式模板**（`templates/archived/index.md` 写着「追加进 requirements/INDEX.md」），**没有写入者、没有读取者、没有检索入口**；
而 Agent 侧每次要认识项目，只能靠把文档或源码**整份读进上下文**——实测源码 199.7 万字符（≈66 万 token）、
文档 45.4 万字符（≈30.2 万 token），任何一次「先读一读」都是灾难级的 token 开销。

要做的事一句话：**给项目加一层「可生成、可检索、有预算、会自我防腐」的知识层**，
让 Agent 用「索引 + 指针 + 按需展开」的方式认识项目和读历史决策，而不是把仓库塞进上下文。

**按人工门反馈（2026-10-01）补充的三块知识域**（原稿只写了「决策/坑 + 代码地图」，缺了它们）：

| 知识域 | 现在的载体（实测，字符口径） | 缺什么 | 补齐方式 |
|---|---|---|---|
| **架构** | `README.md` 四层图（20 行）+ `docs/architecture/` 4 篇（9,083 字符） | 分层职责/依赖方向/关键模块与扩展点**不成体系**，无索引 | 架构条目 + 分层图进知识索引（FR-8） |
| **代码规范** | 散在 **277 个测试文件（1,863,900 字符）** + 9 个脚本（50,668 字符）+ 模块头注释 + 注入铁律；**无 CONTRIBUTING / 无规范索引** | 新 Agent 无法在少 token 内知道「本仓有哪些硬纪律、违反了哪条测试会红」 | 规范条目，**每条挂可执行校验命令**（FR-9） |
| **前端样式与颜色** | `src/client/styles*.ts` **12 文件 / 129,888 字符**（≈1,025 个规则块）：**67 种颜色**（529 处）、**35 个 CSS 变量**、**545 个 `dsh-pm-*` 类名**、4 档断点（1180 / 1200 / 880 / 768） | 改一处 UI 要先吞下 13 万字符 CSS，或者靠猜 | 设计令牌地图（颜色/变量/断点/类名，确定性抽取）（FR-10） |

```
        今天                                   本需求之后
┌──────────────────────────┐          ┌──────────────────────────────────┐
│ 归档 → 文档躺在需求目录里  │          │ 归档 → 强制沉淀成知识条目 + 索引行 │
│ 新窗口 → 整份读文档/源码   │          │ 新窗口 → 读索引(≤8K字符) → 按需展开 │
│ 知识 = 文档 / 靠人记得     │          │ 知识 = 条目 + 指针(路径/符号/REQ)  │
└──────────────────────────┘          └──────────────────────────────────┘
      token 成本 = 仓库体积                  token 成本 = 索引 + 命中的那几条
```

## 产品定义

「项目知识库（Knowledge Base）」= 本仓落盘、由工具维护、**总量有预算**的一层知识与地图，
服务于两种场景：

1. **冷启动认知**：新会话/新窗口的 Agent 要在**几千 token 内**知道「这个项目是什么、代码在哪、有哪些硬契约与坑」；
2. **回档/复用**：需求走完归档后，它的结论、决策、坑变成**可检索的短条目**，被后来的需求引用，
   而不是躺在一个没人再打开的目录里。

它**不是**向量数据库、不是 RAG 服务、不是新的一堆文档——它是「**索引 + 条目 + 生成物 + 检索工具**」四件套，
每一件都有字符预算与失效自检。知识域按**八类**收（`kind`）：架构 `architecture` / 规范 `standard` /
前端令牌 `tokens` / 决策 `decision` / 踩坑与被证伪假设 `pitfall` / 硬契约 `contract` / 代码地图 `map` / 术语 `glossary`。

| 知识域 | 回答什么问题 | 默认载体 | 预算 |
|---|---|---|---|
| 架构 | 分几层、依赖往哪边、改哪里会破界 | `architecture.md` + 条目 | ≤200 行 |
| 规范 | 有哪些硬纪律、违反了哪条测试会红 | `conventions.md`（每条挂命令） | ≤200 行 |
| 前端令牌 | 用哪个颜色/变量/断点/类名，别自己造 | `design-tokens.md`（生成物） | ≤200 行 |
| 决策/坑/契约 | 为什么这么做、踩过什么、被证伪过什么 | `entries/<kb-id>.md` | 单条 ≤200 行 |
| 代码地图 | 符号在哪个文件、角色是什么 | `code-map.md`（生成物） | 全量 ≈4% 量级 |

## 用户与角色

- **新窗口的 Agent（主用户）**：只拿索引与指针就能开工，需要时按 id/符号/关键词取一条，而不是被灌整份文档。
- **前端维护 agent**：改 UI 前先读 `design-tokens.md`（≤200 行）拿到颜色/变量/断点/类名，而不是读 13 万字符 CSS 或自造颜色。
- **实施 agent（规范消费者）**：开工前读 `conventions.md`，按每条挂的校验命令自证；违反纪律时能直接引用条目 id。
- **会话里的用户（PM / 需求方）**：从看板「知识库」页一眼看到沉淀了什么；归档时不用自己记得去更新索引。
- **本插件维护者**：知识层必须有生成者、读取者与防腐门禁，否则第三个月就变成新的文档垃圾场。

## 接口与数据契约

**新增 Agent 工具（`src/tools` 现有 20 个 → 21 个；`README.md` 里「13 个」是过期口径）**：

```jsonc
reqboard_kb({
  query?: string,        // 关键词/问题片段；与 id/kind 至少给一个
  id?: string,           // 精确取某条（kb-xxxx）
  kind?: 'architecture'|'standard'|'tokens'|'decision'|'pitfall'|'contract'|'map'|'glossary',
  limit?: number,        // 默认 5，上限 20
  budgetChars?: number   // 默认 1500，上限 8000；不足则 truncated=true + 指针
})
→ { items: [{ id, kind, title, oneLiner, pointer, confidence, updatedAt }],
    truncated: boolean, budgetChars: number, hint?: string }
```

**落盘契约（新增路径）**：

| 路径 | 角色 | 谁写 |
|---|---|---|
| `docs/knowledge/INDEX.md` | 唯一认知入口（一行一条目，全份 ≤8K 字符 / ≤200 行） | 归档流程 + 生成脚本 |
| `docs/knowledge/entries/<kb-id>.md` | 知识条目正文（固定小节） | Agent（归档/实施时） |
| `docs/knowledge/code-map.md` | 代码地图（每文件一行 + 导出符号清单，生成物） | 生成脚本（可重跑、进版本控制） |
| `docs/knowledge/architecture.md` | 架构总览（分层图 + 各层职责 + 依赖方向 + 扩展点，≤200 行） | Agent（从 README/design 汇总）+ 自检反查 |
| `docs/knowledge/conventions.md` | 代码规范清单（**每条 = 一句话 + 校验命令/测试文件**，≤200 行） | Agent + 自检脚本反查测试与门禁 |
| `docs/knowledge/design-tokens.md` | 前端设计令牌（颜色 / CSS 变量 / 断点 / `dsh-pm-*` 类名，生成物，≤200 行） | 生成脚本（从 `src/client/styles*.ts` 确定性抽取） |
| `docs/knowledge/INDEX.md` 的「待写」节 | 缺口显式化（对齐 project-manual「待写页」） | 自检 / 人 |

**知识条目字段（头部即 front-matter 的替代，沿用本仓「标题 + `serves:` + TL;DR」习惯）**：
`id` / `kind` / `status(active|stale)` / 一句话结论 / 适用条件 / 证据指针（文件 + 行或 REQ id）/ 失效条件 / `supersedes` / `updated`。

**归档侧契约**：`reqboard_submit(kind=archive)` 的 `index_entry` 从「只进台账」升级为
「**写进 `docs/knowledge/INDEX.md` 的必填来源**」，`merged_into` 升级为条目的 `pointer`；
缺失即拒绝（沿用既有 `SubmitArchive` 的代码级拒绝风格）。

**迁移与兼容**：新增路径都是新增文件，不改任何既有产物格式；**老需求无知识条目 → 注入与交互逐字节不变**。
**回滚**：删掉新增目录 + 新工具注册 + 注入改造的三处补丁即可，无数据迁移。

## 功能点

- **FR-1: 单一认知入口（知识索引）** —— 落 `docs/knowledge/INDEX.md`：H1 + 一句话项目摘要 + 分节条目列表（每条一行：`id · kind · 一句话 · 指针`，单行 ≤200 字符），**全文 ≤8,000 字符且 ≤200 行**，超限由门禁拦下；它是 Agent 建立项目认知与回档的第一入口（对齐 `llms.txt` 与 Claude Code 目录预算 ≈1% 上下文的口径）
- **FR-2: 知识条目与固定字段** —— 每条一个 `docs/knowledge/entries/<kb-id>.md`，**正文 ≤200 行**，必填 `id / kind / status(active|stale) / 一句话结论 / 适用条件 / 证据指针 / 失效条件 / supersedes / updated`；`kind` 限定八类：architecture / standard / tokens / decision / pitfall / contract / map / glossary
- **FR-3: 归档即沉淀（写入者闭环）** —— `reqboard_submit(kind=archive)` 必须把 `index_entry` 落成索引行（缺失即代码级拒绝），使 `templates/archived/index.md` 这份**格式模板第一次拥有写入者与读取者**；复盘 `retro.md` 的「被证伪的假设 / 踩到的坑」按 kind=pitfall 入条目；新决策用 `supersedes` 指向旧条目，**索引只列 active**，且条目**只链接归档原文、不复制正文**（避免双份真相）
- **FR-4: 代码地图（签名级、生成物）** —— 由脚本产出 `docs/knowledge/code-map.md`：每文件一行（路径 · 角色一句话 · 导出符号名与签名摘要），支持按符号反查文件；规模对齐「骨架 ≈ 全量 4%」口径，可重跑、进版本控制、不依赖运行时新依赖
- **FR-5: 只读检索工具 `reqboard_kb`** —— 支持按 `id` / `kind` / `query` 取条目，**返回受 `budgetChars` 约束**：预算内回正文，预算不足回指针 + `truncated=true`，永不「把知识库整份倒出来」；工具 schema 与说明**保持短**（常驻成本按每轮计），且描述稳定以利于前缀缓存命中

## 边界

**做**：

1. 知识层落盘 + 生成脚本 + 检索工具 + 索引注入（含看板「知识库」只读页）
2. 归档流程改造：`index_entry` / `merged_into` 成为索引行与条目的强制来源
3. **四类新知识域落盘**：架构总览（FR-8）、代码规范清单（FR-9）、前端设计令牌地图（FR-10）、代码签名地图（FR-4）
4. 死链/孤儿/超预算/stale/生成物漂移五类自检 + 体积探针，进验收与门禁

**不做**：

1. **不引入向量库 / embedding / 外部检索服务**：只用本地文件 + 确定性字符串匹配（插件运行时零新增依赖）。
   依据：Anthropic 明确「**<20 万 token 直接整装 prompt + 缓存**」（延迟 ↓>2×、成本 ↓90%），本知识层目标 ≤8K 字符，检索是负收益
2. **不做自动代码摘要（LLM 批量生成）**：代码地图是**确定性生成物**（符号抽取），不额外烧 token 造知识。
   依据：结构性问答上 **AST 确定性图 > LLM 抽取图 > 纯向量**（纯向量幻觉风险最高）
3. **不改既有产物格式与状态机**：既有 20 个工具的 schema、台账字段、五道人工门、`rtm-*.yml` 一律不动
4. **不做全仓检索索引**（不替代 grep/glob）：知识层只索引「**人已经说清楚的结论**」与「签名骨架」，不索引源码正文
