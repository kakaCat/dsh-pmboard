# REQ-261010192903-fdda · pm 的 goal 串联机制（以 dsh goal 四件套为底本改造）

- 类型：feature（**Spike 先行**：对照实验结论已落本档「Spike 结论」节）
- 阶段：brainstorming
- 关联：平铺布局重构（19 组件包 + pm 主体包）为实施前置

## TL;DR

把 dsh 的 goal 插件（`packages/goal/`：goal 状态服务 + `tool-goal` 工具 + `command-goal` 命令 + `goal-round-driver` 驱动）
**作为底本改造**成 pm 的 goal 机制：goal 不再是一次会话一个的孤立目标，而是**贯穿「立项→需求分析→设计→拆分→实施→
验收→归档」全流程的管理单元**——一个阶段可由多个 goal 完成，goal 完成自动交棒下一个，跨窗口/跨会话不断档。

```
用户意图 ──► [goal₁: 需求分析] ─完成─► [goal₂: 设计] ─完成─► [goal₃: 拆分] ─► … ─► [goalₙ: 实施·卡i]
                 │持久·可跨窗口重建│                每段完成后自动开下一个（串联）
                 └──── 父子嵌套：「这条需求做完」父目标下挂各阶段子目标 ────┘
```

## Spike 结论（可行性对照实验 · 本阶段产出）

验证问题：dsh goal 四件套的状态模型与驱动语义，能否承载 pm 的四项缺口？

| 缺口 | dsh goal 现状（实测） | 判定 |
|---|---|---|
| 多目标串联 | 一次一个 goal（projection-key 为会话单例），complete 后无「下一个」 | **内核可复用，链要新建**：CAS/revision/phases 原样可用；「目标链」是新增领域对象 |
| 跨窗口持久续跑 | 状态从会话事件流 fold（`foldGoal(events)`），**可跨进程重建**；但激活权是进程本地的、不落盘 | **底座已支持**：激活权持久化与交接是改造点，不是重建点 |
| 阶段感知 | goal 无阶段概念（objective 为自由文本） | **需扩展**：goal 需持有 stageRef/requirementRef 引用 |
| 父子嵌套 | 无 | **需扩展**：parentGoalId + 链上事件 |

**一句话结论**：dsh goal 的内核（事件溯源 + CAS + 严格 fold）可直接作为底本；四项缺口全部集中在「目标链 + 激活权持久化 + 阶段/父子引用」这一层新增语义上；它**不取代** reqboard 台账（goal 链管推进，台账管审计真相）。这正面回应了 D-2「goal 服务不满足于 pm 的需求」——内核可复用，语义层自建。

## 产品定义

pm 的长期工作单元从「卡 + 回合」升级为「goal 链 + 卡」：goal 负责**持续推进到完成并自动交棒**，
卡负责**粒度内的验收与门禁**。跨窗口换人干活不再靠上下文拷贝，而靠 goal 的持久状态重建。

## 用户与角色

- **用户**：提需求、在人工门裁决、看验收单。
- **owner 窗口**：持有一条需求的当前 goal，负责推进与交棒。
- **接管窗口**：凭 goal 的持久状态接续推进（无需口述上下文）。

## 功能点

- **FR-1: 目标链服务**：一条需求挂一个 goal 序列；当前 goal 完成 → 自动创建/激活下一个（链可表示父子：全流程父目标下挂阶段子目标）。
- **FR-2: 持久激活与跨窗口交接**：激活权随 goal 状态落盘；窗口 B 接手时能原样续跑（含轮次预算与断点）。
- **FR-3: 阶段感知交棒**：goal 知晓自己在推进哪一阶段；阶段完成即触发下一阶段 goal（含人工门挂起为 blocked 而非静默）。
- **FR-4: 与 reqboard 桥接**：goal 推进通过 reqboard 现有工具面（move/report/submit）执行；台账格式与门禁不变。
- **FR-5: 收敛自造活性机制**：`wake-heartbeat` / `wake-liveness` / `wake-skip-trace` / `idle-capture-actions` 的职能由 goal 链承接或删除（零引用者删）。

## 边界

- 不做：不改 reqboard 台账格式与门禁语义；不引入新的外部服务；不动非 pm 的宿主机制。
- 底本以**源码拷贝 + 改造**方式进入本仓 `pm/` 主体或新增组件包（不进 vendor 镜像，因为要改语义）。
- 不做「并行多目标」——串联语义是单激活。

## 失败与并发路径

- 窗口中断/进程重启：凭事件流重建 goal 状态；重建失败 → 响亮报出，不静默重启 goal。
- 链上目标被拒/返工：goal 置 blocked（带 code+message），人在看板处置后 resume，不自动重试掩盖。
- 双窗口同时推进同一 goal：CAS（revision）拒绝后到者，报错带当前 revision。

## 验收（可执行）

- `pm/goal*` 包的测试：链的串联/父子/CAS/重建用例全绿（判据：命令行读数）。
- 端到端：起一条需求，只发「继续」，goal 链能从当前阶段自动推进到下一阶段的正确门口停下。
- 等价性：现有全量测试用例数不回退、失败集不超出基线清单。
