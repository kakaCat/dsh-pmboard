# 需求说明（REQ-261004184822-9881 看板泳道：刷新不丢位置 + 列高铺满）

> 本文档面向：产品、开发、测试、用户——**写给人看，不是写给代码看**。

## TL;DR

- **这是什么**：项目看板「泳道」视图有两处别扭——① 被自动刷新后横向滚到的位置被打回最左，刚在看的列又变回 draft；② 各状态列只包住自己的内容，下方留一大片空白。
- **为什么现在做**：需求一多，implementing / accepting 列必须横滚才看得到，而看板每 ≤20 秒或每次台账变更都整段重绘，等于每次都要重滚；列高不铺满则长列挤在小框里，看板看着像没做完。
- **做完得到什么**：滚到哪就停在哪（横向与列内纵向都是），列从顶部直通看板底部、列内自己滚。

## 产品定义

**一句话**：把看板泳道的「视图位置」与「数据」解耦（数据随时刷，位置不归零），并让列真正撑满可用高度——一个能长时间停在上面看的看板。

| 痛点（实测） | 本次解决 |
|---|---|
| 横滚到 implementing 列看卡，几秒后自己弹回最左（又看见 draft） | 重绘前记住、重绘后回填 `.dsh-pm-lanes` 的横向滚动位置（FR-1） |
| 自己点一次卡面按钮（也会触发重绘）位置就丢 | 同上：手动刷新、SSE 事件、操作后重绘一视同仁（FR-1） |
| 列内往下翻了几张卡，刷新后回到该列顶部 | 列内纵向滚动按列（`data-lane`）分别记忆并回填（FR-1） |
| 列只包住内容，下方一大片空白，长列无处伸展 | 列纵向铺满看板可视高度，列内卡片区自己滚（FR-4） |
| 位置这类「用户的选择」散落在 DOM 上，重建即归零 | 收敛成一处可测的记忆（作用域与隔离写死，FR-2） |

**与现状的区别**：

| 维度 | 现状 | 本次之后 |
|---|---|---|
| 泳道横向滚动位置 | `render()` 每次 `viewEl.innerHTML = buildBoard(...)` 整段重建 → `scrollLeft` 归零 | 重绘前后取值/回填，位置保持（被新内容裁剪时按新上限收敛） |
| 列高度 | 内容高 + 写死 `max-height: calc(100vh - 200px)`，下方留白 | 铺满泳道区可用高度（拉伸），列内滚动 |
| 同一类缺陷的处置 | 会话节点面板的「我切到泳道，一刷新又回到 DAG」是同一类问题，已由 `dag/view-state.ts` + `panel-hydrate.ts` 修过 | 看板泳道**复用同款做法**（内存记忆表 + 回填），不另起一套机制 |

```
        │
        ├── 当前行为：整段 DOM 重建 → scrollLeft 归零（用户看到「归位」）

        └── 本需求：重绘前取值 → 重绘后回填（超上限则裁剪）
                       │
                       ▼
             仍在 implementing 列，用户不必重滚
```

```
FR-4（列高）：
.dsh-pm-lanes（flex: 1，占据头部与归档条之间的全部高度）
   ├─ 现状：align-items: flex-start + 列 max-height: calc(100vh - 200px)
   │        → 列高 = 内容高，下方留一大块空白

```

### FR-1: 泳道滚动位置跨重绘保持（横向 + 列内纵向）

**功能描述**：泳道视图在屏时，用户滚到的位置（横向 + 每列内部纵向）不再被任何一次重绘打回起点。

**详细说明**：

- **使用场景**：看板泳道视图，用户已横滚到某列（`.dsh-pm-lanes` 的 `scrollLeft > 0`）或已在某列内往下翻（该列 `.dsh-pm-lane-cards` 的 `scrollTop > 0`）。
- **操作流程**：
  1. 用户横滚到目标列（例：implementing）/ 在 long 列里往下翻。
  2. 触发刷新：点「刷新」/ 等一轮 20 秒轮询 / 别的窗口改动台账触发 SSE / 自己点卡面按钮。
  3. 系统取数后重绘看板。
  4. 重绘完成的同一帧内回填横向位置与各列纵向位置。
- **预期结果**：
  - 重绘后 `scrollLeft` 与重绘前一致；若新内容可滚动范围变小，则收敛到新的最大值（不报错、不闪回 0）。
  - 各列 `scrollTop` 按列分别回填（A 列滚到中间不影响 B 列的位置；某列消失则忽略该条）。
  - 若上次位置为 0（用户没滚过），行为与今天完全一致（不额外做事）。
- **边界条件**：
  - 容器里没有 `.dsh-pm-lanes`（列表视图 / 需求详情 / 空态 / 出错页）→ 静默跳过，不抛错、不警告。
  - 取到的值非法（`NaN` / 负数 / 非有限数）→ 按 0 处理（与 `dag/view-state.ts` 的 `sanitizeScroll` 同口径）。
  - 数据变化导致列顺序 / 列宽变化 → 位置按新布局生效，不回退到 0。
  - 列数变化（例如某列变空但仍在）→ 该列位置照旧回填，不串到别的列。

**验收标准**（可跑）：

1. `npx vitest run tests/board-lane-scroll.test.ts` → 用最小 DOM 桩构造容器（横向 `scrollLeft = 260`、某列 `scrollTop = 180`）触发一次重绘，断言重绘后两值都被回填；横向上限小于 260 时断言收敛到上限。
2. 单测断言「按列隔离」：给 A 列记忆 180 后回填，B 列的值为 0（未被 A 覆盖）。
3. 手工（GUI `http://127.0.0.1:19387` → 看板 → 泳道）：横滚到最右 accepting 列 → ① 点「刷新」；② 等一轮 20 秒轮询；③ 在另一个窗口改一条需求（触发 SSE）——三次都在 accepting 列，未被弹回 draft。
4. 改的是 client 源码 → `pnpm typecheck` 退出码 0（C-15）、`pnpm build:client` 输出 `[verify-client] OK`（C-12）。

### FR-2: 位置记忆的作用域与隔离

**功能描述**：位置记忆只服务「项目看板 · 泳道视图」这一处，与需求详情页 DAG 画布的记忆互不干扰；页面重载回到最左。

**详细说明**：

- **使用场景**：同一次页面会话里既看过需求详情 DAG，也看过看板泳道。
- **操作流程**：
  1. 用户在看板泳道横滚（写入记忆）。
  2. 用户打开某需求详情、在 DAG 上改布局方向并滚动（写入的是 DAG 自己的记忆）。
  3. 用户返回看板泳道（读回的是泳道自己的位置，不是 DAG 的）。
- **预期结果**：
  - 两处记忆键互不覆盖：泳道不会因为 DAG 的记忆被搬到别处，DAG 也不因泳道而改变。
  - 记忆**只在内存**：不写 `sessionStorage` / `localStorage`、不进台账、不发请求；刷新浏览器或重开看板 → 回到最左（明确接受）。
  - 列表视图的排序 / 分页偏好不受影响（仍走既有 `dsh-pmboard:list` 键）。
- **边界条件**：
  - 记忆条目数有上限（超出按插入顺序淘汰最旧），不会随浏览时长无限增长。
  - 看板未挂载 / 视图不是泳道 → 不写记忆。

**验收标准**：

1. 单测：写泳道位置后再读写 DAG 状态的键，两者互不相等也不互相覆盖；反向亦然。
2. 单测（静态断言）：本需求新增的代码不出现 `localStorage` / `sessionStorage` 写入（`grep` 断言，沿用仓内既有做法）。
3. 手工：看板泳道滚到中间 → 浏览器刷新页面 → 回到最左（证明未落盘）。

### FR-3: 视图互切与详情往返后位置仍在

**功能描述**：用户显式切视图或进出需求详情，回到泳道时仍在离开时的位置。

**详细说明**：

- **使用场景**：看板泳道 → 点「列表」看一眼 → 切回「泳道」；或泳道 → 点某需求卡进详情 → 点「← 看板」返回。
- **操作流程**：离开泳道（位置入记忆）→ 在别处看一圈 → 回到泳道（位置回填）。
- **预期结果**：回到泳道即停在离开时的那一列（列内位置同理），不必重滚。
- **边界条件**：
  - 期间数据变化导致该列被删（如需求全部移出）→ 位置按新布局裁剪，不报错。
  - 列表视图自身的分页 / 排序行为不变（本 FR 不动它）。

**验收标准**：

1. 单测：`泳道 → 置位置 → 切列表 → 切回泳道` 两段式断言位置一致。
2. 手工：看板泳道滚到 design 列 → 进任需求详情 → 「← 看板」返回 → 仍在 design 列。

### FR-4: 泳道列纵向铺满看板可视高度

**功能描述**：泳道各状态列从列头直通看板底部，高度不再只包住自己的内容；列内卡片超出时在列内滚动，列头保持可见。

**详细说明**：

- **使用场景**：看板泳道视图的常态——包括空列（立项 / 设计）与长列（implementing 十几张卡）。
- **操作流程**：无用户操作。渲染即铺满；浏览长列时在列内滚动，其它列不动。
- **预期结果**：
  - 列高 = 泳道区可用高度（列头与归档条之间），**不随内容多少变化**：空列也到底，不再是一小段空框。
  - 列头固定：列内滚动时「状态名 + 计数胶囊」始终可见。
  - 只出现**列内**滚动条；不出现「看板整页纵向滚动 + 列内滚动」双滚动条。
  - 底部「🗄 已归档」条仍在最下方，不被列压住或遮挡（折叠态时不占多余高度）。
- **边界条件**：
  - 窗口变矮 → 列高随之变矮；不得出现列被裁掉一半或溢出到看板之外。
  - 窗口极矮（低于可用下限）→ 允许列内滚动条照常工作，但**不得**出现内容被永久遮住、滚不到的情况。
  - 列表视图、需求详情、任务总览等其它视图不受影响（本 FR 只动泳道）。
  - 现有列宽规则（`min-width: 320px / max-width: 340px`）不变。

**验收标准**：

1. GUI：看板泳道 → 各列白底卡片的底边贴齐看板底部（归档条之上），不再中途截断；空列（立项 / 设计）与满列同高。
2. 某列卡片很多 → 列内滚动能看到最后一张；滚动过程中列头（状态名 + 计数）保持可见。
3. 把浏览器窗口拉矮 → 列高跟着变矮，列内容不被裁掉（列内仍能滚到底）。
4. 快照 / 静态断言：列高由「填充可用高度」得出，写死视口减常数的 `calc(100vh - 200px)` 不再是列高的依据（若设计阶段判定必须保留某个下限，在设计文档里写清理由与数值）。

## 接口与数据契约（feature 档要求）

- **调用方（FR-1~FR-3）**：`render()`（[src/client/board-mount.ts](../../../src/client/board-mount.ts)）在 `viewEl.innerHTML = buildBoard(...)` **之前**取值、**之后**回填。
- **输入**：承载看板的容器元素（可能为 `undefined`——挂载期卸载）。
- **输出**：无返回；回填是尽力而为（找不到泳道容器 / 找不到该列即静默跳过）。
- **数据契约**：记忆条目 = `{ scrollLeft: number; laneScroll: Record<string, number> }`（键为列 `data-lane`）；横向为单例泳道键（看板泳道是全量视图，不随需求变化）；非法值收敛为 0。
- **错误语义**：不抛错、不发请求、不写存储；容器缺失 = 静默跳过（诚实降级，与 `panel-hydrate` 的「找不到钩子静默返回」同纪律）。
- **样式作用面（FR-4）**：只改样式表（[src/client/styles/base.ts](../../../src/client/styles/base.ts) §泳道），**不改 DOM 结构与事件契约**；若为铺满高度不得不新增一层容器，属结构改动 → 设计阶段必须显式说明并复核是否触发升级（L3）。
- **迁移与兼容**：不新增接口、不改返回体、不改台账结构；旧 bundle（未含本记忆）行为与今天完全一致，可随时回滚（删掉两处调用 + 还原样式即回到现状）。

## 边界（不做什么）

- **不改刷新触发机制与周期**：SSE 事件、20 秒轮询、手动「刷新」、操作后重绘全部保持现状。本次**不做**「数据没变就不重绘」的渲染优化（那是另一类改动，需要单独决策）。
- **不改泳道布局与视觉（仅 FR-4 一处例外）**：除「列高铺满可视区、列内自己滚」外，列宽、列序、卡片样式、归档条、列表视图的排序 / 分页语义一律不动。
- **不做结构性重写与持久化**：不引入虚拟滚动、不把看板 React 化、不把位置写进台账 / 服务端 / 浏览器存储——位置是纯前端会话态。

## 非功能需求

- **零额外请求**：不新增接口、不新增轮询、不改取数路径。
- **无可见闪烁**：回填在重绘的同一帧内完成，不出现「先回到最左再跳回」。
- **不出现双滚动条**：看板整页不因泳道内容而纵向滚动（FR-4）。
- **安全降级**：任何取不到容器 / 取不到值的情形都不抛错、不刷控制台错误。

## 验收标准（整体）

1. 打开看板泳道：各列底边直通看板底部，空列与满列同高（FR-4）。
2. 横滚到最右（accepting 列）。
3. 触发三种刷新各一次：① 点「刷新」；② 等一轮 20 秒轮询；③ 在别的窗口改一条需求（触发 SSE）。
4. 每次刷新后仍在 accepting 列，未被弹回 draft（FR-1）。
5. 在某长列内往下翻 → 再触发一次刷新 → 仍停在该列原位置，且列头可见（FR-1 + FR-4）。
6. 切到列表再切回泳道、进需求详情再返回 → 仍在原位置（FR-3）。
7. `npx vitest run tests/board-lane-scroll.test.ts` 全绿；`pnpm typecheck` 退出码 0；`pnpm build:client` 输出 `[verify-client] OK`。
8. 刷新浏览器页面 → 回到最左（记忆不落盘，符合 FR-2）。

## 轻路径依据与升级（L3）

- **为什么可以走轻档**：改动面小——FR-1~FR-3 是一个纯记忆模块 + `render()` 前后两次取值 / 回填，FR-4 是样式表里泳道段的几行；**无新决策点**，位置语义、生命周期、隔离键都照本仓既有先例（[src/client/dag/view-state.ts](../../../src/client/dag/view-state.ts)）定死，列高目标形态已由用户当场确认；不动接口、台账、数据模型，不新增子系统。
- **单向升级信号**（出现任一条即停手升级为重档，不许反向降级）：
  - 要「跳过无变化的重绘」或改动刷新周期 / SSE 协议；
  - 要把位置持久化到浏览器存储、台账或服务端；
  - 要引入虚拟滚动 / 看板重写 / 为列高新增 DOM 层级；
  - 出现第二个未定决策。

## 依赖与约束

- **依赖**：既有 `render()` 与泳道 DOM 契约——容器类名 `.dsh-pm-lanes`、列 `.dsh-pm-lane[data-lane]`、列内卡片区 `.dsh-pm-lane-cards`（[src/client/styles/base.ts](../../../src/client/styles/base.ts) §泳道、[src/client/views/board.ts](../../../src/client/views/board.ts) §buildBoard）——类名若变，记忆模块的取点必须同步（在测试里锁住）。
- **约束（FR-4）**：现规则是 `.dsh-pm-lanes { flex: 1; align-items: flex-start }` + `.dsh-pm-lane { max-height: calc(100vh - 200px) }`；改成铺满时必须保住列内 `.dsh-pm-lane-cards { overflow-y: auto }` 的滚动能力（父级要有确定高度、`min-height: 0` 链不能断），否则列内滚动条会失效。
