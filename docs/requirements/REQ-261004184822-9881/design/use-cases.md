## UC-1 刷新不弹回 <!-- serves: FR-1 -->

- **用例角色**：看板主人（需求多，implementing / accepting 列在最右）。
- **前置条件**：打开看板，视图为「泳道」；已有若干需求分布在多列。
- **交互流程**：
  1. 横向滚动到 implementing 列，停在那里看卡。
  2. 期间发生刷新：点「刷新」/ 20 秒轮询到时 / 另一窗口改台账触发 SSE / 自己点了卡面按钮。
  3. 看板重绘（rev 号与卡内容可能变化）。
- **异常流**：若取数失败 → 显示错误页；此后再回到看板时，位置仍应是离开泳道前的那个（记忆没被错误页冲成 0）。
- **后置条件**：横向位置与列内位置与刷新前一致。
- **完成标志**：刷新后视线里的列没变，不需要再滚。

## UC-2 出去再回原位 <!-- serves: FR-3 -->

- **用例角色**：看板主人。
- **前置条件**：泳道视图，已横滚到 design 列。
- **交互流程**：
  1. 点「列表」看全量汇总 → 点「泳道」切回。
  2. 或点某需求卡进详情 → 点「← 看板」返回。
- **异常流**：期间该列被清空（需求全部移出）→ 位置按新布局裁剪，不报错、不白屏。
- **后置条件**：回到泳道即在 design 列。
- **完成标志**：两步往返后都不必重滚。

## UC-3 长列直通到底 <!-- serves: FR-1, FR-4 -->

- **用例角色**：看板主人（某列十几张卡，如 implementing）。
- **前置条件**：泳道视图，窗口高度正常。
- **交互流程**：
  1. 观察各列：白底卡片从列头一直铺到看板底部（空列同高）。
  2. 在某列内往下翻到最后一张卡。
  3. 期间发生一次刷新。
- **异常流**：窗口拉得很矮 → 列高随之变矮，列内仍能滚到最后一张；不出现"内容被永久遮住"。
- **后置条件**：列内滚动位置保持，列头仍可见。
- **完成标志**：不用整页滚动就能在一列内看完所有卡，且刷新后不用重新翻。
