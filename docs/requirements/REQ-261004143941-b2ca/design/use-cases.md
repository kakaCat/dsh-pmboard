# REQ-261004143941-b2ca 设计 · 用例（谁在什么宽度下看到什么）

## UC-1 宽窗口：看每节点明细（现状保持）（serves: FR-2, FR-3）

**触发**：标题行容器 ≥1000px（视口约 ≥1050px）。
**看到**：圆点 + 全部节点名 + **每节点 token** + 连线 + `3/12` 计数 + **`🪙 24.8M` 累计**。
**成功判据**：探针 A 档 `tokens(节点级) ≥ 1` 且总数徽章可见；`chartScrollX = 0`。

## UC-2 窄窗口：至少看到累计总数（本需求新增）（serves: FR-2）

**触发**：标题行容器 <1000px（B/C 档），或 <600px（D 档）。
**看到**：节点级 token 按档位隐藏（既有行为），但**计数旁的累计总数恒在**；D 档退化为纯数字（无 `🪙`）。
**成功判据**：探针 B/C/D 档「可见 token 元素数 ≥ 1」（改造前为 **0**——这条断言就是本用例的可证伪形式）。
**为什么以「总数」兜底**：窄档下用户要回答的问题是「这需求烧了多少」，而不是「设计阶段烧了多少」——后者是明细，前者是结论。

## UC-3 无快照的需求：不出现假 0（serves: FR-1, FR-2）

**触发**：老需求（token 功能上线前创建）或从未产出快照的需求，会话头部仍显示流程图。
**看到**：流程图照常（节点、计数、四态），**没有** token 徽章；不出现 `🪙 0`。
**成功判据**：接口响应**无** `tokenTotal` 键；模型层 `tokenTotal === undefined` → 渲染树中无 `.dsh-pm-cprog-token-total`。

## UC-4 详情面板 Token tab：口径不变（serves: FR-3）

**触发**：点击流程图展开详情面板 → 切到 `🪙 Token` 页签。
**看到**：与改造前逐字一致（byStage 明细 + 任务下钻 + 提示词成本估算）。
**成功判据**：`tests/token-tab.test.ts` / `tests/token-endpoint.test.ts` 全绿（本次不动该链路）。
**边界**：本次**不**把 header 的 `tokenTotal` 接进 Token tab（两处口径同源，但接入属于另一个改动面，没写进需求边界即不做）。
