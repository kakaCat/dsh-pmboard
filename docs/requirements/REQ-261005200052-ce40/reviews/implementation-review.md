## 3. 偏离与取舍（如实）

1. **新增内部助手 `isConfirmGateKind`**：设计接口表只列了 `hasConfirmGateOf`。它是同一单点的拆解
   （通知文案与守卫共用门值域判定），无行为变化。
2. **②「看板点确认」也要求产物在册**：设计只写了「仅当有门」。实测口径：看板确认同样要求产物在册，
   无产物时人点了也落不了章——照设计写会再骗一次，故收紧并在用例锁死。
3. **第 5 个消费点 `QueryReport`（看板缺口 why）**：设计只列四处。为保证「看板与 agent 看到同一句话」
   一并接同一 facts。
4. **前移校验的位置**：仍在 `port.register` 之前，但排在「弹框通道不可用 → `fallback=board`」之后——
   保留既有 fallback 契约（否则会带动一条无关的契约变更）。
5. **严格基线不可得**：工作树含其他需求的未提交改动，故以两次全量跑集合差 + 失败逐类归因替代，
   结论「零新增失败」有脚本级证据；此边界已在测试证据里写明。
