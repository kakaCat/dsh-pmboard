判据原文（同一判据，两份逐字同源实现）

出处：src/client/dag/progress-bar.ts 的 chainMissing() 与 src/application/query/QueryDag.ts 的 chainMissingOf()（application 层禁止 import client，故各写一份，必须同步改）。

chainMissing(card, kids):
  kids.length > 0                      → false   有子卡，链在，不标
  stages 是数组且 length === 0          → false   显式 solo（唯一表示「本卡不要子卡」）→ 永不标
  card.status === 'in_progress'        → true    未声明 stages 也算期望有链（默认链按卡 phase / side 推出）
                                                     ── 与旧行为逐字一致，不许放松
  card.status === 'done'               → stages 是非空数组 ? true : false
                                                     ── 本次新增的一半：计划写了链、卡却走完且链从未生成
                                                     ── 未声明 stages 的存量 done 卡 不打标（不噪声）
  其它状态（todo / canceled …）          → false   todo 还没到懒展开，没链是正常态
为什么 done 只在显式声明非空 stages 时才标：autoRun=false 时手动开工从不展开子卡链， expandSubtasks 幂等且只有一次机会——卡走完整个流程也无人发现链没生成。而没有「声明过要链」证据的存量 done 卡， 大面积打标只会变噪声，噪声一多真问题就看不见了。

可访问性约束：红标不能只靠颜色——必须带「链未生成」文字（本页角标 = 圆点 + 文字，title 写原因）； 卡片本身是 button，可访问名里要含状态与原因（本页 aria-label 已含「标注：链未生成」）； 刷新后要播报就更新按钮的可访问名，不要在按钮里再塞 live region（按钮内容对辅助技术是展平的）。 对比：#991b1b on rgba(220,38,38,.10) ≈ 6:1，满足正文 4.5:1。

几何量声明与测法

全页恰好一块几何量声明注释块（在文件末尾 </body> 前，JSON 一行一观测）； 观测量只含「名 + 实测值 + 测量条件」，不含任何阈值字段。

  • cardWidth / cardHeight：量 .np-card（落点①主视图卡）外框，CSS 里定死 300 × 96。
  • badgeHeight / badgeFontSize / badgePaddingX：量 .badge；badgeWidth = 4 个汉字 × 11px + 左右各 6px 内边距 + 2 × 1px 边框 ≈ 58px，随文案字数变。
  • declSlotWidth / declSlotHeight：量 DAG 里代表「声明了但未生成」的虚线子卡段槽 .slot（定死 64 × 22；第五张 solo 小样那个绿槽是自适应宽 .slot.solo，不在本条口径内）。
  • caseColumns / caseColumnGap / pageContentWidth：量对照网格（2 列 × 20px 间距，内容宽 1180px）。
  • dagNodeCount / dagEdgeCount：每个小型 DAG 实际渲染的节点与依赖边数——四态 + solo 小样都是 1 节点 / 0 边（输入差异只在 status 与 stages，不在图形）。
  • markedCaseCount / unmarkedCaseCount：页内标红 / 不标的情形数，与上一节自检同源。

测量窗口宽显式写为 1280；inflight 指进行中态量的，terminal 指终态（done）量的。换窗口宽重测时必须改 at.width，否则量错。
