# 用例设计 · 面板自刷新与陈旧可见（REQ-261001124111-5d36）

> **TL;DR**：五个用例覆盖本次事故的全部分支：① 任务落库后自动出现；② 拿不到数据时明说"这是旧的"；
> ③ 切换需求不串档；④ 插件更新后不再靠人猜"要不要刷新"；⑤ SSE 活着时的事件级即时刷新。

## UC-1 任务落库后自动出现（`serves: FR-1`）

**角色**：需求提出者 / PM（人）。**前置**：面板已展开在「拆分」节点，且当前显示 0 张卡（或旧数量）。

| 步骤 | 谁做 | 期望 |
|---|---|---|
| 1 | 人在另一个窗口把任务卡落库 / 推进一张卡 | 服务端 `/stages` 的 `body.tasks` 立即变化 |
| 2 | 面板自己（5 秒轮询或 SSE 事件） | **≤5 秒**内出现新卡（DAG 节点 / 泳道卡片 / 计数之一），**全程不刷新页面** |
| 3 | 人看面板头 | 「数据时间 HH:MM:SS」随之前进 |

**异常分支**：轮询与 SSE 同时不可用 → 进入 UC-2（明说旧数据），**不得**显示「暂无任务」冒充空。

## UC-2 拿不到最新数据时明说「这是旧的」（`serves: FR-3, FR-2`）

**前置**：面板已有一次成功数据（`fetchedAt=t0`），随后网络断开或接口 5xx。

| 步骤 | 期望 |
|---|---|
| 1 | 面板出现红条：`刷新失败：<原因> · 显示的是 HH:MM:SS 的旧数据`（`role="alert"`） |
| 2 | 面板**继续显示**旧 overview（不白屏、不清空），但头时间戳 `data-stale="1"` 转警示 |
| 3 | 恢复网络 ≤10 秒 → 红条消失、时间戳前进、`failureCount` 归零 |
| 4 | 若**从未**成功过（`fetchedAt` 缺失）→ 只显示「详情暂不可用：<原因>」，不渲染空任务区 |

**反例（当前缺陷）**：面板显示「暂无任务」而服务端有 23 张卡、且无任何提示 —— 本用例即为此设。

## UC-3 切换需求不串档（`serves: FR-4`）

**前置**：面板展开显示需求 A 的 DAG；用户切到需求 B 的会话窗口。

| 步骤 | 期望 |
|---|---|
| 1 | 面板先进入 `loading`（「详情加载中…」），**不得**继续显示 A 的卡片 |
| 2 | 新数据到达后只显示 B 的 DAG / 泳道 |
| 3 | 若 B 的请求失败 → 显示 B 的错误态，**不得**回退显示 A 的数据 |

## UC-4 插件更新后不再靠人猜（`serves: FR-5`）

**前置**：页面已加载旧 bundle，磁盘上 `lib/client.cjs` 已被重新构建（戳 `S2`），页面内联戳为 `S1`。

| 步骤 | 期望 |
|---|---|
| 1 | SSE 重连/首连时收到 `event: build` 帧（`{"stamp":"S2"}`） |
| 2 | 面板显示（一次）：`插件已更新（S1 → S2），点此刷新`（`role="status"`） |
| 3 | 人点击 → `location.reload()`；**不自动刷新**（避免打断正在输入的消息） |
| 4 | 若 `lib/client.cjs` 读不到（服务端不发帧）或老 bundle 无内联戳 → **不显示**提示（宁可漏报，不误报） |

## UC-5 SSE 活着时的事件级即时刷新（`serves: FR-1`）

**前置**：SSE 正常连接（`/events` 有帧）。

| 步骤 | 期望 |
|---|---|
| 1 | 任务事件（`task-created` / `task-moved` / `task-updated`）或台账事件到达 | 触发一次 `refresh('event')` |
| 2 | 已在飞时 | **不发新请求**（去重），不产生请求风暴 |
| 3 | 事件级刷新与 5 秒轮询并存 | 两者渲染结果一致（同一事实源 `/stages`），不闪跳 |
| 4 | SSE 断线（关掉 EventSource / 代理缓冲） | 退化为纯轮询，UC-1 的 ≤5 秒承诺**仍然成立** |
