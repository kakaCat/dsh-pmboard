# 需求文档：详情页文档路径绝对化 + 缺失判据按需求自身工作区

- 需求 id：REQ-261005143615-5ab1
- 类型：feature（缺陷驱动）
- 立项日期：2026-10-05
- 来源：本窗口现场诊断（REQ-261005123641-3982 详情页整列「文件缺失」并划线，磁盘上 25 份文件一份不少）

## TL;DR

- **是什么**：详情页判「登记文档在不在盘上」时用错了根（用了阅读会话的工作区，解析不到就回落插件宿主目录）。
- **为什么**：于是文件明明都在，页面整列写「文件缺失」并划线——归档后被当成"归档把文件删了"。
- **得到什么**：判存在性与打开都按**需求自己声明的工作区**算绝对路径；读根确实不可得时只说「未判定」，绝不说「缺失」。

## 产品定义

现在的判据链是「阅读会话工作区根 → 解析不到就回落插件宿主目录」；宿主目录里没有
`docs/requirements/`，于是每条登记文档都落 `file-missing`。改后按需求自己的根判，页面上不再出现
整列谎报。

```
现状（错的根）                          改后（对的根）
读详情页（?session=当日窗口）            读详情页（?session=任意/不带）
        |                                        |
        v                                        v
   解析阅读会话工作区                      候选根按序尝试：
        |  ├─ 成功 → 本仓根（碰巧对）       需求自身 workspaceRoot  ←①
        |  └─ 失败 ↓                        阅读会话工作区        ←②
        v                                   组合根 cwd            ←③
   插件宿主目录 ~/.dsh/profiles/<p>/            |
   （没有 docs/requirements/）                  ├─ 任一命中 → 用它的绝对路径判存在
        |                                       └─ 全不可得 → state='unknown'（未判定）
        v
   25/25 → file-missing + 划线（撒谎）
```

## 用户与角色

- **人（看板读者）**：归档前后翻这条需求的文档，要看到真实状态，并点开真实文件。
- **窗口 agent / 服务端**：读根解析与状态判定的实现方（谁判、按哪个根判，写进设计）。

## 边界

- **做**：① 存在性判定按需求自身 `workspaceRoot`（多候选按序）；② 新增「未判定（读根不可得）」态，
  禁止把未知写成缺失；③ `DocsResponse` 每条文档行带绝对路径（加性字段），显示与打开都用它。
- **不做**：① 不改台账存储格式（仍存工作区相对路径 + `workspaceRoot`/`docBasePath` 声明）；
  ② 不改右侧栏打开通道（复用既有 `dsh-resource` 绝对路径能力与 `absolutizeDocPath`）；
  ③ 不为「文档真的不在盘上」翻案——既有 `file-missing` 语义是对的，错的是判据用错了根。

## 功能点

| 编号 | 名称 | 判据（看到什么算过） |
|---|---|---|
| FR-1 | 存在性判定改按需求自身工作区 | 服务端用该需求记录的 `workspaceRoot` 拼绝对路径判存在，不再以阅读会话为唯一依据 |
| FR-2 | 读根多候选按序尝试 | 序 = 需求自身根 → 阅读会话根 → 组合根 cwd；命中哪个根就用哪个根算绝对路径 |
| FR-3 | 三态而非两态（unknown ≠ missing） | 候选全不可得 → `unknown`（「未判定（读根不可得）」）；候选可得而文件不在 → 仍 `file-missing` |
| FR-4 | 响应与渲染给绝对路径 | `documents[].absPath` 供显示与打开；`unknown`/`file-missing` 不给 `absPath`，也不给可点假出口 |
| FR-5 | 加性兼容与回滚 | 老客户端不认 `absPath`/`unknown` 时行为不变；回滚只关判定分支，台账零迁移 |

- **FR-1: 存在性判定改按需求自身工作区**：服务端对每条登记产物，用该需求记录声明的
  `workspaceRoot` 拼绝对路径判存在，不再以阅读会话为唯一依据。
- **FR-2: 读根多候选按序尝试**：候选序 = 需求自身根 → 阅读会话根（`?session=`）→ 组合根 cwd；
  任一命中即算存在，且**命中哪个根就用哪个根算绝对路径**。
- **FR-3: 三态而非两态（unknown ≠ missing）**：所有候选都不可得（解析不到 / 根目录不存在）→
  新增状态 `unknown`，页面写「未判定（读根不可得）」；候选可得但文件确实不在 → 仍是 `file-missing`。
- **FR-4: 响应与渲染给绝对路径**：`DocsResponse.documents[]` 增可选 `absPath`（命中根时给出）；
  文档行的显示与打开都走它；`unknown` / `file-missing` 不给 `absPath`，也不给可点的假出口。
- **FR-5: 加性兼容与回滚**：老客户端读不到 `absPath`、不认 `unknown` 时行为不变；
  回滚只关判定分支，台账零迁移。

## 接口与数据契约

- 端点：`GET /dashboard/api/reqboard/requirements/:id/docs`
  （调用方：board-mount 详情页壳 → `fetchReportDocs`）。
- 变更（**全部加性**）：`documents[].absPath?: string`；`DocPanelState` 增 `'unknown'`。
- 错误语义：读根不可得**不是** 500、也不是「缺失」——200 + `state:'unknown'`，
  如实说「这台机器上判不了」。
- 旧数据：存量台账不变；`absPath` 由服务端现算，不落库。

## 验收（可跑、可证伪）

| # | 动作 | 看到什么算过 |
|---|---|---|
| 1 | `curl ".../REQ-261005123641-3982/docs"`（**不带** `?session=`） | `state=='file-missing'` 条数为 **0**（现状 25/25） |
| 2 | 同上带 `?session=<本仓会话>` | 每条 `state` 与 `os.path.exists(absPath)` 逐条一致（脚本比对 0 分歧） |
| 3 | 候选根全指向不存在目录 | 全部 `unknown` + 文案「未判定（读根不可得）」，**不出现** `file-missing` |
| 4 | 回归 `REQ-260930094139-2d65`（文件真没了） | 候选根可得时仍如实 `file-missing`，不被 `unknown` 掩盖 |
| 5 | `pnpm build:client` / `pnpm build` / `pnpm typecheck` / `pnpm test` | C-11、C-12、C-15 退出码 0；C-14 失败数不高于基线 |

## 轻路径依据（为什么可走轻档）

- **改动面**：三处——`QueryDocs` 判据（读根候选 + 三态）、`protocol.ts` 加性字段、
  `docs` 面板渲染（显示绝对路径 + 新态文案）。
- **无新决策点**：存储格式、候选序、三态语义都在这份文档里定死；不新增子系统、不动台账数据模型。
- **单向升级**：一旦发现需要改台账存储、新增读根服务、或改打开通道协议 → **立即停手升级重档**。
