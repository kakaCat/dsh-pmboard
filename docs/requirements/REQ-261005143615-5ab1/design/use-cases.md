## UC-1：人在归档后翻这条需求的文档（主场景） `serves: FR-1, FR-2, FR-4`

- 角色：看板读者（可能**不在**这条需求的来源窗口里，甚至不在同一个项目窗口）。
- 现状：读根按阅读会话解析 → 解析不到就回落插件宿主目录 → 整列「文件缺失」+划线（要求归档后尤其常见：
  归档即工作结束，来源窗口往往已关闭）。
- 期望：按需求声明的 `workspaceRoot` 判存在并给出绝对路径 → 状态如实、点开就是真文件。

## UC-2：换机器 / 仓被移动（判不了的场景） `serves: FR-3`

  因为这台机器上根本没有那个根，判不了就是判不了。
