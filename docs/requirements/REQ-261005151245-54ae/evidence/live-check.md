# 实机复核记录（t6 · 待人工核对）

> 为什么必须人工：侧栏标题、模式芯片、模型选择器都要**眼睛看**；agent 拿不到 GUI 画面，
> 也不该自己给自己盖章。机器侧能证的部分见 `checks.md`（用例 + 探针 + 构建）。
>
> **前置：本次改的是插件 host 侧代码，运行中的宿主仍持着启动时加载的旧模块。**
> 先在仓库根跑 `pnpm build`（已由 t5 执行、退出码 0），再**重启 DSH 应用**（或重载插件），
> 否则下面看到的是改造前的行为。

## 复核步骤（照做即可，三条命令都不需要）

| # | 做什么 | 期望看到什么 |
|---|---|---|
| 1 | 找一个窗口：标题不是默认（例如「登录重构」）、模式为**创造模式**、模型选择器是**非默认模型**（例如 `deepseek-reasoner` + 推理档 high） | 三样都记下来，作为对照基准 |
| 2 | 在该窗口让 agent 调 `reqboard_open_window`（不传 `title`） | 回执里有 `window_key` 与 `inheritance`；`inheritance` 三项均为 `set`、`reasons` 为空 |
| 3 | 看侧栏 | 出现一个新会话，标题是「<源标题> (1)」（源标题带序号时序号 +1） |
| 4 | 打开这个新会话 | **模式芯片** = 创造模式；**模型选择器** = 第 1 步记下的同一个模型（含推理档） |
| 5 | 再点一次看板「存储与数据库」页的迁移发起（需要人工确认票） | 新窗口标题为「台账迁移窗口」（显式语义名，不递增源标题）；模式与模型同样继承 |

## 出问题时的定位顺序（写给复核人，不必自己排障）

1. 回执 `inheritance` 里哪一项不是 `set` → 那一项的原因就在 `reasons`，含宿主错误原文。
2. 三项都是 `failed` 且原因是「未装配读画像能力（readProfile）」→ 跑的还是旧构建，回到前置步骤重建并重启。
3. 回执说 `set` 但界面不一致 → 这是**真缺陷**（回执与事实不符），请原样记录 `window_key` 与截图，
   按验收退回处理（此时问题在本需求的适配器映射或界面呈现口径）。
