# REQ-261004154937-2ca3 设计 · 用例（谁在什么情形下看到什么）

## UC-1 没派过子代理的窗口：数字与今天逐字相同（serves: FR-1）

**触发**：窗口从头到尾自己干活，`closure(parentSession)` 为空。
**看到**：节点/任务/需求的数与改造前完全一致；口径标注为「含子代理」（虽然此刻等于自身）。
**成功判据**：既有夹具下，聚合结果 == 改造前的数字（回归锁）。

## UC-2 派过子代理的窗口：数字变成真实总量（serves: FR-1）

**触发**：窗口用子代理并行干活（本仓常见：`subagent` / `workflow`）。
**看到**：数字**明显变大**——例如样例窗口从 141.1M 变成约 226.4M（+14 个子代理的 85.3M）。
**成功判据**：主 + 2 子夹具下 `tokenTotal == 主 + 子1 + 子2`；真数据取证与独立复算一致。

## UC-3 阶段进行中新起一个子代理：它的消耗归本阶段（serves: FR-2）

**触发**：进入"实施"阶段后派了子代理（阶段开始时的快照里还没有它）。
**看到**：该子代理**创建以来的全部消耗**计入本阶段的差值（不是只算它出现之后的增量）。
**为什么**：它诞生于两次快照之间 ⇒ 它的全部消耗都发生在本阶段内。
**成功判据**：单测锁住「新成员全额计入」。

## UC-4 某后代取不到用量：数字不凭空变化，且如实标注（serves: FR-3）

**触发**：后代会话的投影缓存没有该行，且冷读超出预算（默认 8 个 / 200ms）。
**看到**：数字只含可得成员（**不补 0**）；徽章/详情标注「含 N 个未取到的子会话」。
**成功判据**：注入一个"永远取不到"的后代 → 合计 == 可得成员之和，`degradedMembers` 含它。

## UC-5 历史需求：数字保持旧口径，页面说清时间分界（serves: FR-4）

**触发**：查看本需求上线前就已在进行/已完成的需求。
**看到**：数字仍是"不含子代理"的旧值；Token tab 注明「本口径上线前的历史数字不含子代理」。
**成功判据**：文案存在（结构断言）+ 旧快照能正常参与差值（`legacy-snapshot` 退化，不抛错）。

## UC-6 起链预算闸：口径不变，差异写在明处（serves: FR-4）

**触发**：新起一条链，`maxCacheReadTokens` 判据读需求累计 cacheRead。
**看到**：闸门行为与今天一致（**不含子代理**）；Token tab 写明「展示含子代理 / 预算闸不含」。
**成功判据**：`chain-budget.ts` 的相关用例保持不变；文档与 UI 文案在场。

## UC-7 DSH 服务不可得（老宿主 / 降级环境）（serves: FR-1, FR-3）

**触发**：`sessionPersistence` 或 `sessionProjectionCache` 未装配。
**看到**：数字与今天逐字相同，`scope='self'`、`degradedReason='descendants-unavailable'`；**不假装聚合过**。
**成功判据**：单测注入缺服务 → `scope='self'` 且 `degradedReason` 命中；数字等于自身路径。
