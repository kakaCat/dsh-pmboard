## 四、如实声明：未落地项、偏离与既有红（不静默）

1. **全量套件非全绿（本仓既有）**：74 条失败全部可在开工前提交上复现（id 格式迁移、
   `apply` 语义变更等存量问题）。本需求**未修**它们，也未把基线拉高。逐条清单见证据文件。
2. **FR-10 的「再往上汇总」四项服务端未给**：墙钟 / 窗口数 / 轮次 / 零产出执行。
   端点的扩展段只合并了按阶段表、优化点与可得性三态；面板按「响应里有才渲染」实现，
   **不伪造 0**（已显式列出「未给出的项不渲染」）。要真落地需服务端补字段。
3. **Tab 角标只填了三处**：`docs`（产物条数）、`dag`（任务卡数）、`token`（合计，K/M 一位小数）。
   `trunk` / `dialogue` / `prompts` **留空**——它们的计数要额外读文档目录 / 会话事件 / 注入留痕，
   首屏只发一个请求，不为此加读；**拿不到就不显示角标**，不前端推算。
4. **`renderProcessFold` 未被调用（卡面要求的偏离）**：它需要 `StageDetail`（artifacts/timeline/tasks），
   而 `/prompts` 响应没有这些字段；拿空数据喂它会把每条动作算成「未见记录」= 用缺数据伪造否定结论。
   改为把它的三段内容与标记迁进提示词 Tab。
5. **尺寸门禁（单文件 ≤400 行）超限**：`report-tabs.ts` 731 / `api.ts` 553 / `QueryReport.ts` 605 /
   `QueryTrunk.ts` 774 等。该门禁**开工前就是红的**（28 个历史超限文件不在白名单），
   本次让清单变长但没有改变该文件的通过/失败状态。拆分路径已写在 `report-tabs.ts` 的注释里。
6. **计划漏项已补齐并声明**：六个端点里的 `prompts` 查询在拆分计划里**没有任何卡承接**

   ① `PanelQueryDeps` 补 `docs` / `now` / `isolations` / `systemPrompt` / `pendingConfirms`；
