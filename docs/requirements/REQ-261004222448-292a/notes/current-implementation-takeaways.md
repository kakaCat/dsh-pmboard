> 来源：2026-10-04 用户裁定「tab 里的内容你要参考现在的实现，现在实现的内容有可取的内容」。
> 用途：**新原型与新设计的每一条内容，先到这张表里找底稿**；找不到才允许新设计。
> 证据：全部带 `文件:行`，来自对现有代码的逐行核对（不是回忆）。

## 0. 一句话结论

现有实现**不缺内容，缺组织**。可取之处集中在三类：
① **诚实标注**（不补 0、回填标、降级、缺链标）；② **原文可开**（open-doc / jump-session / 片段文件）；
③ **视图状态保持**（DAG 视图、滚动、草稿、Tab）。
本设计的活儿是**重新组织 + 补主干**，而不是重造内容。

## 11. 三态降级 ↔ 现有机制对照（"诚实空态"的落点）

新设计的"三类空态"**不是新规矩**，现有实现里每一种都有对应做法，逐一对接：

| 新设计的说法 | 现有机制（证据） | 页面表现 | 原型里的示例 |
|---|---|---|---|
| **未采集** | 端口未装配 → `available=false`（`routers/injection.ts:27-47`、`isolation.ts`） | 「不可用（端口未装配）」——**不写「0 条」** | 提示词 B 块说明 |
| **不可得 / 降级** | 文件 ENOENT → 空 + 说明；`open-doc` 预检 → `dsh-pm-doc-missing` 标灰 | 「文件缺失」+ 路径划线 | 文档 Tab「任务卡 tasks/t-003-dev.md（已登记但文件不在）」 |
| **无快照** | `token-info.ts` 按节点表：如实标「无快照」，**不补 0** | 「无快照」+ 「部分数据」 | Token Tab「归档」行 |
| **回填** | `timeline.ts` `inferred` 标（由 createdAt + 评论反推） | 事件带「回填」标 | 对话 Tab 第一条系统消息 |
| **文档未提供该节** | ✅ 新规矩（主干抽取特有） | 「文档未提供该节」——不编、不留白 | 汇报 Tab 抽取规则表「缺节时」列 |

> 结论：**只有"文档未提供该节"是本需求新增的说法**，其余四种都是现有纪律的沿用与显式化。
