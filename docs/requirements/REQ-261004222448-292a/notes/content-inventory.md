# 需求详情页 · 内容清单（v1）

> **本文只定「有哪些内容 / 从哪来 / 多大体量 / 怎么处置」，不定版面。**
> 状态：待用户圈定。圈定后据此重写 `requirement.md`（先内容、后版面、最后才画图）。
> 来源：2026-10-04 用户口述的六项 + 我建议补的四项（已确认全要）。

## 0. 口径（三条，先立规矩再看内容）

**0.1 读者与决定**——内容由决定导出，不由数据表导出。

| 读者 | 读完要决定 |
|---|---|
| 立项人 / PM | 继续 / 催办 / 退回 / 取消 |
| 实施窗口 agent | 下一步调什么、产物齐不齐 |
| 旁观窗口（worker / observer） | 能插什么手 / 只读 |
| **接手者**（换窗口、断线重连） | 从哪接、上下文是什么 |
| **审计 / 复盘者**（事后，可能隔很久） | 当时谁批的、依据是什么、证据在哪 |

**0.2 内容三级**——决定「常驻 / 浅折叠 / 折叠或跳转」，**不按"重要不重要"分**：

| 级 | 特征 | 处置 |
|---|---|---|
| L1 结论 | 一句话就能改变读者下一步动作 | **常驻，永不折叠** |
| L2 依据 | 支撑 L1 判断的清单/表格 | 常驻或浅折叠（一层） |
| L3 明细 | 可追溯的流水与正文 | 折叠，或点开才取 |

**0.3 分层取数**——「一屏定调 + 块内深挖」，不是一页全铺：

```
L0 首屏（一屏内，一次请求 = 摘要）
  状态 + 一行结论 + 缺口 3~5 条 + 六个块的入口行（每行带关键数字）
        ↓ 点某块才取那块数据（独立端点 / 独立缓存 / 独立刷新）
L1 块视图（长列表分页 / 窗口化）
        ↓
L2 明细（正文、逐条流水、更早的聊天页）——点开才取
```

**0.4 第一性（2026-10-04 用户澄清，优先级最高）：详情页 = 工作汇报**

用户原话把口径说清楚了：聊天 = **会议记录** · 文档 = **工作确定文档** · DAG = **工作步骤** · token = **项目花费** · 详情页 = **工作汇报**。

于是页面分三层：

| 层 | 回答 | 内容 |
|---|---|---|
| **主干**（汇报体） | 为何有它 / 解决什么 / 怎么做 / 做到哪 / 结果如何 | 六条：由来 · 问题 · 思路 · 取舍 · 进度 · 结果 |
| **附件**（佐证） | 过程能不能查证 | 会议记录（聊天）· 确定文档 · 工作步骤（DAG）· 核验 · agent 怎么跑（提示词与注入） |
| **花费** | 值不值 | token / 时间 / 窗口数 / 轮次 |

> ⚠️ **§1、§2 画的全部是「附件 + 花费」；主干今天在页面上几乎没有落点**——这才是用户感觉"漏了但没想到"的地方。

**0.5 汇报主干：六条（本轮真正要补的）**

| # | 汇报里那句话 | 页面该给的 | 来源 | 今天 |
|---|---|---|---|---|
| M1 | **为何有这个项目** | 由来与触发场景：谁在何时因什么提出（含源窗口、立项方式） | 需求描述 + 立项评论 + 立项弹框作答 | ⚠️ 只有一个 description 字段，未成块 |
| M2 | **解决什么问题** | 问题定义 + 现状痛点 + 影响面/收益预期 | 需求文档「产品定义 / 为什么现在做」节 | ⚠️ 要抽文档，页面无落点 |
| M3 | **实现思路** | 方案主线（一段话）+ 关键模块划分 | 设计文档「架构 / 接口」节 + 计划 summary | ⚠️ 要抽文档，页面无落点 |
| M4 | **关键决策与取舍** | 做过哪些取舍、否掉了什么、为什么（含人的退回理由） | 设计文档决策节 + 人工门往返留痕 | ❌ 无落点 |
| M5 | **范围边界** | 明确**不做什么**（防"以为没做"） | 需求文档「边界」节 | ❌ 无落点 |
| M6 | **结果与成效** | 验收结论 + 逐项结果 + 遗留问题 / 后续 | 验收记录 + 复盘文档 | ⚠️ 终态才有原始记录，无"成效"归纳 |

**这层的工程含义**：主干不是把文档全文搬上页，而是**从文档里抽取结构化摘要**（点开可回到原文）。
抽取不到时**如实显示「文档未提供该节」，不许编**——这与"诚实空态"同一条纪律。

## 1. 首屏 L0（一屏内读完，不滚动）

| 项 | 内容 | 来源 | 体量 | 处置 |
|---|---|---|---|---|
| 身份 | 需求 id / 标题 / 类型 / 难度 | 需求记录 | 极小 | 常驻 |
| 归属 | 源窗口、席位（owner/worker/observer）、创建时间、工作区与文档根（可复制） | 需求记录 | 小 | 常驻 |
| 阶段 | 8 态进度 + 当前阶段停留时长 + 距上次变更 | 需求记录 + 状态事件 | 极小 | 常驻 |
| **一行结论（补充 A）** | 在跑什么 / 谁在跑 / **几件事等人** / 下一步谁动手 | 派生：任务 + 挂起确认 + 门禁 | 极小 | **常驻** |
| **缺口 3~5 条（补充 B）** | 该有而没有的（详见 §2.7） | 派生 | 小 | **常驻** |
| 六块入口行 | 每块一行：图标 + 名称 + **关键数字** + 进入 | 各块摘要 | 小 | 常驻 |

## 2. 六个块（用户口述要看的）

### 2.1 🧱 系统提示词
- **内容**：本次装配组了哪几段（逐段列名）、每段字符与估算 tokens、**被预算裁掉的段**、每段正文（可读）。
- **来源**：提示词装配服务（读时算，不是留痕）。
- **体量**：小（几段，正文数 KB）。
- **处置**：块内一次取；每段正文折行展开。

### 2.2 💉 注入的提示词
- **内容**：每次注入的时间 / **来源**（闸门 H3 · Dive 节点 · Dive 轮次）/ 窗口 / **后果**（真投递进会话 vs 只留痕）/ 命中的片段（逐段列名）/ 字符数 / **被裁片段** / 正文。
- **来源**：注入留痕（环形 500 条）。
- **体量**：中→大（正文每次数 KB）。
- **处置**：**列表只给元信息**；正文点开才取；分页；未留痕的类别如实标「未留痕（采集缺口）」。
- **已知缺口**：Dive 轮次真正投递的那条今天**没有留痕**，需补（含正文，单条上限 + 截断标注）。

### 2.3 🪙 Token 记录
- **内容**：累计 / 输入 / 输出 / 缓存命中；按节点下钻、再按任务执行下钻；固定提示词成本；注入成本与占比；墙钟耗时。
- **来源**：需求记录 + 任务执行快照。
- **体量**：聚合小、明细大。
- **处置**：**聚合在服务端算**；下钻分页；**可得性三态**（快照齐 / 部分数据标下界 / 无快照）——**禁显示 0**。

### 2.4 🕸 DAG（agent 分了几步）
- **内容**：层级 / 依赖 / 每节点状态；**每步挂执行结果（补充 D）**：谁做、多久、成败、产出条目、汇报四要素；子卡链（dev→review→test）；关键路径。
- **来源**：`queue.json` 的 tasks / edges / layers + 任务执行记录。
- **体量**：小（几十张卡）。
- **处置**：图一次取全；**节点详情点开才取**（执行流水按需）。

### 2.5 📄 文档与核验文件
- **内容**：文档清单（类型 / 路径 / 登记时间 / **可打开**）；验收单逐项（标准 / 实际结果 / 证据 / 来源 agent\|human / 需人工 / 意见 / 裁决）；**门禁裁决留痕（补充 C）**：谁批的、何时、**什么方式**（弹框 / 看板 / 文字 evidence）、退回理由、改版变更说明、旧批准作废；归档（目录 / 清单 / 合并去向 / 索引条目 / 说明书更新点 / 清单对账）。
- **来源**：产物登记 + 计划记录 + 验收记录 + 归档记录。
- **体量**：中。
- **处置**：只列路径与结论；**正文点开才取**（沿用现有作法）。

### 2.6 💬 一条流：聊天 + 系统消息（人 ↔ agent）
- **口径（已定 A，2026-10-04 修订）**：**像微信那样——一条连续时间线，不按窗口分组**。
  - 只取「人说的话」+「agent 的**文本回复**」；
  - **排除** `tool/call`、`tool/result`、推理过程、`run_code`，以及"正在读取文件…"这类过程叙述。
- **呈现**：单列、时间倒序分页；每条带时间与 actor（人 / agent + 窗口码）；不分组、不折叠。
- **来源**：会话事件（`user/message` + `assistant/message` 文本）+ 需求评论。
- **体量**：大。
- **处置**：默认只渲染最近 N 条（建议 20）；向上滚动再取更早；**页内检索**（关键词搜历史消息）。
- **衍生用法（重要）**：**机器事件也作为「系统消息」混进这条流**（灰底小字、居中、不可回复），例如
  「阶段推进到实施 · w-b262610a」「计划 v1 被退回：粒度太细」「窗口交接：w-3643cb19 → w-b262610a」
  「中断：upstream stream idle，23:16 恢复」「验收单第 3 项驳回」。
  好处：① 一条流就能回答"当时发生了什么"；② **不额外增加页面长度**（本来就要看聊天）；③ 免掉单独一块"时间线"。
- **备注**：窗口跳转入口（补充 E）本次未选——现有页面本就有，建议保留现状、不额外扩展。

### 2.7 ⚠️ 缺口清单（补充 B 的完整形态）
- **内容**：未被任何任务接收的条款；当前阶段必备产物未登记 / 未确认；验收材料缺失；归档清单未对账；条款→设计→任务→测试 的断链；挂起确认未作答。
- **来源**：派生（条款接收状态 + 产物 + 追溯 + 挂起确认）。
- **体量**：小。
- **处置**：首屏放前 3~5 条（按严重度），完整清单在块内；**无缺口时明确说"无缺口"**，不画空表格。

## 3. 性能：六条具体做法

1. **首屏只发摘要**——沿用「`/state` 只发摘要」，进详情不拉全量。
2. **每块独立取数、独立缓存、独立刷新**——不是"一个巨型请求换整页"。
3. **长列表分页 / 窗口化**——聊天、注入留痕、执行记录默认只渲染最近 N 条。
4. **正文一律点开才取**——提示词正文、文档原文、验收证据都不进首屏。
5. **聚合在服务端算**——token 汇总、覆盖度、缺口判定；前端不做全量遍历。
6. **局部更新**——台账一变只换受影响的那块，不整页重绘（顺带解决"刷新就重置、折叠态全丢"）。

## 4. 明确不放

- 整场测评的结论（跨需求，属于对外接口）
- 全局统计（看板 / 统计页的事）
- 别条需求的内容（一跳到位即可，不复制）
- agent 干活的过程叙述（工具调用、推理、读文件…）——聊天只留文本往返

## 6. 候选补充：我替你想到的"漏"

> 用户 2026-10-04：「我觉得还有漏的但是我没想到」。
> 推导方法：**不盯着已有六块想，而是问"你什么时候会拍桌子"**——列出会让你当场骂人的场景，再倒推页面缺什么。

| # | 场景（什么时候会拍桌子） | 缺的内容 | 归属 | 体量 |
|---|---|---|---|---|
| S1 | 换窗口/断线回来："上次为什么断的？我从哪接？" | **断点与接力**：中断原因原文、pendingAction、窗口交接记录、席位变化 | 进「一条流」当系统消息 | 小 |
| S2 | 半天没动静："它到底停在哪了？" | **停机原因**：阻塞标记与原因、暂停原因、失败连击/熔断、停滞计数 | 首屏缺口 + 系统消息 | 小 |
| S3 | "它怎么老是自己绕回来？上下文是不是爆了？" | **上下文与压缩**：每回合上下文水位、压缩次数与策略、节点隔离留痕（替换/跳过/拒绝）、输入包大小 | 归入「系统提示词」块（与"agent 怎么运行"同源） | 中 |
| S4 | "这需求有没有漏做的？" | **条款覆盖四态逐条**（done/received/skipped/**unreceived**）+ 追溯断链（FR→设计→任务→测试） | 归入「文档与核验」块（改名：产物·核验·覆盖） | 中 |
| S5 | "我记得它说过一句关于 X 的话，找不到了" | **页内检索**：在聊天 / 执行 / 注入 / 文档里按关键词搜 | 页面能力（不是内容块） | — |
| S6 | "这页的数字靠谱吗？是不是缓存的旧数据？" | **数据新鲜度**：各块何时取的、是否陈旧、以及当前插件构建指纹 | 页脚一行 + 悬浮提示 | 极小 |
| S7 | "我现在能点哪个按钮？点了会怎样？" | **动作清单与后果**：当前合法动作 + 每个动作的后果说明 + 只读态标识（observer） | 首屏「一行结论」旁 | 小 |
| S8 | "这次烧的 token 比上次多，多在哪？" | **成本对比**：本条需求 vs 同类需求基线（或上一次） | 归入「Token」块（可选） | 小 |
| S9 | "哪一步最耗时、最容易返工？" | **关键路径与返工**：DAG 关键路径、失败重跑次数、返工卡 | 归入「DAG」块 | 小 |
| S10 | "当时是谁决定不做 X 的？" | **决策留痕**：人工门退回理由、覆盖式通过留痕、取消/回滚记录（已有部分） | 「一条流」系统消息 + 文档与核验块 | 小 |

**我的推荐（若只加三个）**：S1（断点与接力）、S2（停机原因）、S4（条款覆盖与断链）——
理由：这三个都是"没有它就得去翻别处、翻不到就骂人"的；其余可后置或并入已有块。
