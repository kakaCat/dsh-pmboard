`[data-tab-content="token"]` 特异性 (0,2,0) > 前两条 (0,1,0)，**与源码顺序无关，必然获胜**；

## 3. 三档展示面（同一份数据模型，三种编排）

| 档 | 展示面 | 宽度 | 放什么 | 明确不放 |
|---|---|---|---|---|
| 一 | **会话头部**（`conversation.session.header.utilities`） | 一行 | 阶段条 + 「到哪一步 + 卡在哪」 | 其它一切。现有 `conversation-progress` 已做对，**本档不改** |
| 二 | **会话内展开面板** | 约 470px | 现在该谁动手 / 缺口 / 任务进度 / 最近对话 / 「打开完整详情」 | 轨迹、文档表、成本、矩阵表 |
| 三 | **看板页**（完整档） | ≥1080px | 下述 8 段纵向流 | — |

**为什么分档**：窄面板铺全量正是"影响对话"的根源（展开就把对话挤掉）。
档二的目标是**收敛现有的 `node-panel.ts`**（与详情页并列的第二套渲染器）。

### 档三（看板页）的 8 段

| 段 | 回答的问题 | 相对现状 |
|---|---|---|
| **结论头**（常驻） | 现在怎么样、卡在谁手上 | 把四处重复压成一处（阶段条 + 一句话结论） |
| **① 现在该谁动手** | 下一步谁动、按钮是什么 | 闸门提示与操作按钮合一并说清后果 |
| **② 缺口与提醒**（常驻） | 该有而没有的 | 新增；无缺口时明说"无缺口" |
| **③ 产物与五道门禁** | 五道门各到哪步 | 新增：登记→确认→放行三态成表 |
| **④ 执行** | 任务跑到哪、链在动吗 | 原「执行」+ 运行态（run/step/心跳）+ 子卡链 |
| **⑤ 验收与归档** | 结论 | 未到阶段给**诚实空态**（不画空表格） |
| **⑥ 对话** | 人机往返说了什么 | **新增**：从时间线里拆出，归档后保留 |
| **⑦ 状态变更** | 机器事件怎么走 | 原时间线的机器事件部分，默认折叠 |
| **⑧ 成本** | 花了多少 | 原「Token」，折叠 + 可得性三态；归档后默认不展开、不进档二 |

## 4. 设计约束（写进 design）

1. **同一事实只说一遍**：状态/阶段/卡点唯一落点在结论头。
2. **未达成不画空表格**：未提交产物显示解释性空态。
3. **缺口必须响亮**：「该有而没有」进②段常驻，不藏折叠区。
4. **可得性三态**：成本段三态（正常 / 部分数据 + 说明缺哪段 + 标为下界 / 无快照），**禁止用 0 冒充**。
5. **档位不越界**：窄面禁止渲染完整档内容（"影响对话"的根源）。
6. **注释与实现同步**：死代码（`buildTaskColumns` / `renderProcessFold`）要么接上要么删。

## 6. 怎么打开

直接双击 HTML（零依赖、不发请求）。

- 重构稿：`?surface=page|panel|header` × `?state=inflight|terminal`；档三支持锚点深链（`#now` `#gaps` `#gates` `#exec` `#accept` `#dialog` `#history` `#cost` `#prompt` `#refresh`）
- 基线标本：`?tab=overview|execution|timeline|archive|token`

**评审辅助参数**（原型专用，生产不实现）：

| 参数 | 作用 | 为什么需要 |
|---|---|---|
| `?open=1` | 展开全部折叠段 | 折叠内容截不到，评审看不到就等于没画 |
| `?only=<段id>`（逗号分隔） | 只留指定段 | 逐段细看/逐段截图；整页已 ~6 700px |
| `?diag=1` | 输出布局诊断到 `#diag`（视口宽 / scrollWidth / 页高 / 横向溢出元素清单） | 溢出这类缺陷在缩略图上肉眼会漏，用数字说话 |
| `?top=1` | 强制显示浮动「↑ 顶部」 | 其可见性绑在滚动上，headless 锚点滚动不触发，截不到 |

逐段截图命令（PowerShell/bash 通用思路）：`?surface=page&open=1&only=gates` 之类，窗口宽务必显式传 `--window-size=1280,<高>`——**漏传会用默认 ~800px，量出来的换行是假的**（原型自己踩过，见坑记 4）。

⚠️ 原型自身踩过的坑（已修，记录备查）：
1. 三档的显示切换用 `body[data-surface] .face-*`，但 `.face { display:none }` 匹配的是**类名 token**——`face-page` ≠ `face`，导致 page 面在其它档位不被隐藏。生产实现请用**单一开关源**（只渲染当前档位，而不是渲染三份再 CSS 隐藏）。
2. 去掉目录后把 `.doc` 改成 `display:block`，却被 `body[data-surface="page"] .face-page { display:grid !important }` 压回旧栏宽（186px），**版面塌成窄柱**——`!important` 的栅格定义是隐性继承源，改骨架时必须同时改它。
3. 浮动「↑ 顶部」的显示条件是"滚过一屏"，而 headless Chrome 下**锚点滚动不触发**（`data-show` 始终 0）→ 截图验证不了。为此加了评审开关 **`?top=1` 强制显示**（仅原型用）；真实浏览器里滚一下即可看到。这也提醒生产实现：不要把"可见性完全绑在滚动事件上"，深链进入时首帧要补算一次（现已在 `load` + 350ms 兜底）。
4. **量错比画错更贵**：逐段截图时漏传 `--window-size` 的宽度 → Chrome 用默认 ~800px → DAG 三个节点折成三行，我一度把它当成"flex 换行的锅"写进注释。实际是**测量环境**的问题。教训：① 截图必须显式给窗口尺寸并回读 PNG 真实像素；② 结论先落到"能不能被复现"，再写进代码注释。
