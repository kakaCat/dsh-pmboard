### 为什么新增卡还会带占位符（根因，已实测）

**运行中的插件加载的是构建产物，不是 `src/`。** 本需求的回填修复落在 `src/application/internal/lazy-expand.ts`，
而 reqboard 宿主在**启动那一刻**就把 bundle 读进内存了——此后我改 `src/`、甚至重跑 `pnpm build`，
**当前进程仍在跑旧代码**。于是本会话期间由这个进程新落的卡（我这个需求的、以及其它并行窗口的）
仍然是未回填的模板原文。

三条可复核的旁证：

```
$ grep -c "fillStageAcceptance(spec.acceptance" src/application/internal/lazy-expand.ts
1                                    # 源码里回填在位

$ grep -o "子卡验收标准回填后仍残留占位符" dist/index.mjs
子卡验收标准回填后仍残留占位符            # 构建产物里也有回填（某个窗口跑过 pnpm build）

$ 本需求自己的 26 张任务卡：带占位符 17 张
```

第三行尤其能说明问题：**我这个需求的子卡**（`t-6d2ddc` / `t-5b3e2a` / `t-e03744` …）也带着
`` `npx vitest run <本卡改动涉及的测试文件>` ``——它们是本会话用**尚未加载修复的运行时**落的，
不是"修复没写对"。
