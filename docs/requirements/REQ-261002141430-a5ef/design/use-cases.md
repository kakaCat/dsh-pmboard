> 本文件只承载需求文档放不下的**多角色/多分支**场景；单线条行为已在 requirement.md 的 FR 里写清。

| 场景 | 角色 | 触发 | 完成标志 | serves |
|---|---|---|---|---|
| UC-1 | 驾驶 reqboard 的 agent + 看板前的人 | 产物提交后自动弹框（宽限内未作答） | 自动链停手，且作答后无需人工催办即续跑 | FR-1, FR-3 |

## UC-1 提交产物 → 弹框在途 → 停手 → 作答 → 续跑 `serves: FR-1, FR-3`

- **用例角色**：驾驶 reqboard 的 agent（主）+ 在弹框里裁决的人。
- **前置条件**：需求 `armed`；本窗口无其他挂起确认；弹框通道可用。
- **交互流程**：
  1. agent 调 `reqboard_submit`，产物登记成功 → 后台自动弹框（2 秒宽限）；
  2. 人不在旁，超宽限 → 登记挂起 ticket，`reqboard_submit` 立即返回 `pending=true`；
  3. **本需求生效点**：弹框在途 → 登记在途 + 写停手位 → 自动链停手（不投回合、不派卡）；
  4. 人回来点「确认」→ 后台落章 + 推进 → 清停手位 → 自动续跑一回合。
- **异常流**：
  - 人选「需修改」→ 不落章、不推进，但**同样清停手位**（agent 必须能回来按意见改）；
  - 人在看板点确认（不走弹框）→ `confirm-settle` 收敛点清停手位，续跑同源；
  - 弹框通道不可用 → 不登记在途（`fallback=board`），走看板确认。
- **后置条件**：`driverHealth` 无 `awaiting-confirm:` 前缀；台账有两条留痕（进入等待 / 解除等待 + 出口）。
- **完成标志**：从"人回来点确认"到"agent 收到下一回合"之间，人**不需要**再打一句"继续"。

## UC-2 无弹框的自动流程照跑 `serves: FR-1`

- **用例角色**：驾驶 reqboard 的 agent。
- **前置条件**：本窗口无在途弹框（在途表为空）。
- **交互流程**：1. 需求处于 `implementing` 且 `autoRun=true`；2. 一张子卡完成 → 链推下一张；3. Dive 起下一回合。
- **异常流**：在途表非空但 `ref` 已 `exit` → 视为无在途（不得因残留条目停手）。
- **后置条件**：投递次数、派卡次数与改动前**逐字一致**。
- **完成标志**：反向用例 TC-4 绿——本需求对非门禁流程**零影响**。

## UC-3 Dive 主动弹人工门框 `serves: FR-5`

- **用例角色**：Dive 驱动器（弹框发起方）+ 看板前的人。
- **前置条件**：需求停在某人工门（产物已登记未确认，或产物已确认但状态未推进）。
- **交互流程**：
  1. agent 空闲 → 跑批 → 门状态判定命中 → **先登记在途**、再弹框；
  2. 同一拍的 `requestDrive` 因判据为真而跳过（不再"框刚弹出、agent 就跑"）；
  3. 人作答肯定 → `applyConfirmDecision` 落章/推进 → 清停手位 → 下一次 idle 拍照常起轮。
- **异常流**：弹框抛错 → 吞掉降级 + 立即清停手位（不得留下永久停手）；到重弹上限 → 既有"到顶留痕停手"语义不变。
- **后置条件**：停手位与在途表同步、成对出现与消失。
- **完成标志**：TC-7 绿——同一拍内不存在"在途弹框 + 新投回合"。

## UC-4 过期与重启后的兜底恢复 `serves: FR-4`

- **用例角色**：值班的人 + 周期心跳（系统）。
- **前置条件**：停手位存在（`reason='awaiting-confirm:*'`），而在途表为空（人一直没答、TTL 过期；或插件重启）。
- **交互流程**：
  1. 心跳 tick 先跑"停手对账"一趟；
  2. 命中"停了但没人等"→ 清停手位 + 台账留痕说明原因；
  3. 后续 idle 拍照常起轮。
- **异常流**：对账写失败 → 告警 + 保留停手位（下一趟重试），不阻断既有唤醒趟。
- **后置条件**：需求回到可驱动；没有人需要手动打"继续"。
- **完成标志**：TC-6 绿——"停了没人叫醒"这一形态在本需求后不可复现。
