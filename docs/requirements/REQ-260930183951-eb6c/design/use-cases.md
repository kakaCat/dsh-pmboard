## UC-1 提交验收：有子卡的交付（主场景） serves: FR-1

| 项 | 内容 |
|---|---|
| 触发 | 实施 agent 在需求执行/验收态调 `reqboard_submit(kind=verification, summary, evidence)` |
| 前置 | 队列里有 1 张父卡（无 `parentId`）+ 3 张子卡（`parentId` 指向父卡），均 `done` |
| 主流程 | ① 读队列任务 → ② `toSheetTasks` 剔 `canceled`、**保留 `parentId`** → ③ `buildSheet` 再过滤一次 `parentId !== undefined` → ④ 编号连续分配 |
| 可见结果 | 验收单任务项 **只 1 项**（父卡）+ 需求级项 + 系统项；子卡不出独立验收项 |
| 验收判据 | `sheet_items === 2`（无系统项时）；`items.filter(source.kind==='task')` 长度为 1 |
| 为什么重要 | 现状事故：2d65 的 29 张卡交付产出 29 个任务项（含 23 张子卡），同一交付被重复验收 |

**备选流**：一次提交里既有父卡又有存量卡（无 `parentId`）→ 两者都进验收单（存量卡本就是顶层）。

## UC-2 提交验收：验收标准引用了不存在的测试文件 serves: FR-2

| 项 | 内容 |
|---|---|
| 触发 | 同上；某任务卡的 `acceptance` 写着 `npx vitest run tests/submit-verification.test.ts`，而该文件已改名/不存在 |
| 主流程 | ① `collectMissingAnchors` 从 `acceptance` 提取 `tests/*.{test,spec}.*` 路径 → ② `docs.exists` 判定 → ③ 非空则透传 `anchorGaps` → ④ `buildSheet` 追加一条需求级可见项 |
| 可见结果 | 验收单多 1 项：「验收锚点失效：以下验收标准引用的测试文件在仓库中不存在——<卡> → tests/…」 |
| 关键语义 | **不阻断提交**（人仍可裁决）；通过该项时须写处置说明（由既有 `applyVerdicts` 强制，本需求不加新规则） |
| 为什么重要 | 现状事故：2d65 的验收单有 5 个项引用了 3 个不存在的测试文件，人照抄执行必然失败 → 只能形式合规点过 |

**备选流**：所有锚点都存在 → 不追加项（不制造噪声）。
**边界**：只认 `tests/` 下的 `*.test.*` / `*.spec.*`；`docs/*.md`、`src/*.ts` 不参与（evidence 存在性另有硬拦）。
**护栏**：工作区连 `tests/` 目录都没有（裸夹具/非本仓布局）→ 整段跳过，不把"全量缺失"当结论。

## UC-4 异常与降级 serves: FR-1, FR-2, FR-3

| 异常 | 期望行为（明确方向） |
|---|---|
| 队列里某任务缺 `parentId` 字段 | 视同顶层卡（进入验收单）——不猜、不静默丢弃 |
| `parentId` 为空串 | 归一为顶层卡（返回对象不写该键），避免 `''` / `undefined` 两态 |
| 工作区里没有 `tests/` 目录 | 锚点探针整段跳过（读数未知不追加）；**不**因此阻断提交 |
| 锚点指向的文件确实不存在 | 产出可见项；**不**阻断提交，由人裁决并写处置说明 |
| `acceptance` 为空 | 不参与锚点提取（既有"不可照着验"探针另行点名，职责不重叠） |
| `docs` 端口未装配 | 不在本层兜（`deps.docs` 是必填端口）；探针只调 `exists`，无异步失败面 |
| 提交被既有门禁拒绝（文档不齐 / 覆盖度不足） | 走既有拒绝路径，本需求不改其口径 |
