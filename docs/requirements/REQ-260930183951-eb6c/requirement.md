## 2. 产品定义

REQ-260930094139-2d65 把「验收纪律」做成了代码级硬约束，它的验收阶段却给出了反证：**交付物没有在产出验收单的那个运行实例中生效**，于是验收单呈现的正是它要修掉的三个旧行为（子卡注水、断链静默、时间戳塌缩）。更危险的是第二类问题——验收单的操作步骤引用 3 个不存在的测试文件，人按单执行会直接失败，此时人只有两个选择：误判「不通过」，或形式合规地点「通过」；后者恰恰是 2d65 立项要治的事故形态。

本需求只修**代码层的真实缺陷 + 验收单可读性**，让「验收单可用」这一前提成立：①把 `parentId` 真的投影进验收单输入，让 domain 二次过滤从「只有测试能证明」变成「生产也成立」；②给验收锚点加存在性校验，锚点指向不存在的文件时生成可见提示项（与既有孤儿/断链提示同构）；③让系统项编号连续、标题按缺口类型区分，消除「跳号 + 重名」。

## 3. 用户与角色

- **验收人（PM/需求方）**：要一张**规模真实**（不被子卡注水）、**步骤可执行**（锚点指向真实文件）、**编号连续**（不疑心少了两项）的验收单。
- **实施 agent**：交付后重新提交验收时，验收项的操作步骤必须是真能跑的；开工时若改了测试文件名，需要一条机制提醒自己回写设计。
- **流程维护者**：依赖 `rtm-lifecycle.yml` 做阶段耗时复盘的人（本需求不修 FR-4 的生效问题，但要在验证里如实记录它仍未生效）。

## 4. 功能点

- **FR-1**: 任务投影补 `parentId` —— `SubmitVerification` 构建 `buildSheet` 输入时透传 `parentId`，使 `AcceptanceSheetSpec.buildSheet` 的 domain 侧二次过滤真正生效；并补一条**经 use case 全链路、调用方故意不做过滤**的用例（构造 1 父 3 子，断言验收单任务项 = 1 项），该用例在「把 `parentId` 从投影里删掉」时必须变红。
- **FR-2**: 验收锚点存在性校验 —— 生成验收单时扫描验收项的「操作步骤」中形如 `tests/xxx.test.ts` 的路径，若该文件在工作区不存在，则生成一条**需求级可见提示项**（`gapKind: 'consistency'`，与既有孤儿用例 / 追溯断链提示项同构，**不阻断提交**），文案列明失效锚点与「请改锚点或回写设计」。探针失败/工作区无 `tests/` 目录 → 不追加项（读数未知不追加）。
- **FR-3**: 系统项编号连续 —— `buildSheet` 里五类系统项不再使用固定预留位 `taskCount+2..+6`，改为**按实际生成顺序连续编号**，消除 `v1-31`/`v1-32` 这类空洞。
- **FR-4**: 需求级项标题按缺口类型区分 —— `VerificationDoc` 渲染与另两处消费点不再统一标题为「需求级验收」，而是按 `gapKind`（缺省 / `e2e` / `orphan` / `consistency` / `traceability`）+ criterion 前缀给出可区分标题（如「需求级验收 · E2E 覆盖」「· 锚点失效」「· 不可照着验」），消除验收结果表里多行同名。

## 5. 边界

**做**：
1. **投影修复（FR-1）**：`SubmitVerification` 透传 `parentId` + 一条能证伪投影的用例。
2. **锚点守卫（FR-2）**：验收单生成时校验 `tests/*.test.ts` 锚点是否存在，缺失即生成不阻断的可见提示项。
3. **可读性（FR-3 + FR-4）**：系统项按实际生成顺序连续编号；需求级项标题按缺口类型区分。

**不做**：
1. 不改 2d65 已交付三条 FR 的**判定语义**（`passed` 必填意见、断链提示项、`statusHistory` 读法一律不动）。
2. 不回填历史验收单（已生成的单保持原样，新规则只作用于**重新生成**的单）。
3. 不代 2d65 重新走验收流程（「重建生效 → 重交 verification → 重新生成验收单」是运维动作，在本需求验证阶段作为**验证步骤**执行一次并如实记录，不写成产品功能）。

**升级信号（出现即停手并升重档）**：需要改 `VerificationItem` / `VerificationSheet` 的持久化结构（新增必填字段）、需要改裁决 API 契约、或 FR-2 需要引入新的文件系统端口。

## 6. L1 一句话目标 + 可证伪判定标准

**目标**：修掉让 2d65 验收单「规模失真、步骤不可执行、编号跳号」的三个真实缺陷，使验收单重新成为可信的裁决依据。

**可证伪判定标准**：
1. 构造「父 1 + 子 3」的提交场景 → 验收单任务项 **= 1**（仅父卡）；把 `toSheetTasks` 投影里的 `parentId` 删掉 → 投影用例**变红**。
2. 验收标准里写 `tests/foo-not-exist.test.ts` → 验收单多出一条「锚点失效」提示项并列出该路径；全部锚点都存在 → 不出现该项。
3. 触发 E2E 缺口（`e2eCoverage=false`）的验收单编号**连续无空洞**；验收结果表中需求级项标题不再是多行同名。
4. `npx vitest run tests/sheet-projection.test.ts tests/sheet-anchor-gaps.test.ts tests/sheet-items-format.test.ts` 全绿；`npx tsc --noEmit` 错误数不高于基线（220）。
