## 2. UC-1 维护者加一个工具后同步 `serves: FR-1, FR-2, FR-3, FR-4`

- **用例角色**：插件维护者（人），在本仓干活。
- **前置条件**：本需求已交付（README 表 27 行、登记面 27 条、两条校验用例在场）。
- **交互流程**：
  1. 维护者在 `src/tools/` 下新建 `XTool/` 并实现工厂。
  2. 在 `src/tools/registry.ts` 补一条登记（`key` / `factoryFile` / `dir` / `toolName` / `responseSources`）。
  3. 在 `src/index.ts` 注册工厂（日志名单**自动**跟着登记面走，无需手改）。
  4. 在 `README.md` 的工具表里补一行（放在对应分组）。
  5. 跑 `pnpm vitest run tests/readme-tool-face.test.ts`。
- **异常流**：
  - 忘了第 4 步 → 用例红，消息 `README 缺：reqboard_x`；补上即绿。
  - 忘了第 2 步 → 既有门禁红（`tests/tools-dispatch` 的目录集合 / `tests/apply-wiring` 的注册名单）。
  - 第 4 步把工具名写错（如 `reqboard_xx`）→ 用例红，同时报"缺 `reqboard_x`"与"多 `reqboard_xx`"。
- **后置条件**：登记面、磁盘目录、注册名、README 表四处一致；日志名单自动一致。
- **完成标志**：`pnpm test` 全绿，且 `git diff` 里没有任何手改的数字。

## 3. UC-2 新窗口 agent 照 README 找工具 `serves: FR-1`

- **用例角色**：窗口 agent（新开窗口接管一条需求，上下文里没有本插件的任何记忆）。
- **前置条件**：本需求已交付。交付前该场景会坏（见异常流）。
- **交互流程**：
  1. agent 读 `README.md` 的「提供的工具」一节。
  2. 按用途分组找到需要的工具（如"跨窗口协作"组里的 `reqboard_handoff` / `reqboard_bind`）。
  3. 直接调用该工具。
- **异常流**：
  - **交付前**：协作组的三个工具该 agent 在 README 里根本看不到（`handoff` / `skill_install` / `task_refs` / `archive_amend` 缺失），
    它只能靠 `reqboard_status` 返回的提示词兜——文档少列 4 个、多列 1 个不存在的名字。
  - 照 README 调 `reqboard_advance` → 工具不存在（宿主无此名），调用失败。
- **后置条件**：agent 对工具面的认知与事实一致。
- **完成标志**：README 里能找到全部 27 个工具，且不存在任何未注册名字。

## 4. UC-3 漂移被门禁拦下 `serves: FR-1, FR-2, FR-3, FR-4`

- **用例角色**：评审者 / 验收人。
- **前置条件**：本需求已交付。
- **交互流程**：
  1. 评审者跑 `pnpm vitest run tests/readme-tool-face.test.ts tests/registry-log.test.ts`。
  2. 两个文件全绿。
  3. 评审者随机做一次逆验证（删 README 一行 / 改表头计数 / 改登记面）→ 复跑 → 红并点名。
  4. 还原 → 复绿。
- **异常流**：
  - 用例恒绿（断言写空）→ 第 3 步不会红，评审者据此判定交付不合格（逆验证是本需求的验收红线）。
  - 只改了源码注释没改 README → T-8 的静态闸门与 T-1 的集合断言各自从不同角度拦。
- **后置条件**：评审者对"工具面清单可信"有可复核依据（命令 + 读数），而不是"看着对"。
- **完成标志**：正向绿 + 逆验证红，两者都复现过。
