## TL;DR

模型写完工汇报时，把大段中文连引号一起塞进 `reqboard_task_report` 的参数，**只要有一处引号没转义，整个回合就报废**：本轮推理、文本、其它工具调用全部作废，汇报永远落不了库，实施链卡住。

本需求把"怎么写这类长文本参数"从**靠模型自觉**变成**工具描述里写死的约定 + 实施阶段提示词里的一条纪律**，把踩坑概率压下来。

失败粒度（"一处坏 JSON = 整轮失败"）在 DSH 核心，不在本仓——那部分明确**不做**，另立需求（见「边界」）。

```
            任务卡 lastReport 永不写入
            → 复核子卡永远 in_progress → 整条链停摆（t-f81376 实测）
```

## 根因

**触发点（本仓能治）**：这类工具的入参是**长中文自由文本**，而模型对"字符串里的半角双引号"转义并不稳定；现状的工具描述里**只有长度上限，没有"怎么写"的约定**（`src/tools/TaskReportTool/prompt.ts` 只说了参数是什么）。

**放大点（本仓治不了）**：DSH Messages 适配器在流收尾处要求工具参数 JSON **完全合法**，且**不做局部降级**（`deepseek-harness/packages/llm/llm-deepseek/src/translate.ts:149-158`：只有 `max-tokens` 截断被豁免）。于是失败的粒度是**整轮**，而不是"这一次工具调用失败、模型看到报错再试一次"。

两个层次的边界，正是本需求「边界」一节的核心。

## 本需求要修的条款

- **FR-1: 汇报工具的入参写清"怎么写"**——`reqboard_task_report` 的工具描述与参数说明里写死三条约定：`completed` 每条为**短句**（建议 ≤60 字）；正文**避免半角双引号**（需引号时用中文「」『』）；**单次汇报文本过大时拆成多次调用**（本工具幂等追加，天然支持分段）。
- **FR-2: 同类长文本工具共用同一份约定**——把上述约定抽成**一处共享文本**，覆盖 `reqboard_task_report` / `reqboard_submit` / `reqboard_ask_confirm` / `reqboard_task_move` / `reqboard_capture` / `reqboard_note_interruption` 的长文本字段说明；并用一个用例**遍历这些字段**，断言约定在场（防"只改了一处、下次换个工具又踩"）。
- **FR-3: 实施阶段提示词加一条汇报纪律**——`implementing` 阶段片段（轻档 + 重档 + 本仓 overrides）里加一行：汇报前自检"正文无半角引号、`completed` 每条短句、太长拆多次"，并按 C-16/C-17 重生成与校验产物。

## 产品定义

**是什么**：把"写长文本工具参数时如何避免踩 JSON 转义坑"做成**工具与提示词自带的约定**，而不是留给模型临场自觉。

**核心价值**：少一次整轮报废 = 少一次"做完的活全丢 + 链停摆 + 人手动重推"。这不是让报错更好看，是让**失败不发生**。

**与现状的区别**：

| 维度 | 现状 | 修复后 |
|---|---|---|
| 谁负责避免 | 模型临场自觉（无任何文本引导） | 工具描述写死的约定 + 阶段提示词的一条自检 |
| 覆盖范围 | 无 | 报告 + 同类长文本工具（共享一处文本） |
| 出错时 | 整轮失败，无提示（本次事故） | 概率下降；真正的粒度修复另立需求（见「边界」） |

**三要素检查**：

- [x] 说清"是什么"——工具描述与阶段提示词里的**写法约定**（不是代码逻辑）
- [x] 说清"核心价值"——整轮报废的概率下降
- [x] 说清"与现状的区别"——从"无引导"到"约定 + 自检 + 覆盖面"

## 功能点（需求条款）

### 功能点清单

| 编号 | 功能（一句话概述） | 优先级 |
|------|------------------|--------|
| FR-1 | 汇报工具的入参说明写清"怎么写"：短句、「」代引号、大汇报拆多次 | P0 |
| FR-2 | 约定抽成一处共享文本并覆盖同类长文本工具，用遍历用例守住覆盖 | P0 |

### 功能点详细说明

**详细说明 · FR-1**

- **使用场景**：模型准备调 `reqboard_task_report` 时，读到工具描述与每个参数的说明。
- **操作流程**：
  1. 模型读到 `completed` 的说明：每条短句 ≤60 字、别用半角引号、要引号用「」。
  2. 读到工具描述里的分段指引：文本大就拆成多次调用（幂等追加，不会重复登记产物）。
  3. 模型按此生成参数——入参 schema 一字不改。
- **预期结果**：
  - 结果 1：`TASK_REPORT_PROMPT` 含三个可断言的锚点（短句上限、「」代引号、拆多次调用）。
  - 结果 2：工具入参字段名/类型/必填/长度上限**零变更**；拒绝码与落盘格式**零变更**。
- **边界条件**：
  - 边界 1：历史调用（老参数写法）行为不变，不新增拒绝。
  - 边界 2：用户自定义的 `completed` 文案仍原样落盘，不做改写。

**验收标准 · FR-1**：

1. `npx vitest run tests/arg-guidance.test.ts`（规划名）断言 `TASK_REPORT_PROMPT` 同时命中三锚点。
2. 反向：把任一锚点从描述里删掉 → 该用例必须**红**（证明确实在守）。

**详细说明 · FR-2**

- **使用场景**：任何"要模型写一段中文"的工具入参（提交材料、确认问题、改验收标准、立项摘要、断点原因）。
- **操作流程**：
  1. 约定文本收敛到一处（如 `src/tools/shared.ts` 的常量）。
  2. 各工具的长文本字段说明引用它（不复制粘贴）。
  3. 用例遍历"工具 × 长文本字段"清单，逐项断言约定在场。
- **预期结果**：
  - 结果 1：清单内每个字段的说明都含共享锚点；清单缺项（新增工具未接入）时用例给得出缺失名单。
  - 结果 2：新增同类工具时，用例**自动**把它纳入检查范围（或显式失败要求登记）。
- **边界条件**：
  - 边界 1：`files_changed` 这类**路径**字段不纳入（路径里本来就不该有引号，另有归一化在管）。
  - 边界 2：纯英文短字段（如 `task_id`）不纳入，避免描述膨胀。

**验收标准 · FR-2**：

1. `npx vitest run tests/arg-guidance.test.ts` 里"遍历断言"用例全绿，且失败时输出缺失字段清单。
2. 反向：新增一个长文本字段但故意不接约定 → 用例必须**红**。

**详细说明 · FR-3**

- **使用场景**：实施阶段（implementing）每次落完工记录之前。
- **操作流程**：
  1. 在轻档 / 重档 / 本仓 overrides 的实施片段里各加一行汇报纪律。
  2. 跑 `node scripts/inline-prompt-fragments.mjs` 重生成产物（C-16）。
  3. 跑 `node scripts/check-prompt-fragments.mjs` 校验片段与产物一致（C-17）。
- **预期结果**：
  - 结果 1：注入到模型的实施提示词里能看到这条纪律。
  - 结果 2：片段与生成产物一致，C-16/C-17 两条命令退出码 0。
- **边界条件**：
  - 边界 1：heavy 片段受 C-17 约束（须与 vendor 原文一致）——只加在与 vendor 无关的覆盖层，不改受约束的正文。
  - 边界 2：提示词注入预算（C-03）不得因这一行被裁掉保底项。

**验收标准 · FR-3**：

1. `node scripts/inline-prompt-fragments.mjs` 与 `node scripts/check-prompt-fragments.mjs` 退出码均为 0。
2. 反向：手工改一份生成产物使其与片段不一致 → `check-prompt-fragments` 必须**非零退出**。

## 边界（不做什么）

- **不做**：不改 DSH 核心的 DeepSeek Messages 适配器（`deepseek-harness/…/llm-deepseek/src/translate.ts`）——"坏 JSON 要不要修复 / 要不要把失败粒度从整轮降到单次调用"是跨仓且带独立决策点的改动，**另立需求**（本需求文档只把它作为根因记录与后续项）。
- **不做**：不改任何工具的入参 schema（字段 / 类型 / 必填 / 长度上限）、不改拒绝码与错误文案结构、不改落盘格式与幂等语义——本需求只加**文本引导**。
- **不做**：不做"自动修复模型输出"（不新增二次 LLM 调用改写汇报、不加客户端正则洗文本）——那会把"响亮失败"换成"静默改数据"。

## 接口与数据契约（feature 档）

| 项 | 结论 |
|---|---|
| 对外入口 | 工具描述文本（`description` 与各参数 `description`）、阶段提示词片段文本 |
| 输入 / 输出 | **零变更**：入参字段与返回体一字不改 |
| 数据契约 | **零变更**：不新增字段、不改必填性、不改版本 |
| 迁移与兼容 | 无需迁移；老窗口/老调用行为不变；回滚 = 还原描述文本（无数据影响） |
| 谁调用 | 由 agent 在 implementing 阶段调 `reqboard_task_report`；描述随工具定义注入模型 |

## 验收标准（整体）
