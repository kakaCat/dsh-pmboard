# 需求说明（REQ-261005193546-1b1a 看板不再展示已取消卡：视图与统计都不再算上退出赛道的卡片）

> 本文档面向：产品、开发、测试、用户——**写给人看，不是写给代码看**。
> 触发场景：上一条需求（REQ-261005105032-3b02）两次回退产生 26 张已取消卡，验收时暴露两个后果——
> ① 看板「DAG 层级」把它们与在位卡混在一起显示，人一眼读成「132 张里 26 张没做完」；
> ② 测试覆盖度门把已取消卡算进分母，覆盖度上限只有 106/132 = 80.3%，**刚过 80% 阈值**，
> 再多取消几张这条需求就交不上验收——门禁在惩罚「回退」这个正当动作。

## TL;DR <!-- serves: FR-1 -->

**让退出赛道的卡片从看板与统计里彻底消失，但台账留活口。**
看板上你只会看到「该做的卡」；进度、覆盖度、甘特、追溯也都按「该做的卡」算。已取消的卡不进界面、不进分母，但一条都不删——它们在台账里，需要复盘时查得到，并且从今以后取消时会记下**谁、何时、为什么**。

```
                      +-------------------------------+
   台账（唯一事实源）  |  106 张活卡  +  26 张已取消卡  |
                      +---------------+---------------+
                                      |
                            活卡过滤（FR-4 单点判据）
                                      |
        +-----------------------------+-----------------------------+
        v                             v                             v
  DAG 层级（FR-1）            进度 / 甘特 / 计数（FR-2）      覆盖度门（FR-2）
   显示 106 张                  按 106 算                     分母 = 106
   取消卡 0 处                  取消卡 0 处                   撤销对回退的惩罚
        |                             |                             |
        +-----------------------------+-----------------------------+
                                      v
                        界面一处都不出现取消卡（FR-5 / D-7）
                        台账与任务文档全部保留（FR-5 / FR-6）
                        取消留痕：谁 / 何时 / 为什么（FR-3）
```


## 边界 <!-- serves: FR-1 -->

**做**：已取消卡退出所有界面与统计；统一「活卡」判据为一个单点；取消动作留下人/时间/原因；旧数据零迁移。

**不做**（明确划出，避免范围膨胀）：
- **不物理删除任何卡片**——卡片 id 被父卡依赖、子卡链、追溯覆盖度、需求评论引用，且它是回退事故的第一手证据；删数据会同时破坏审计线与引用完整性。
- **不做「显示已取消」开关**——按用户裁定：彻底不可见。
- **界面不给任何计数交代**（连「另有 N 张已取消」这样一行都不给）——按用户裁定。
- **不改「取消 = 人工门」这条属性**（agent 仍无权取消），也不改取消卡的历史文档与追溯文件。
- **不改现有统计的计量粒度**（一卡一行的地方仍一卡一行），只做「剔除已取消」这一件事。

## 产品定义 <!-- serves: FR-1 -->

**「活卡」**：状态不是 `canceled` 的任务卡。它同时是**界面展示的集合**、**统计的分母**、**依赖判定的对象**。

**「退出赛道」**：卡片被取消（人工门动作），从此不参与交付，也不该继续影响任何读数。它是**逻辑退出**，不是物理消失。

**「一个口径」**：视图、进度、覆盖度、甘特、追溯、详情计数，全部使用同一个「活卡」判据——不允许某处漏了、某处又算上（这正是本次要修的病）。

## 用户与角色 <!-- serves: FR-2 -->

| 角色 | 他要什么 | 现在的问题 |
|---|---|---|
| **交付负责人（看板的人）** | 一眼看出这条需求还剩多少卡 | 被已取消卡干扰，误读成"没做完" |
| **验收的人** | 验收材料的前置门按"该做的卡"判 | 覆盖度分母含已取消卡，回退被惩罚成覆盖率不足 |
| **复盘的人（事故调查）** | 能查到"当初谁因为什么取消了这些卡" | 取消只有评论里的自由文本，无结构化留痕 |
| **维护者（本仓开发）** | 判据只有一个来源，不会四处漂移 | 同一口径四处实现，两处做了两处漏了 |

## 功能点 <!-- serves: FR-1 -->

- **FR-1: 已取消卡退出「DAG 层级」视图，且不阻塞活卡的依赖**
  看板「DAG 层级」（阶段详情）不再列出已取消卡；与依赖图、文档面板的既有口径一致。
  **取消卡不构成依赖阻塞**：活卡的依赖若指向已取消卡，该边按「已满足」处理——活卡不因它掉层或成孤岛（被取消的卡永远不会完成，把它当未满足会把活卡永久卡死）。
  判据：同一标本改前显示 132 张、改后只显示 106 张；活卡拓扑层号与"把取消卡的边删掉"重算的结果一致。

- **FR-2: 一个口径贯穿全部统计**
  凡「该完成的卡」的分母一律剔除已取消卡：**测试覆盖度门（验收前置）**、看板进度与完成度、甘特、需求详情页计数、追溯。
  判据：上一条需求（REQ-261005105032-3b02）的测试覆盖度从 **80.3% → 100%**（26 张已取消卡不再计入分母）；同一需求看板进度与追溯读数一致。

- **FR-3: 取消动作留下「谁 / 何时 / 为什么」**
  取消卡片时写入取消时间、取消人（kind + 会话/操作者）、取消原因。字段为**加性可选**：旧数据缺字段 = 未采集，不补齐、不改写、无迁移脚本。
  判据：取消一张卡后台账三字段均有值；旧分片（无三字段）经生产读路径读取不报错、不产生写回。

- **FR-4: 「活卡」判据收敛为单点**
  过滤逻辑收敛为一个导出纯函数 + 一个同源的"计数/分母"helper；所有消费点复用它（顺带收编现在手写的两份 filter）。
  判据：源码级断言——消费点不得再各写一份 filter（删掉复用改为手写即红）。

- **FR-5: 界面不出现，台账不消失**
  已取消卡不被任何界面投影返回；但台账记录与任务卡文档仍在磁盘，审计与归档路径可读（归档材料可引用计数）。
  判据：界面投影里取消卡条数为 0；同一份台账里取消卡记录数与磁盘任务文档数不变。

- **FR-6: 兼容与不追溯**
  旧数据读取零异常；历史追溯文件与任务卡文档不删除、不改写；已取消卡不回填新字段。
  判据：全量存量需求目录读取零异常；读取前后目录逐字节一致（无写回）。

## 验收标准 <!-- serves: FR-2 -->

分组列出，每条都可执行：

**A. 视图（FR-1 / FR-5）**
1. 标本需求（132 张卡、26 张已取消）在「DAG 层级」只显示 106 张；断言取消卡条数为 0。
2. 活卡的依赖若指向已取消卡，该活卡层号与"删掉该边后重算"一致（不掉层、不成孤岛）。
3. 依赖图、文档面板、详情计数的取消卡条数同为 0。

**B. 统计（FR-2 / FR-4）**
4. 同标本的测试覆盖度门分母为 106（不是 132），覆盖度为 100%。
5. 上一条需求（REQ-261005105032-3b02）重跑验收前置：覆盖率 80.3% → 100%。
6. 源码级断言：把任一消费点的复用改回手写 filter → 用例必红。

**C. 留痕与兼容（FR-3 / FR-6）**
7. 取消一张卡后台账三字段有值（人/时间/原因）。
8. 旧分片（无三字段）读取不报错、值未采集、全量读取不写盘（mtime 逐份不变）。
9. 历史追溯与任务卡文档未被删除或改写。

## 迭代计划 <!-- serves: FR-4 -->

1. **第一批（最小闭环）**：活卡单点 + 补上两处漏掉的过滤（DAG 层级、覆盖度分母）+ 收编两份手写 filter + 防漂移断言。
2. **第二批**：取消留痕三字段（写侧 + 读侧兼容）+ 验收前置口径复核。
3. 存量不追溯：只为将来取消的卡留痕，历史取消卡如实标注未采集。
