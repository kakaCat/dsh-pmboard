## 边界与假红防线 <!-- serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6 -->

| 边界 | 口径（用例必须照此写） |
|---|---|
| **brainstorming 期不适用** | 覆盖度门只在 `design` / `decomposing` / `accepting` 有阈值；`coverageGateOf` 不接受 `brainstorming`。用例在 early stage 显式**跳过并说明**，不许"跑过了但没有任何断言"（那不是绿，是空转） |
| **读数未知不判** | `syncRTMYaml` 读盘失败返回 `undefined` → `coverageGateOf` 返回 `undefined` = **不拦截**。用例必须断言 `undefined`，**不得**把它当 0、也不得当通过；"未知"与"0"是两个值 |
| **存量豁免** | 无 `requirement.md` / `artifacts` 为空的直种需求（S-5）走 `isLegacyForDocs` 豁免：探针为 `undefined`、不拦截。断言写「**豁免**」，不写「通过」 |
| **空集合（活卡 0 张）** | `coverage.total === 0`（S-6）→ **不拦截**；边界语义是"无项可判"，**不是**"0 张 = 100% 通过"、也不是"0 分被拒"。用例断言 `undefined` 并另行说明，不把它算成覆盖率满分 |
| **陈旧快照（存量需求永不触发 RTM）** | 取消动作发生在最后一次 RTM 触发**之后**的需求（S-9），其 `rtm-*.yml` 里 `task_to_tests` / `fr_to_tasks` **仍含取消卡**。用例**只断言"界面不出现取消卡行 / 无取消计数"**，**不**断言追溯行数 == 活卡数；**不**为了凑等式去裁剪或重算 RTM。四数相等的数值断言只对**新触发过 RTM 的**需求成立 |
| **假红防线 1：手写过滤基线** | 判据是「**新增**手写点即红」，**不是**「全仓零手写」。现状 54 处 / 34 文件，本需求只收编消费点与依赖判定各处；把"全仓零手写"写成判据会得到一个永远红或永远被跳过的假用例 |
| **假红防线 2：文档面板不变量** | 按**活卡口径**对账（`documents + Σdiscovered == 活卡产物数`）。若照旧按全量产物对账，则"界面不列取消卡产物"必然让恒等式永远对不上——那是设计缺陷，不是用例失败 |
| **假红防线 3：覆盖度改前对照是"两种"失败** | ① **压线通过但点名**：106/132 = 80.3%，`rate` 取整 **80**，恰好压阈值 ⇒ 通过、但 `uncovered` 点名 26 张；② **真被拒**：`covers` 标注为 0（S-3a，上一条需求真实发生的那次）→ `rate = 0` 被拒。**两种形态分列断言，不混成一条**；另加「再取消 5 张 → `rate < 80` 被拒」作为可证伪判据。**测试阈值语义不动**（不用改阈值来掩盖口径） |
| **假红防线 4：数值不是标量** | 106 / 26 / 94% 只是 **S-1 这一条标本**的数（原型里已注明这些是示意标本）。断言写**恒等式与关系式**（四数相等、差值 == 取消卡数、取消卡条数为 0），不把标量硬编码进生产代码 |
| **假红防线 5：三条判据不可互相替代** | "只删节点不剔边"时 `data-dag-task-count` 仍是 106（TC-1 / TC-4 会绿），**只有 TC-2 会红**；"不漏行但不能开工"时 TC-1/TC-4 绿、**只有 TC-3 会红**；"只修一条 RTM 入口"时其余全绿、**只有 TC-5 会红**。每条判据各自可失败，不允许合并成一条"综合检查" |
| **假红防线 6：存量目录零写回** | 全量读取的 mtime / 哈希比对必须覆盖**全部**需求分片与 `tasks/*.md`，不是抽样；抽样会让"只写回了几份"逃过 |
| **假红防线 7：防漂移用例必须独立** | TC-6 **新建独立文件**，**不挂进 `tests/layer-boundary.test.ts`**——那个用例当前本就红，把新判据挂进去等于把它埋在已知失败里（新网再响也看不见） |

## 关键决策与取舍 <!-- serves: FR-2, FR-4, FR-5 -->

| 取舍点 | 否掉的方案 | 选了 | 为什么（依据） |
|---|---|---|---|
| 判据写成标量还是恒等式 | 断言 `=== 106` | **恒等式 + 关系式**（四数相等、差值 == 取消卡数） | 106 是 S-1 标本的数；标量断言换个标本就假红，且会把"示意标本"当契约 |
| 防漂移的范围 | 全仓零手写 filter | **基线 + 新增即红** | 现状 54 处 / 34 文件；全收编等于把缺陷修复变成全仓重构，回归面不可控 |
| 逆验证放哪 | 人工评审清单 | **写进用例（改坏必红）** | 本仓的教训是"只测成功路径等于没测"；可失败的逆验证才是网 |
| 「能开工」要不要单独一条 | 并进 TC-2（层号对了就算通了） | **独立 TC-3** | 三处 ready 判定只有一处对，错的正是界面用的那处；层号对 ≠ 卡能开 |
| 覆盖度入口 | 只测会话工具那条 | **两条入口都测** | 只测一条时"两套分母"照样能在生产里并存 |
| 覆盖度"改前对照"写几条 | 只写"80.3% 被卡"一条 | **两种失败形态分列**：80.3% 压线通过但点名 26 张；`covers` 为 0 → 真被拒（S-3a，上一条需求真实发生的那次） | 两种形态的**错因完全不同**（一个是分母含取消卡，一个是根本没标注）；混成一条会掩盖真正的回归面 |
| 文档面板不变量 | 沿用全量产物的原恒等式 | **换成活卡口径** | 界面按 A3 不列取消卡产物；恒等式不重述就会永远对不上 |
| 只读投影与写盘的关系 | 读的时候顺手补字段（"反正要补"） | **读取零写回（mtime + sha256 逐份比对）** | FR-6 / D-5：零迁移、不追溯；隐性写回会污染历史证据 |
| 防漂移用例挂哪 | 顺手加进 `tests/layer-boundary.test.ts` | **新建独立文件** | 那个用例当前本就红；挂进去等于把新网埋在已知失败里，响了也看不见 |
| 追溯行数的断言范围 | 所有需求都断言"追溯行 == 活卡数" | **只对新触发过 RTM 的需求断言数值**；存量需求只断言"不出现取消卡行 / 无取消计数" | 存量需求永不触发 RTM ⇒ 追溯读数是含取消卡的**陈旧快照**（已知边界）；一刀切会得到永远红或被迫造假的用例 |

## 技术方案与亮点 <!-- serves: FR-2, FR-4, FR-6 -->

**测试分层**：

| 层 | 测什么 | 手法 | 为什么放这一层 |
|---|---|---|---|
| 纯函数 | 判据、分层、剪边、ready | 直接调 `domain/status/Predicates.ts` 的纯函数（`isLiveTask` / `liveTasksOf` / `liveCountOf` / `liveLayers` / `liveReadyTasks` / `isDependencySatisfied` / `splitDependencyEdges` / `isReadyTask` / `layerInputOf`），喂标本数组 | 无 IO、快、可穷举分支（含悬空依赖 / 环 / 空集合）；悬空单独成桶的分支只有这一层测得干净 |
| 投影 / 端点级 | 四个展示面读数、`/state` 边界、`toCard` 独立漏点、客户端 `topoLevels` 剪边、覆盖度两条入口、文档面板不变量 | 走生产读路径（`assembleStageDetail` / `handleState` / `toCard` / `topoLevels` / `syncRTMYaml{,WithSnapshot}` / `QueryDocs`） | 口径分叉发生在接线处与"当场算"的地方，只测纯函数抓不到"某条路径忘了过滤 / 忘了剪边" |
| 源码级扫描 | 判据单点被复用、**无新增**手写 filter、无开关名 | 读源码文本 + S-8 基线清单比对（手法与既有 `tests/layer-boundary.test.ts` 同款，但**新建独立文件**） | 防漂移只能靠机械检查；人工评审不阻止下一个人手写一行 |
| 磁盘级 | 零写回、台账与卡文档不消失 | `mtimeMs` + sha256 逐份前后比对 | 隐性写回与误删只有落到字节才能证明 |

**关键实现手法**：

| 手法 | 说明 |
|---|---|
| 标本复用一张台账 | S-1 一张台账喂 TC-1~TC-4、TC-9~TC-11，保证"四个展示面同一个数"是在**同一份输入**上比的 |
| 对照标本只差一个开关 | S-2 与 S-1 的差别**只有**活卡过滤这一处，使"差值 == 26"成为可失败的结构性质（复刻原型的 `#mock-after` / `#mock-before`） |
| 三处层号实现同台比对 | TC-2 同时跑服务端 `liveLayers`、手工"删边重算"、客户端 `topoLevels`——**真正的分层在客户端当场算**，不比一遍就抓不到"剪边没落进去" |
| 留痕用例覆盖写入路径的四种形态 | 人工取消 / 非人工路径不写 / 复活不清空 / `reason` 纯空白不写（TC-7） |
| 每条判据各留一条逆验证 | 见「逆验证」表；判据与逆验证成对出现，不留"看起来在测"的用例 |
| 基线快照而不是硬编码计数 | S-8 存位置清单；新增点被点名，已清理的基线点也不会造成假红 |

**与常规做法的差异**：

| 差异 | 常规做法 | 本方案 | 为什么 | 可核验指向（测试） |
|---|---|---|---|---|
| 视图类需求的判据 | 截图比对 / "肉眼看着对" | **结构量 + 计数断言**（行数、条数、取消卡 0 条） | 截图不可复核、也不可失败；本仓既有面板用例本来就是字符串断言 | TC-1、TC-4、TC-11 |
| 依赖正确性 | 只断言"图没报错" | **层号与「删边重算」逐卡比对 + 真的能开工** | D-8 的两半（不掉层、不阻塞）都得证明，且各自可失败 | TC-2、TC-3 |
| 口径一致性 | 各处分别断言各自的数 | **等式断言（四数相等）+ 两入口读数相等 + 追溯面限定范围** | "约定一致"不可失败，等式可失败；范围不限定则会拿陈旧快照当缺陷 | TC-4、TC-5 |
| 防漂移 | 人工 review 拦"又写了一份" | **机械扫描 + 新增即红 + 独立用例** | 本仓已有同类先例；但新网必须挂在绿的用例上才看得见 | TC-6 |
| 兼容性 | 只测"能读出来" | **能读 + 零写回（逐份哈希）** | FR-6 的要求是"不追溯、不改写"，只测读取会把写回漏过去 | TC-8 |
