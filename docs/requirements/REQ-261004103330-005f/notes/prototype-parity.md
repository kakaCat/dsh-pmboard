# 原型对齐清单（REQ-261004103330-005f · 返工依据）

> **为什么有这份文件**：人验收时反馈「实现的和原型不一致」。核实结论——**不是细节偏差，是整体形态不一致**。
> 根因：设计期我定了 R4「生产用真令牌、不给第二套视觉体系」，这条对；但我把「不用私令牌」过度执行成了
> **「不用原型的视觉结构」**，四张前端卡的派单只写"形态以原型为准"，**验收标准里没有一条断言视觉结构**——
> 于是每张卡都"绿"，界面却不是原型那个样子。这与"每张卡都绿但接起来是断的"是同一类错误：
> **把"没有反例"当成"符合要求"**。
>
> 本文件把「形态」拆成**可勾选、可断言**的条目；每趟对齐必须**重新截图并亲眼看过**才算完成。

## 基准

- 权威界面：`prototype/board-settings.html`（可交互）+ `prototype/preview-*.png`（截图）
- 实现渲染自证：`npx vitest run tests/_tmp-settings-render.test.ts` 导出 `/tmp/impl-*.html`，
  再用 `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --window-size=1280,1000 --screenshot=/tmp/after-<pane>.png "file:///tmp/impl-<pane>.html"` 截图
- **不许**出现原型里的私有令牌（`--s-line`/`--s-pill`/`--s-primary`/`--s-text`）与裸类名；类名一律 `dsh-pm-set-` 前缀，颜色一律真令牌

## 一、共享视觉基元（第一趟建立，其余屏复用）

- [ ] 分组盒子：section 标题 + 与内容的分隔（原型 `存储与数据库` 下分 `后端` / `迁移与校验` 两组）
- [ ] 说明框：带底色、圆角、内边距（上限屏底部那句"取值 1–10000…保存写入…来源顺序"就在框里）
- [ ] 阶段色点：按阶段配色，取既有泳道阶段色令牌，**不自造 hex**
- [ ] 行标签/值两列：`标签` 左、`值/控件` 右（存储屏的"当前生效 / 设置里的目标 / 生效来源 / 生效时机"都是这个形）
- [ ] 行内徽章：`当前` / `实验性` / `插件配置` / `待保存` 同款胶囊
- [ ] 左菜单小图标位

## 二、上限屏

- [ ] 每行阶段名前有**彩色圆点**
- [ ] 阶段名后是**中文副标题**（`立项 · 立项草稿`），**不是英文 key**
- [ ] 表头四列：`节点（需求阶段）` / `内置默认` / `上限` / `当前来源`
- [ ] `当前来源` 徽章：`内置默认` / `插件配置` / `设置文件` / `待保存`
- [ ] 每行 `恢复默认`
- [ ] 脏态条：`有 N 项改动未保存` + **撤销** + **保存**
- [ ] 底部说明框含：取值 1–10000、**下一个回合**生效、已在跑的不受影响、标「不自动跑」阶段留着对账、**保存写入 `~/.dsh/dsh-reqboard-settings.json`**、**来源顺序：设置文件 > 插件配置 > 内置默认**
- [ ] 标题下一行只说"每个节点（需求阶段）允许自动续跑的最大回合数"

## 三、存储与数据库屏

- [ ] 后端为**分段开关**（`JSON 分片`[当前] / `SQLite`[实验性]），不是三个平铺按钮
- [ ] `数据位置` 行：显示数据根 + **改路径**入口
- [ ] **改路径**用的是既有接口 `PATCH /settings` 的 `storage.sqlitePath`（接口已支持，UI 之前漏做）
- [ ] `生效来源` 行 + `设置文件 > 插件配置 > 环境变量 > 内置默认` 的说明
- [ ] `生效时机` 行：`已在生效（重启后仍为 …）` / `需要重启宿主生效`
- [ ] 长解释：切换只发生在装配期、**绝不半途换存储实现（做一半会丢写）**、重启前请先跑迁移否则新库是空的
- [ ] `迁移与校验` 分组标题：`把 JSON 分片搬进 SQLite 并逐项校验`
- [ ] **手动迁移命令** 折叠/展示（给想手跑的人）
- [ ] 文案：这件事**不用你做**——点下面按钮会**开一个 Agent 窗口**，由它执行 `备份 → 建库 → 迁移 → 校验 → 写设置`，完成后回报结论；你只需看结果、重启宿主
- [ ] 按钮：`交给 Agent 处理`、窗口开出后 `打开迁移窗口`、失败态 `重来一次`
- [ ] 旧库检出提示（`系统记录里检出「已存在的旧库」…`）

## 四、系统记录屏

- [ ] 顶部说明句：`这台机器上「数据放在哪、以前用过哪个后端、谁在什么时候改的」`
- [ ] 成组信息：`记录文件`（追加式；机器写，人只读）/ `路径` / `写入者` / `更新时刻` / `初始化`（启动时自动创建；幂等——已存在只追加不覆盖）/ `保留策略`（只追加不裁剪）
- [ ] `本安装版本`：`dsh-pmboard <版本> · build <指纹>`，并注明"写在本文件顶层 `plugin` 块"
- [ ] `版本字段`：每条事件都带 `plugin: { version, buildStamp }`
- [ ] `后端使用史` 时间线（含 `启动` / `迁移` / `后端切换` / `升级`），`以前用过 SQLite` 这件事回滚后仍查得到
- [ ] 陈旧时分叉红字 + **无任何合并入口**
- [ ] 档案损坏：红字原因与路径，**不白屏**

## 五、通用屏

- [ ] 说明句：`只读信息，用来对账「现在跑的是哪份东西」`
- [ ] `设置文件` 行：路径 + `尚未创建（当前全部走内置默认；首次保存上限或确认切库时才落盘——惰性，避免把默认值冻进文件）`
- [ ] `台账数据根` / `当前后端（来源：…）` / `PM 插件版本`（单一来源：package.json，运行时读取，同时落盘进系统记录顶层 `plugin` 块）
- [ ] `插件构建指纹` / `台账 schema`（`REQBOARD_SCHEMA_VERSION = 9`，**不因加 SQLite 而升版**）/ `运行时`（node 版本 · `node:sqlite` 可用，experimental 警告如实保留）
- [ ] 读不到的值写"未知"并注明以宿主日志为准，**不编数字**

## 六、确认门与迁移各态（原型的 `preview-confirm.png` / `preview-agent-*.png`）

- [ ] 确认框：标题 `确认执行？` + ✕、正文影响清单、`取消` / `确认执行`
- [ ] 迁移进行中/完成/失败三态的呈现与原型一致（失败态给 `重来一次`）

## 七、必须补的**视觉结构断言**（本次教训的制度化）

每屏至少一条断言钉住"形态"（而不只是文案），例如：

- [ ] 上限屏：渲染结果含阶段色点元素与**中文副标题**，且**不含**英文 key（`draft`/`implementing` 之类）
- [ ] 存储屏：渲染结果含**改路径**入口与**手动迁移命令**区
- [ ] 记录屏：渲染结果含 `记录文件` / `写入者` / `保留策略` 三组标签
- [ ] 通用屏：渲染结果含 `台账数据根` 与 `REQBOARD_SCHEMA_VERSION`

> 这些断言的价值不在"多几条测试"，而在**把"形态"从口头要求变成会红的东西**——这正是上一轮缺的那一环。

## 十一、这一轮暴露的三类问题（写给后来人）

1. **模板字符串里的反引号**：CSS 注释里写 `` `.pane-title .muted` `` → **提前闭合 `SETTINGS_CSS`**，
   195 行之后的样式全成了代码、类型变成 `number`。**改完不跑 `tsc` 就发现不了**（构建照样通过）。
   → 教训：改样式分片后**必须**跑 `tsc` 或相关测试；注释里不要用反引号。
2. **"最常见的那种状态"漏了共有形态**：记录屏 `ready` 分支漏拼 `title`，只有 loading/error/invalid 带标题——
   结果是正常态反而没有屏标题。**单屏测试永远发现不了，必须四屏横向比**。
   → 已补一条"四屏共有的形态"断言，把这类问题变成会红的。
3. **一个渲染基元会把标题转义**：`groupHtml` 的标题参数会被 `esc`，传入带 HTML 的副标题会露出 `&lt;span`。
   → 新增 `groupBoxHtml`（标题为可信 HTML）并全线改用；坑写进注释。
