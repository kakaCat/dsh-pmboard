## 汇报 1（2026-10-03T14:37:20.855Z，窗口 session-278681bb-b160-4067-8740-3d5a0f2c7426）

这一步把「文档打不开」的根因从代码层拔掉了：读根不再是插件宿主的工作目录（那是服务自己的落脚处，跟文档毫无关系），而是**发起阅读的那个会话的工作区**；前端也带着会话 id 来、并按同一个根把相对路径拼绝对，预检与打开从此同口径。最要紧的一处发现是测试当场抓到的：路由层是白名单式转发，少一行整条修复就静默失效——已补上并留了注释。

### 完成项

- 服务端新增共享解析器 resolveDocRoot（会话根优先，回落 legacy 并在响应里如实标注来源），预检与打开共用这一处
- artifacts 路由：classify / handleFileRead / handleDocsResolve 全部改按会话根判定；删掉遗留的 workspaceRoot()（它正是「除需求目录外文档一律判不存在」的根因）
- /state 下发三件：workspaceRoot 改为会话工作区、新增 sessionWorkspaceRoot 与 docsRootSource（诊断用，不静默降级）
- 组合根注入 sessions 服务并把解析器交给路由（惰性、解析失败只告警并回落）
- 客户端：fetchState / resolveReqDocs 带上当前会话 id；open-doc 的根选择改为「需求级 → 会话工作区 → 服务端 workspaceRoot」，三者都无则原样交相对路径、不拼必然不存在的绝对路径
- 新增 tests/doc-root-session.test.ts 六个用例：带会话 id 的 state/预检/读全文、不带会话 id 的回落与对照（证明「能开」是换根换来的）、需求目录内文档仍可开
- 测试当场抓到一个真接线漏点：routes.ts 的 deps 映射是白名单，漏转发 sessionWorkspace 会让整条修复静默失效（组合根传了、路由收不到）——已补并留注释
- 零回归：类型错误 149 与上一张卡逐字相同；全量测试 98 失败与失败集合逐字相同；构建退出码 0
