# 需求说明（REQ-261007210801-3bff）

> 状态：需求分析（brainstorming） · 窗口 session-be1b4f3d · 立据：2026-10-07
> 宣布路径：Bounded（交付物是一份规划文档，范围封闭；人可推翻）

## 背景与动机

用户（pmboard 作者/主要维护者）原话：

> 「现在我是想到哪里坐到哪里，没有清晰的规划」
> 「我想给 pm 插件做一个规划，可以把精力放到一个方向」

仓库现状佐证（2026-10-07 盘点）：

- 100+ 条历史需求、27 个 agent 工具、20+ 篇机制文档，能力面广但无主线；
- 当日体检报告（[reqboard 插件工具面体检](../../strategy-research/reqboard-plugin-audit-2026-10-07.md)）列出 3 个高危 bug、工具面精简方案、3 个待裁决项——候选方向之间的取舍一直没有被正式做过。

经与用户讨论，主攻方向已裁定：**C. 体验与可视化**（否掉：A 还债稳基 / B 自动化深化 / D 产品化外发）。

## 目标

| 编号 | 目标 | 价值 | 衡量指标 | 目标值 |
|---|---|---|---|---|
| G1 | 产出一份 pmboard 产品规划，唯一主攻方向 = 体验与可视化 | 给「下一步做什么」一个确定答案 | 规划正文存在且写明唯一方向 | 1 份文档，1 个方向 |
| G2 | 方向下给出具体事项清单与优先级顺序 | 从「方向」落到「动作」 | 清单事项数与排序 | 3–7 项，有显式优先级 |
| G3 | 明确不做什么（非目标清单） | 给「想到的新念头」一个拦截依据 | 非目标条数 | ≥3 条 |
| G4 | 给出「方向做透、可换下一个」的判据 | 规划有终点，不是无限期 | 判据可核验 | 每条判据附验证方式 |

## 非目标

- N1 不实施任何体验与可视化的具体改动（本需求只产规划，不写代码）
- N2 不修体检报告中的 H1–H3 高危 bug（仅作为规划输入引用，修复另行立项）
- N3 不做工具面精简、不做外发/发布相关工作
- N4 不推翻「主攻方向 = 体验与可视化」这一已裁定结论（反悔走修订流程，见失败路径）

## 边界（不做什么）

只改文档，不产代码改动；不触碰 src/、tests/、台账数据。规划正文的落点见「大纲」节。

## 失败与并发路径

- **失败路径**：规划正文验收时被发现「事项不可执行 / 无非目标 / 无做透判据」→ 按验收意见返工重写，不进入归档。
- **并发重复**：规划期间冒出的新想法（如想修 H1）→ 不并入本需求，单独立项；本规划的非目标清单即为拦截依据。
- **状态机非法迁移**：方向裁定后用户反悔 → 不直接改文档，走「重交需求文档 + change_note」的修订流程，旧确认自动作废。

## 目标读者

pmboard 维护者本人。读完能答出：下一阶段只做哪几件事、按什么顺序、什么念头来了应该忍住不做、什么时候可以换方向。

## 大纲

规划正文章节：① 背景与方向裁定 ② 主攻方向：体验与可视化（为什么是 C）③ 事项清单与优先级 ④ 非目标（不做什么）⑤ 做透判据与换方向的信号。

- 正文落点：`docs/requirements/REQ-261007210801-3bff/design/product-plan.md`
- 归档时合并去向：`docs/strategy-research/`（长期指导页），并在 `docs/architecture/project-manual.md` 挂链

## 关键决策与取舍

- **主攻方向选 C 体验与可视化 → 否掉 A 还债稳基**（3 个高危 bug 暂缓）：用户判断自用场景下体验痛点最直观，还债类工作不带方向感 → 人裁定，2026-10-07。
- **否掉 B 自动化深化**：其依赖 H3 的「单进程假设」裁决，而 H3 属 A 的范畴，B 现在动会悬空。
- **否掉 D 产品化外发**：安装门槛与文档完整度未达标，外发前需先还债，与 C 相比离用户当前痛点更远。
