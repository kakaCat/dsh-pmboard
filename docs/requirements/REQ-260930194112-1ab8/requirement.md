# REQ-260930194112-1ab8 列表视图自适应修复：窄宽度下列被压缩换行、操作按钮重叠

> 档位：轻档（改动面小、无第二个未定决策）· 类型：feature（实为列表视图布局缺陷修复）

## TL;DR

列表视图是 8 列固定表格，**没有任何自适应规则**：当可用宽度低于内容所需时，浏览器按 min-content 压缩列，中文可逐字断行、ID 断在连字符上，操作列被压到按钮溢出重叠。修复 = 「关键列不换行 + 次要列按宽度让位 + 表格保底横向滚动 + 操作列不可压缩」四件套，纯 CSS + 少量列类名，宽屏视觉零变化。

```

┌──────────────────────────────┐                          ┌──────────────────────────────┐
│ ID    标题        分类 状态 … │                          │ ID           标题      状态 操作│
│ REQ-  修复验收    功  拆      │ ← 中文逐字竖排            │ REQ-2609…  修复验收…  拆分 →实施│ ← 关键列单行
│ 2609… 单自证失    能  分      │ ← ID 断在连字符           │            + 元信息          │    次要列让位
│ eb6c  败：…       ↑2行 ↑2行   │                          │                              │
│        操作：[→实施][取=消会话]│ ← 按钮重叠（取消/会话）   │        操作：[→实施][取消][会话]│ ← 按钮不重叠
└──────────────────────────────┘                          └──────────────────────────────┘
                                                          低于 720px：表格整体横向滚动，不再压扁列
```

## 判定标准（可证伪）

用 headless Chrome 渲染「列表视图标本页」，在 640 / 760 / 840 / 1080 / 1680 五档宽度下断言：

| 断言 | 量法 | 通过条件 |
|------|------|----------|
| 关键列不换行 | `.dsh-pm-card-id` / `.dsh-pm-status-badge` / `.dsh-pm-cat` 的行盒数 | 可见时恒为 1 |
| 操作按钮不重叠 | 同行按钮包围盒两两相交检测 | 无相交 |
| 操作列未被压缩 | 操作列 `clientWidth ≥ scrollWidth` | 恒成立 |
| 保底横向滚动 | 表格滚动容器 `scrollWidth > clientWidth` | 仅 < 720px 时为 true |

实测结果（当前仓库源码 → 修法注入标本页）：

```
before: 640/760/840/1080px → problems 非空（ID 占 2~3 行、状态 2 行、分类 2 行、按钮重叠 取消/会话、操作列被压缩）
        1680px → NONE
fixed : 640/760/840/1080/1680px → NONE（640px 时 overflowX=true，其余 false）
```

## 产品定义

「列表」是看板两大视图之一（与泳道互补），回答「项目有哪些事、各自到哪一步、谁在做」。它被渲染成一张 8 列表格：`ID | 标题 | 分类 | 状态 | 进度 | 负责人 | 更新时间 | 操作`。

问题不在数据而在布局：表格既没有列宽下限，也没有横向滚动兜底，列宽完全交给浏览器的自动表格算法。中文与带连字符的 ID 在 min-content 计算里可以被断到**单字宽**，于是可用宽度不足时列被压成「一个字一列」，操作列内的 `取消` / `会话` 按钮互相叠字。

受影响场景不止窄窗口：高分屏（截图即 2x 缩放，CSS 宽度约 840px）、GUI 内嵌面板、分屏/小窗口都会命中。

## 用户与角色

- **看板用户（PM / 需求方）**：扫列表判断进度、点「→ 实施 / → 验收 / → 归档」推进的人；按钮叠字时点错按钮是实际风险
- **实施 agent**：截图交付时列表塌陷会让截图无法作为验收证据
- **前端维护者**：需要一套明确的宽度档位规则，而不是每次遇到窄屏再补一条 hack

## 功能点

- **FR-1: 关键列恒为单行**——ID、分类、状态、进度百分比、负责人窗口 chip、更新时间六类单元格不换行（`white-space: nowrap`），标题列例外、允许折行
- **FR-2: 标题列吸收剩余宽度**——标题列去掉 380px 硬上限（保留 220px 下限），窄宽度下不再被压成每行 5~7 字
- **FR-3: 操作列按钮不重叠**——操作列内层按钮组不可压缩（`flex: none` + `min-width: max-content`），窄宽度下 `取消` / `会话` 并排显示或整列让位，绝不允许叠字
- **FR-4: 窄宽度次要列按档让位**——≤1180px 隐藏「分类 / 负责人 / 更新时间」三列；≤880px 再隐藏「进度」列；被隐藏列的信息仍可从详情页取得
- **FR-5: 表格保底横向滚动**——表格外包一层 `overflow-x: auto` 容器，表格 `min-width: 720px`；宽度低于 720px 时整表横向滚动，而不是把列压扁
- **FR-6: 宽屏视觉零变化**——≥1180px 时列表渲染结果与现状逐项一致（列数、列序、列宽、样式不变）
- **FR-7: 自适应回归探针**——新增可复跑探针脚本（标本页 + headless Chrome 断言上述四条量法），作为该视图的布局回归门

## 边界

**做**：
1. 列表视图自适应规则：滚动容器 + 关键列 nowrap + 标题列弹性 + 操作列不可压缩 + 两个宽度档位的列让位（`src/client/styles/board.ts`、`src/client/views/board.ts` 列类名）
2. 自适应回归探针脚本（标本页渲染 + headless Chrome 断言，可离线复跑）
3. 窄宽度下被隐藏列的信息可达性说明（详情页已含分类/负责人/更新时间，不做额外折叠 UI）

**不做**：
1. 不动泳道视图、需求详情页、DAG 画布与任务面板的布局
2. 不改列表的列内容、排序、分页、分组逻辑（`dsh-pm-list-toolbar` / `renderListCard` 的行为保持不变）
3. 不删除旧卡片式样式类（`.dsh-pm-list-card` 等保留，避免影响其他引用点）；不引入 JS 宽度监听或容器查询

## 档位依据（轻档）

- 改动面：1 个视图函数（加列类名 + 滚动容器）+ 1 个 CSS 分片 + 1 个探针脚本，无数据模型 / 接口 / 架构变更
- 无第二个未定决策：宽度档位（1180 / 880 / 720）与让位列序已在本文定死
- 单向升级：若实施中出现「需要 JS 监听宽度」「需要容器查询」「需要改列集合本身」等新决策，立即停手升级重档
