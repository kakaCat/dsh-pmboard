# REQ-260930194112-1ab8 用例 · 三个角色的操作路径 serves: FR-1, FR-2, FR-4, FR-5, FR-6, FR-7

> 每个用例给出「操作 → 修复前 → 修复后」，供验收时对照截图复核。

## U-1 · PM 在窄面板扫列表并点推进按钮 serves: FR-1, FR-3

- 操作：窗口约 840px（高分屏 2x、GUI 内嵌面板或分屏）打开「列表」，找到某条需求，点「→ 实施」。
- 修复前：ID 占 3 行、`功能`/`拆分` 竖排、`取消` 与 `会话` 叠字——看不清状态，且可能点错按钮。
- 修复后：ID 单行完整、状态徽章单行、三个按钮并排清晰，一次点中目标按钮。

## U-2 · PM 在超窄窗口查看完整信息 serves: FR-2, FR-5

- 操作：把窗口压到 640px 以下，横向滚动表格查看被让位的进度/分类等列。
- 修复前：没有滚动兜底，列继续被压成单字宽，滚动也救不回可读性。
- 修复后：表格保持 `min-width: 720px`，出现横向滚动条，列不再被压扁；标题列吃掉剩余宽度（实测 640px 档标题列 282px）。

## U-3 · 宽屏用户确认「没有任何变化」 serves: FR-6

- 操作：在 1680px 显示器上打开「列表」，与修复前截图逐项比对列数、列序、列宽。
- 修复前：8 列、标题列 540px。
- 修复后：8 列、标题列 540px、三个「让位列」全部可见——零变化（探针 A6 断言）。

## U-4 · 用户想知道被隐藏列的信息 serves: FR-4

- 操作：窄宽度下列表不再显示「分类 / 负责人 / 更新时间」，用户点开该需求详情。
- 修复前：窄宽度看不到分类与时间，且详情外无处可查（只能放大窗口）。
- 修复后：三列信息在详情页可得（分类见需求头、负责人见来源窗口 chip、更新时间见阶段时间线）；列表侧不做额外折叠 UI（边界第 3 条）。

## U-5 · 前端维护者回归验证 serves: FR-7

- 操作：改完 `styles/board.ts` 或 `views/board.ts` 后跑 `vitest run tests/list-responsive.test.ts` 与 `tsx scripts/list-responsive-probe.mts`。
- 修复前：无任何布局回归门，只能靠人肉缩小窗口发现塌陷。
- 修复后：静态断言 + 5 档宽度真实渲染断言，任一档换行/重叠/列数错位即红灯。
