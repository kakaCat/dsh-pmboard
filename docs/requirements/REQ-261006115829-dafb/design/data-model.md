# 数据模型设计（REQ-261006115829-dafb）

> 本需求**不改表、不改 schema、不写台账**。本文的职责是把「无变更」这个判定写清楚：
> 判定依据是什么、影响面在哪、迁移与回滚怎么做——不是凑字数。

## 结论：无数据变更 `serves: FR-1`

| 问 | 答 | 判定依据（可核） |
|---|---|---|
| 新增 / 修改台账字段？ | 否 | 改动面只有 `docs/**`；无需碰 `src/domain/**`、`src/repositories/**` |
| 新增 / 修改 SQLite 表结构？ | 否 | 无迁移脚本、无 store schema 变更 |
| 新增配置项 / 环境变量？ | 否 | 条目的命令只**读** HTTP 响应，不写任何状态 |
| 新增持久化产物？ | 是——**一份 Markdown**（`docs/guides/plugin-reload-troubleshooting.md`） | 文档即产物，无解析器、无 schema 约束 |

为什么能在设计阶段就把「无变更」钉死：本需求的交付物是**文档 + 两处链接**，
既不引入读写路径，也不改变任何既有数据的解释方式（无「同一字段改含义」这类隐性迁移）。

## 唯一的「数据」：文档自身的形状 `serves: FR-1`

| 载体 | 字段 / 属性 | 类型 | 约束 |
|---|---|---|---|
| `docs/requirements/<REQ>/design/*.md` | 每个 H2 上的 `serves: FR-x` 标注 | Markdown 行内反引号或 HTML 注释 | 每节至少一条；指向 `requirement.md` 里真实存在的 FR |
| `docs/guides/plugin-reload-troubleshooting.md` | 五个 H2 标题（症状 / 判据 / 机制 / 处置 / 非目标） | 标题文本 | 逐字命中（验收按 `grep` 断言） |
| 同上 | 命令示例里的 `<host>` / `<rev>` | 文本 | 必须写成占位并注明「逐次实测取值」，不得固化为常量（FR-3 边界） |
| 同上 | 命令与期望输出的对照 | 文本 | 每条命令都要有期望输出；禁用「应该能」「一般会」 |

## 迁移方式 `serves: FR-1`

无数据迁移：无存量数据需要回填、无格式升级、无版本兼容分支。
新增条目文件随提交进入仓库，读者下次打开文档即生效；两处入口的新增行对既有读者是无感的增量。

## 回滚 `serves: FR-1`

`git revert <本次提交>` → 条目文件被删除、两处入口的追加被还原，回到「没有这条判据」的状态。
不需要数据补偿，不影响任何运行时行为（无表、无台账、无客户端 bundle）。
