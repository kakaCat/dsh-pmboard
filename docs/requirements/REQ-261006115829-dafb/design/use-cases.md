# 用例设计（REQ-261006115829-dafb）

> 谁、在什么场景下、照条目走到什么结论。场景全部来自本次真实报障（2026-10-06）及其前后文；
> 相关裁定：D-1（先判「噪声 vs 真缺陷」）、D-2（404 = 插件包 rev 过期）、D-3（产物 = 排查条目文档）。

## 场景地图 `serves: FR-1, FR-2, FR-3`

```
场景                                 走条目的哪几段                        结论
UC-1 开发者重建后页面报 404  ──▶ 症状 → 判据(C-2/C-3) → 机制 → 处置 ──▶ 刷新页面即恢复
UC-2 用户看到 ERR_FAILED 报障 ──▶ 症状 → 判据(C-1) → 机制         ──▶ 通道活着，断线重连；刷新

```

## UC-1：开发者重建客户端后，页面报插件包 404 `serves: FR-1, FR-3`

**角色**：本插件开发者（D-3 的产物就是给他/她用的）。

**触发**：改了 `src/client/**` → `pnpm build:client`（必要时重启宿主），而页面一直开着。

**现象**：控制台红字 `Failed to load resource: the server responded with a status of 404 (Not Found)`，
对应地址形如 `dsh-app://app/plugins/??dsh-pmboard/client.js&rev=<重建前的 rev>`。

**走条目**：

1. 症状段对上（地址形态是 `…/plugins/??…&rev=…`）；
2. 判据段跑 C-2 → `404`；跑 C-3（把 rev 改错）→ `404`；
3. 机制段确认：包地址带 rev，宿主只服务**当前** rev，重建即让旧 rev 失效；
4. 处置段：刷新页面（HMR 客户端本来也会重试最新图，但刷新最快）。

**结论**：噪声，刷新即恢复。**若**刷新后同一地址仍 404 → 转 UC-4。

## UC-2：用户看到 ERR_FAILED 来报障 `serves: FR-1, FR-3`

**角色**：用户 / PM（D-1 里就是这样报的：「报错了」+ 两行控制台文本）。

**触发**：宿主重启（本次为 11:31 重启）或页面卸载，把 HMR 长连接掐断。

**现象**：控制台红字 `Failed to load resource: net::ERR_FAILED`，地址 `dsh-app://app/plugins/events`。

**走条目**：

1. 症状段：认出这是 `plugins/events`（HMR 通道），不是本插件的接口；
2. 判据段跑 C-1 → `200` + `text/event-stream`（通道本身是活的）；
3. 机制段：EventSource 自带重连，断线是重启的必然现象；
4. 处置段：刷新页面（或等它自己重连）。

**结论**：噪声。**注意**：不能只看 C-1 —— 若 C-1 失败，说明 HMR 宿主半边没注册，属真缺陷。

## UC-3：不记得文件名，从入口找 `serves: FR-2`

**角色**：下一个遇到同样报错的人（含未来的自己）。

**触发**：知道「以前好像写过一条」，但想不起文件名。

**走条目**：

1. `docs/architecture/project-manual.md` 索引区一行（现象 → 条目标题）→ 点进条目；或
2. `docs/architecture/plugin-runtime-prerequisites.md` 的「构建产物 ≠ 已加载模块」节末尾回链 →
   （回链自带一句机制：包地址带 rev，rev 过期即 404）。

**结论**：一步到条目，不需要先读插件加载链。

## UC-4：判据不符 → 真缺陷分诊 `serves: FR-3`

**角色**：按条目走到「不符」分支的排查者，或报障后由 agent 接手。

**触发形态**（任一）：

- C-1 非 `200` 或不是 `text/event-stream` → HMR 通道本身没起来；
- 刷新后同一包地址仍 `404` → 不是竞态；
- 报错 URL 根本不是 `…/plugins/??…`（例如 `/dashboard/…`、`/api/file?path=…`）；
- `curl` 连不上宿主。

**走条目**：「非目标」段的对应行 → 按取证步骤留证据（DevTools → Network 按状态码筛 404，
保留**完整 URL** 与状态码；必要时附 `curl` 输出），再交回本插件排查。

**结论**：判为真缺陷，升级排查（本条目不负责给出根因，但负责**不把真缺陷刷新掉**）。

## 边界与反例 `serves: FR-1`

- 地址里**没有** `rev=` 参数：实测一律 `404`（例：`/plugins/??dsh-pmboard/client.js` 不带 rev → `404`），
  这**不是**竞态，是地址形态不对；
- 报错 URL 是 `/assets/**`：那是壳内静态资源，属另一类问题（本条目不覆盖）；
- 宿主没起：`curl` 直接失败，不适用「噪声」判定。
