# 接口设计（REQ-261006115829-dafb）

> 本需求**没有运行时接口**。这里定义的「接口」是**给人看的契约**：条目页必须提供哪几段、
> 判据命令的输入 / 输出 / 边界语义、入口链接落在哪——零上下文的执行者照本文就能把页面写对。
> 依据的裁定：D-1（先判噪声还是真缺陷）、D-2（404 = 插件包 rev 过期）、D-3（产物 = 排查条目文档）。

## 条目页契约总览 `serves: FR-1`

| 段落（H2） | 必须回答的问题 | 判定方式 |
|---|---|---|
| 症状 | 两条红字分别长什么样、各自指向哪个地址 | 读者能逐字对照自己的控制台 |
| 判据 | 三条命令 + 期望输出 | 命令可复跑，输出与文中一致 |
| 机制 | 包地址的 `rev` 从哪来、为什么会过期、谁负责重试；`/plugins/events` 是什么、为什么会断 | 每条红字都能对上一句机制 |
| 处置 | 先做什么（刷新页面）、仍红做什么（取证） | 30 秒内能定位到本段 |
| 非目标 | 哪些 404 **不**属于本条（非包地址、宿主不可达） | 读者不会把真缺陷刷新掉 |

## 条目页骨架（结构签名） `serves: FR-1`

```
# 桌面端控制台：插件包 404 / plugins/events ERR_FAILED 排查
## 症状        ← 两条红字原文 + 地址形态（含 rev 参数）
## 判据        ← C-1 / C-2 / C-3 三条命令 + 期望输出 + 不符时的分诊
## 机制        ← rev 的来源与过期判据；HMR 通道的作用与断线语义
## 处置        ← 刷新页面（噪声分支）/ 取证步骤（真缺陷分支）
## 非目标      ← 不是包地址的 404、宿主不可达、无 rev 的地址 → 各自去哪查
```

约束（写进页面的硬要求）：

- 每个 H2 标题**逐字**含上表的关键词（验收按 `grep "^## .*症状"` 这类断言核）；
- 全文 ≤ 120 行（`wc -l`）；「处置」不出现在首屏之后；
- 命令块里的端口与 `rev` 一律写成占位（`<host>` / `<rev>`）并在正文注明**逐次实测取值**。

## 判据命令契约 `serves: FR-3`

三条命令的输入 / 输出 / 失败语义（`<host>` = 当前宿主，本机 2026-10-06 实测 `127.0.0.1:19387`）：

| 编号 | 命令 | 期望输出 | 不符时的含义（分诊） |
|---|---|---|---|
| C-1 | `curl -sS -i -m 3 http://<host>/plugins/events`（只看头部与首帧） | `HTTP/1.1 200` + `content-type: text/event-stream`，首帧含 `"type":"graph"` | 非 200 / 非流式 → HMR 宿主半边没注册或宿主没起（真问题） |
| C-2 | 从 C-1 的图帧里抄出 `plugins/??<包>/client.js&rev=<rev>`，原样 `curl -sS -o /dev/null -w '%{http_code}' 'http://<host>/<该地址>'` | `200` | `404` → **页面手里的地址已过期**（本条目主场景：重建 / 重启竞态） |
| C-3 | 同 C-2 的地址，把 `rev=<rev>` 改成一个不存在的值再请求 | `404` | `200` → 宿主不按 rev 校验（与本次实测不符，判据失效，回去重查） |

**判据的合成读法**：`C-1 通过` + `C-2 404` + `C-3 404` = 噪声（刷新即可）；
`C-1 失败` 或 `C-2 刷新后仍 404` = 真缺陷（走 UC-4）。

## 错误语义与边界 `serves: FR-3`

| 情形 | 判定 | 条目里怎么写 |
|---|---|---|
| 报错 URL 不是 `…/plugins/??…`（如 `/dashboard/…`、`/api/file?path=…`） | 本条目不覆盖 | 明说「去查该路径自己的路由 / 文件」，并给「怎么把完整 URL 取出来」 |
| `curl` 连不上宿主 | 真问题 | 归到「宿主没起」分支，**不判噪声** |
| 地址里没有 `rev=` 参数 | 形态不符（手写或旧版地址） | 实测：不带 rev 的包地址一律 `404`；提示「带 rev 复现」 |
| 刷新后同一包地址仍 404 | 真问题（不是竞态） | 提示留 Network 记录（状态码 + 完整 URL）交回插件排查 |

## 兼容性 `serves: FR-1`

条目是新增页面，不改任何运行时接口；两处入口只增行 / 只追加一句，既有阅读路径与既有结论逐字不变。
回滚见 `design/architecture.md` 的「兼容与回滚」。
