# REQ-261004151652-d535 设计 · 用例（不同宽度下看到什么）

## UC-1 宽窗口（容器 > 780px）：每节点名 + 各自的数（serves: FR-1, FR-2）

**触发**：视口约 ≥830px（容器 = 视口 − 48px）。
**看到**：7 个节点名，每个名字**正下方**是它自己的 token（`需求分析/827.8k`、`设计/10.9M`、`拆分/922.0k`、`实施/12.7M`），节点间有连线，右侧是 `3/12`；**没有**累计徽章（明细相加即总数）。
**成功判据**：探针该档 `可见名数 = 7`、`可见数 = 有快照的节点数`、徽章隐藏、`problems=NONE`。

## UC-2 中档（600 < 容器 ≤ 780px）：只剩当前节点，但**它带着自己的数**（serves: FR-2）

**触发**：视口约 650–828px。
**看到**：只有当前节点的名字（其余只有圆点与序号），**其名字下方仍有该节点的 token**；无连线；无徽章。
**为什么这样切**：这一档名字已经只能留一个（既有档位规则），若再连它的数一起裁掉，用户就彻底看不到「当前阶段烧了多少」——本需求要修的正是这种「有名字没数」。
**成功判据**：探针该档 `可见名数 = 1`、`可见数 = 1`（当前节点有快照）、徽章隐藏。

## UC-3 窄档（容器 ≤ 600px）：明细让位给「总数」（serves: FR-3）

**触发**：视口 ≤648px。
**看到**：七个圆点 + 计数 `3/12` + 累计徽章 `🪙 25.3M`（图标在该档收起，只留数字）；没有名字、没有节点数字、没有连线。
**成功判据**：探针该档 `可见名数 = 0`、`可见数 = 0`、**徽章可见**、`rowRightOverflow ≤ 0`。

## UC-4 没有 token 的节点：不补 0（serves: FR-1, FR-2）

**触发**：某节点从未产出快照（老需求 / 尚未进入的阶段）。
**看到**：该节点只有名字，**名字下方空白**；其余有数据的节点照常显示数字。
**成功判据**：接口层 `nodes[].tokens` 键缺席（既有用例锁）；渲染层不出现 `0` 文本；不因「一行里少一个数」而错位（纵排天然按节点各占一列）。

## UC-5 不支持容器查询的降级（serves: FR-1, FR-3）

**触发**：浏览器无容器查询能力 / 组件被放到没有容器祖先的位置。
**看到**：与宽档一致（全部明细可见），且**没有**累计徽章（默认隐藏）——不会出现「明细与总数同时在场」的重复。
**成功判据**：探针 `--fallback` 模式 PASS，且断言「全部节点 token 可见 + 徽章隐藏」。
