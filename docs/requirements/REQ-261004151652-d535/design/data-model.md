# REQ-261004151652-d535 设计 · 数据模型（常量模型与可见性判定）

## 常量模型（serves: FR-2）

```ts
export const FLOW_TIERS = {
  token: 600,   // 本次：1000 → 600（与 label 相等 ⇒ 有名字就有数）
  link: 780,    // 不变：连线与非当前节点名的断点
  label: 600,   // 不变：全部节点名的断点；也是明细/总数的分界
} as const
```

| 键 | 语义 | 本次变化 |
|---|---|---|
| `token` | 节点 token 的可见断点 | **1000 → 600**（等式：`token === label`） |
| `link` | 连线与非当前节点名的断点 | 不变 |
| `label` | 全部节点名的断点；明细↔总数的分界 | 不变 |

**为什么保留三个键而不是合成一个**：`link` 仍是独立语义（连线比名字更早让位）；把 `token` 与 `label` 合成一个键会失去「这条等式是刻意定的」这一信息，也会让既有断言面（三段阈值与常量逐一相等）失去粒度。等式由**单测断言** `FLOW_TIERS.token === FLOW_TIERS.label` 锁住。

## 可见性判定规则（单一事实源）（serves: FR-1, FR-2, FR-3）

给定容器内容盒宽 `C`（`.titleRow` 的 inline-size 内容盒）：

| 条件 | 节点名 | 节点 token | 连线 | 累计徽章 |
|---|---|---|---|---|
| `C > 780` | 7 个全显 | 有快照者全显 | 显 | 隐 |
| `600 < C ≤ 780` | 仅当前节点 | 仅当前节点（有快照则显） | 隐 | 隐 |
| `C ≤ 600` | 全隐 | 全隐 | 隐 | **显** |

**结构性性质（可直接断言）**：
1. **有名字就有数**：可见名数 > 0 ⟺ 可见 token 数 ≥ 1（当且仅当「每个可见名都有快照」时取等；标本里当前节点 `implementing` 有快照）。
2. **明细不可见 ⟹ 总数可见**：`C ≤ 600` 时徽章必显。
3. **总数不与明细重复**：`C > 600` 时徽章必隐。

## 尺寸预算（阈值取 600 的依据）（serves: FR-2, FR-3）

实测（真 Chrome + 真 CSS + 真模型，`evidence/` 里有两张对照图）：

| 布局 | 7 节点名 + 数字 + 连线 | 芯片总宽（含计数） | 行内其他固定座位 | 需要的最小容器 |
|---|---|---|---|---|
| 现状（横排） | 358px | 463px | 约 156px（工具组 + 角落） | > 1000（旧阈值的由来） |
| 本次（纵排） | **214px** | **320px** | 约 156px | **> 476px** ✅ 取 600 有 124px 余量 |
| 窄档（只有圆点 + 计数 + 总数） | 0 | 约 220px | 约 156px | > 376px ✅ |

结论：**600 是保守取值**——纵排后真正的边界约 476px，留余量给「需求标题/分支按钮更长」与字体渲染差异；不追极限（极限值换不来用户价值，只换来边缘档位抖动）。
