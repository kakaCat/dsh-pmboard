# REQ-261004151652-d535 · 流程图每节点 token 在窄窗口也要看得到（节点内改上下两行）

## TL;DR

- **是什么**：会话头部流程图现在只有宽窗口能看到「每个节点自己的 token」，窄窗口（容器 <1000px）整批被隐藏，只剩一个累计总数——用户要的「每个节点用了多少」看不到。
- **关键实测：不是放不下**。7 个节点名 + 4 个数字**左右并排**要 358px；改成**上下两行**（名字在上、数字在下）只要 **214px**（省 40%），芯片总宽 463 → 320px。旧的 1000px 阈值是按「带 token 近 790px」定的，而那是**节点缩小前的旧账**（圆点 22→14px、节点最小宽 58→32px 之后没人重算）。
- **得到什么**：几乎任何窗口宽度都能看到**每个节点自己的 token**（上下两行）；累计总数只在节点明细确实看不见时才出现，不再与明细重复。

## 一句话目标 + 可证伪判定标准

**目标**：流程图节点内改为**上下两行**（名字在上、该节点 token 在下），并把「每节点 token」的可见阈值按实测量算，做到**只要有节点名就带该节点的数**；累计 Token 徽章改为只在节点明细不可见时出现。

**判定标准（跑什么、看到什么算完成）**：

1. `./node_modules/.bin/tsx scripts/header-progress-probe.mts` 退出码 **0**，且每档满足两条新断言：
   ① **有名字就有数**——该档可见的节点名数 == 该档可见的节点 token 数（当前 B/C/D 档是「有名字没数」）；
   ② **明细不可见时总数必在**——节点明细被隐藏的档位里，累计徽章必须可见（D 档现状已满足，C 档需补）。
2. 探针 DIAG 的 `tokens=<节点级>+<徽章>`：容器 ≥780 的档位 `节点级 ≥ 1`（改造前 B 档为 **0**）。
3. 不变量不破：6 档 `problems=NONE`、`rowRightOverflow ≤ 0`、`docOverflow = 0`、`chartScrollX = 0`。
4. `./node_modules/.bin/vitest run tests/header-progress-responsive.test.ts` 全绿，且新增/更新断言：
   `FLOW_TIERS` 新值与三段 `@container` 逐一相等；累计徽章「默认隐藏 + 窄档显示」规则在场；
   节点 meta 为纵向（`flex-direction: column`）的结构断言在场。
5. `pnpm build:client` 退出码 0（C-12：`[verify-client] OK`）。
6. **视觉**：宽（视口 ≥1280）与窄（视口 ~830）两档标本截图里，**每个有数字的节点，其数字都在该节点名字的正下方**（窄档同样看得到）。

## 业务流程图

```
进度接口 nodes[].tokens.total（已有，不动）
        │
        ▼
流程图节点（.dsh-pm-flow-node）
        ├─ 现状：dot ／ [名字  数字]  ← 左右并排：7 节点合计 358px → 窄档只能整批隐藏
        └─ 改造：[名字]              ← 上下两行：合计 214px（省 40%）
                 [数字]
                          │
                          ▼
        档位（FLOW_TIERS 单一源）：有名字就有数；明细看不见时才显累计总数
```

## 产品定义

**是什么**：对会话头部流程图 token 展示的一次**排版与阈值修正**——把「名字与数字并排」改为「名字在上、数字在下」，用纵向空间换横向空间，从而让**每节点明细**在窄窗口也留得住。

**核心价值**：用户要回答的问题是「**每个节点各烧了多少**」。上一轮只保证了「至少有个总数」，明细在窄窗口仍然消失。本次让明细本身在几乎任何宽度都可见。

**与现状的区别**：
- 现状：容器 <1000px → `.dsh-pm-flow-token` 整批 `display:none`，只剩累计总数；
- 改后：节点内上下两行、阈值按 214px 实测重算 → 只要节点名还在，它下面就有该节点的数；累计总数只在明细看不见时才出现。

## 用户与角色

| 角色 | 什么场景用 | 痛点（现状） |
|---|---|---|
| 看板使用者 / PM | 会话跑到一半想知道「哪个阶段最烧」 | 窄窗口只剩一个总数，看不出是设计还是实施烧的 |
| Agent（各窗口） | 自证某阶段消耗、判断要不要拆小 | 同上，只能点开详情翻 Token tab |
| 插件维护者 | 改头部档位 | 阈值是旧尺寸的旧账，且档位规则把「有名字」和「有数」拆成了两件事 |

## 边界

- **不做**：不改 token 口径（仍是执行会话累计快照差值；**不含子代理**——已按人裁定另立项）。
- **不做**：不给最窄档（D 档，只有圆点）硬塞每节点数字；D 档保持「圆点 + 计数 + 累计总数」。
- **不做**：不改芯片座位（仍在右侧工具组 `order -20`）、不改详情面板锚定、不新增后端字段。

没写进上述边界的，即本次不做。

### 详细说明

**FR-1: 节点内改上下两行**
`.dsh-pm-flow-meta` 由「名字与数字左右并排」改为**纵向**（`flex-direction: column`，居中对齐），节点宽取 `max(名字, 数字)`——不再被 32px 最小宽压到数字与邻节点碰撞（实测：并排时 700px 窗口下数字串成 `827.8k10.9M922.0k12.7M`）。
判据：截图里每个数字都在其节点名字**正下方**且互不重叠；结构断言存在。

**FR-2: 阈值按实测重算（有名字就有数）**
`FLOW_TIERS.token` 从 1000 下调，取值由实测决定并落到「有节点名就有该节点的数」：
上下模式实测 7 节点名 + 4 数字 + 6 连线 = **214px**，芯片总宽 **320px** → 容器低至 ~600 仍放得下（design 阶段按探针复测定死具体数值，**只改 `FLOW_TIERS` 单一源与三段 `@container`**）。
判据：探针每档「可见节点名数 == 可见节点 token 数」，且容器 ≥780 档位 `节点级 token ≥ 1`。

**FR-3: 累计 Token 徽章只在明细不可见时出现**
`.dsh-pm-cprog-token-total` 改为**默认隐藏**（宽档不再与明细重复显示「一共多少」），在节点明细被隐藏的档位（`@container` 内的窄档规则）才显示。
判据：宽档截图中无该徽章；窄档截图中该徽章在场；探针「明细不可见时总数必在」断言通过。

**FR-4: 可证伪回归**
① 探针新增两条断言（有名字就有数 / 明细不可见时总数必在），并更新档位期望表——**改造前这两条必须有档位是红的**（B/C 档「有名字没数」）；
② `tests/header-progress-responsive.test.ts` 更新 `FLOW_TIERS` 常量断言、新增 meta 纵向与徽章显隐规则断言；
③ `pnpm build:client` 退出码 0；
④ 宽/窄两档截图（窄档为本次的重点证据）。
判据：上述命令退出码 0 + 截图落盘。

## 现状证据（E）

- **E-1**：窄档确实一个节点数都没有。探针实测（改造前）：容器 1232 → `tokens=2+1`；容器 976/852/720/592/452 → `tokens=0+1`（节点级 0，只有上一轮加的累计徽章）。
- **E-2**：隐藏发生在展示层。`src/client/styles/board.ts` 的 `@container (max-width: FLOW_TIERS.token)` 块内 `.dsh-pm-flow-token { display: none }`；`FLOW_TIERS.token = 1000`。
- **E-3**：**旧阈值是旧账**。文档写「带 token 近 790px」，但那是节点缩小前的尺寸（变更史第二轮：圆点 22→14px、节点最小宽 58→32px、内边距收紧），之后没人重算。本次实测并排 = 358px、上下 = 214px（芯片 463 / 320px）。
- **E-4**：并排布局在窄档会碰撞。700px 窗口强制显示时，数字串成 `827.8k10.9M922.0k12.7M`（节点被压到 20–32px，数字比节点宽）——这是改上下模式的直接动因。
- **E-5**：数据一直在。`nodes[].tokens.total` 由 `src/http/routers/stages.ts` 的 `nodeTokensOf` 给出（本次不动后端）。
- **E-6**：上一轮交付（REQ-261004143941-b2ca）已归档：累计徽章 + 探针「各档可见 token ≥ 1」硬断言；本需求改的是**明细的排版与阈值**，以及徽章的显隐策略。

## 已定决策与待裁定项

- **已定（用户裁定）**：走**上下模式**（名字在上、数字在下）；「每节点 token」要显到窄档；**累计徽章只在明细看不见的窄档出现**。
- **待裁定（design 阶段）**：`FLOW_TIERS.token` 的最终取值（按探针在上下模式下复测定死）；C 档是否保留「仅当前节点的名字 + 它的数」；数字字号是否需要从 10px 微调。
