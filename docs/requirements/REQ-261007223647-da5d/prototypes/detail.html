FR-1 弹框投递与作答解耦

优先级 P0 · 后端为主 · 状态：线框
交互路径（确认票为例）：
1. agent 调工具 → 票先落台账（pending，带到期时间）→ 弹框只是票的「通知器」
2. 工具 30s 超时 / 调用中断 → 票仍在，看板与重投入口可见（FR-5 承接展示）
3. 人作答（弹框或看板）→ 作答到达即落盘（含「✖️ 不需要立项」拒绝留痕），不等调用延续段
4. 票丢失/中断 → 回执给 ticket，一键重投（同一张票重发通知，不新开第二道门）
分支：弹框通道不可用 → 票照样落台账，走看板作答；两边都不在 → 响亮失败，不静默。
