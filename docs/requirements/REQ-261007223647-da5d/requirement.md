# 需求说明（REQ-261007223647-da5d）

> **TL;DR**：弹框与确认门是人与流水线的唯一对话通道，现在它会吞答案（超时丢票丢留痕）、说黑话（✖️置首/裸哨兵/问数漂移）、没存在感（pending 票看板不可见）。本需求修三样：作答不丢、内容说人话、pending 看得见。得到：立项 1 次点击完成，挂起的门打开看板 10 秒可见。

> 状态：需求分析（brainstorming） · owner session-3a744c5e · 立据 2026-10-07
> 档位：轻档（依据见 §轻路径依据） · 长期页：[product-plan-ux-focus.md](../../strategy-research/product-plan-ux-focus.md) P1 项

```
  agent 调工具                    人                      看板
      │                           │                        │
      ▼                           │                        │
  票先落台账(pending) ──通知──▶ 弹框作答 ──作答即落盘──▶ 台账留痕
      │                           │ （超时/中断不丢）        ▲
      └──── 工具30s超时 ≠ 票消失 ──┘                        │
      └──────────────── 看板首屏醒目展示 pending 票 ────────┘
                        （剩余时间 + 一键作答/重投）
```

## 一句话目标（L1）

让弹框与确认门「内容说人话、作答不丢失、pending 看得见」——弹框默认动作 = agent 推荐项；
工具超时不再吞掉人的作答与留痕；挂了的人工门在看板一眼可见、一键可答。
**可证伪判定**：§验收标准 每条附可跑命令或台账读数，全过 = 完成。

## 背景与证据

2026-10-07 真实使用事故（交接自 REQ-261007210801-3bff 规划对话）：

1. 用户连续取消 3 次弹框（立项三问 2 次 + ask_user_question 1 次），最终走文字路径才完成立项；
2. `reqboard_submit(kind=verification)` 工具 30s 超时 → 确认票 pc-a3d0aa 丢失（interrupted），挂死阻塞下游约 30 分钟；
3. 用户不知道有票挂着——pending 确认票在看板不够醒目。

本需求 brainstorming 期间代码审核新坐实三条（均为 2026-10-07 实读证据）：

4. **立项弹框 ✖️ 置首**：[capture-mapping.ts:106-118](../../../../src/application/internal/capture-mapping.ts) 把「✖️ 不需要立项」硬编码在第一位，agent 推荐候选被挤到第二位，与工具提示词「最贴切一项放首位」直接矛盾；
5. **拒绝留痕不落盘**：`~/.dsh/state/capture-rejections.json` 中无用户最近一次点「✖️ 不需要立项」的记录——`record()` 在工具调用延续段执行，调用超时/中断则答复与留痕一起丢失，拒绝粘滞（FR-5）形同虚设；
6. **文档打开拿错根**：[open-doc.ts:78-90](../../../../src/client/open-doc.ts) 三级根回落（需求级根 → 会话工作区 → 服务端根）在缓存缺失/串会话时拼出错地址（用户现场：地址落到 ./dsh 文件夹下，实际文件在工作区文档位置）；台账记录本身正确（docBasePath / workspaceRoot 已验证），是前端解析链 bug。

## 边界（不做什么）

- B1 不改五道人工门的存在性与强度（产品纪律，本需求只优化体验层）；
- B2 不动 host 半状态机与台账/API 结构——FR-1 若设计阶段判定必须动，本需求立即升级重档并在设计文档单列说明；
- B3 不做视觉重设计/换肤；不做 P2–P4（看板首屏信息架构 / 卡点可见 / 空态引导，按规划页另行立项）。

## 产品定义

弹框与确认门是人与流水线的唯一对话通道。本需求把它从「会吞答案的死弹框」修成：
**内容**（题干带上下文、推荐项可辨可一键过）、**可靠**（作答与留痕不随调用超时丢失）、
**可见**（pending 门在板上有醒目的存在感和剩余时间）三个维度达标。

## 用户与角色

- **唯一用户**：维护者本人（人）——弹框作答者、看板读者；
- **agent**：弹框内容生产者（title_options / summary / reason），不替代人作答；
- **看板**：弹框通道不可用/人不想弹框时的降级作答通道。

## 功能点

- **FR-1: 弹框投递与作答解耦**：弹框投递、人作答、留痕落盘不再绑死在同一次同步工具调用上——工具 30s 超时 ≠ 弹框消失/答复丢失/留痕丢失。确认票丢失支持一键重投；「✖️ 不需要立项」等弹框作答在到达时即落盘（不依赖调用延续段存活）。
  宿主侧实测依据（2026-10-07，app.asar 内 `dsh-user-questions`）：Client 倒计时结束以 `ASK_TIMED_OUT` reject，host **映射为 pending 结果**（非错误），卡片仍可作答，迟到回答以 steer 交给 agent 且答案批次与即时回答同形——解耦能力宿主原生存在，本 FR 的实质是**插件侧接住它**（超时留票 pending + 接 steer/看板作答）。
  判据：新增/改造的单测通过（模拟调用中断后作答与拒绝留痕仍可查），`pnpm vitest run` 相关测试文件退出码 0。
- **FR-2: 取消/拒绝后的替代作答引导**：用户取消弹框时给出可见的替代作答方式（看板路径/文字路径）；同一窗口连续取消 N 次（N 设计阶段定，初值 3）主动提议改走看板，不再裸重弹。
  判据：取消路径的回执文案含替代作答方式（`grep -c "看板" <取消回执文案源文件>` ≥ 1）；连续取消计数有台账读数可查（读数键名设计阶段定，验收时按读数 = 实际取消次数核对）。
- **FR-3: 立项弹框内容重构**：第一段——题干带一句话立项理由（reason/summary 接入弹框）、推荐候选置首、「✖️ 不需要立项」置末并写明收益（30 分钟不再弹）、新增「全部按推荐值立项」一键过（后四问走默认并记 defaults_used）；第二段——算力档位问项按「影响 LLM 算力投入」重写选项说明、文档位置/工作区两问合并为一问「文件落点」（方案 A，选项直接给拼好的绝对路径预览）、推荐标记全弹框统一一种写法、消灭裸哨兵标签（session-workspace 等机器词不得面向用户）。
  宿主推荐契约（2026-10-07 实测 `dsh-client-ui-user-questions`）：**仅当第一个选项的 label 以 `（推荐）`/`(recommended)` 结尾**（半全角括号、大小写不敏感）时宿主才预选该项并渲染推荐标记；description 里的推荐字样宿主不参与判定（现状「死弹框」根因）。注意：提交回来的 selected 是**含后缀的原始 label**，映射层必须先剥后缀再严格相等校验，否则静默回落默认。
  判据：capture 弹框构造单测断言首项 label 带 `（推荐）` 后缀且 = 推荐候选、✖️ 居末、问项数 5→4、映射层剥后缀后类型/难度取值不回落默认；原型 prototypes/detail.html #FR-3 与人确认一致。
- **FR-4: 文案口径一致性**：立项问数六处不一致对齐到单一事实源（实际 4 问：名称/类型/算力档位/文件落点——CAPTURE_QUESTION_IDS 同步收口）；submit prompt「五类」补 prototype；全工具面文案漂移按 [reqboard-plugin-audit-2026-10-07.md](../../strategy-research/reqboard-plugin-audit-2026-10-07.md) 清单收口。
  判据：`grep -rn "三问\|四问" src/tools src/application` 命中数 = 0 或全部与事实源一致；提交契约扫描测试通过。
- **FR-5: pending 确认票看板醒目**：看板首屏对 pending 确认票醒目展示（剩余时间 + 一键作答入口），人不用进详情页即可发现并处理挂起的门。
  判据：看板渲染断言存在 pending 票区块且含剩余时间与作答按钮（`npx vitest run tests/` 下新增看板渲染用例全绿，断言选择器设计阶段定）；原型 #FR-5 与人确认一致。
- **FR-6: 文档打开根解析修复**：open-doc 三级根回落在需求级根缓存缺失/串会话场景拿错根的链路修复；面板显示地址与文件实际落盘地址一致性自检（不一致即红字，不静默）。
  判据：新增解析链单测通过（`npx vitest run tests/` 下 open-doc 根解析用例全绿：缓存缺失/串会话两场景均解析到需求级 workspaceRoot）；用户现场路径（./dsh 错地址）不再复现，面板地址 = 落盘地址（取值比对：`data-doc-dir` 属性 == 台账解析目录）。

## 失败与并发路径

- **失败路径**：验收发现「弹框仍吞作答 / 地址仍错 / 文案仍漂移」→ 按验收意见返工，对应 FR 的实现卡重做，不进入归档；
- **并发重复**：使用期间再冒出新的弹框/看板体验问题 → 记需求评论留痕，不扩本需求范围；P2–P4 的念头由规划页拦截，另行立项；
- **状态机非法迁移**：范围或方案反悔（如文件落点改回两问）→ 不直接改代码，重交 requirement.md + change_note，旧确认自动作废后重新确认。
