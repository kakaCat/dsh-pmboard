# 用例设计（REQ-261005154851-8512）

> 需求源：`requirement.md`（FR-1~FR-5）。场景语言：谁 → 什么条件 → 做什么 → 看到什么。
> 字段与签名见 `interfaces.md` / `data-model.md`，文件级改动见 `backend.md`，用例编号见 `test-cases.md`。

## UC-1 每轮系统提示词：选了 expert 就拿到重档 `serves: FR-1, FR-2, FR-4`

**谁**：任何挂着 expert 需求的窗口。**条件**：该需求仍是可注入节点（brainstorming/design/…），文本描述本身推不出档位。

1. 触发：宿主组装下一轮系统提示词（每轮都会发生，不需要人做任何事）。
2. 插件侧：读同步缝 facts（该窗口的开态需求）→ 取 `promptDifficulty` → 映射成两档 → 传给唯一取词入口
   → 声明档与文本推断**取重不取轻** → 命中的分片进提示词。
3. 留痕：把最终档位与依据写进注入记录。
4. **看到**：该轮注入记录里 `fragmentIds` 是 `brainstorming/heavy*`（改造前是 `light*`），
   `difficultyReasons` 里有一句「声明难度 expert → 取词档 heavy」。

**对照（改造前后）**：同一条需求在同一阶段，改造前留痕 `light`、改造后 `heavy` —— 两段记录可同屏对照。

## UC-2 无声明 / 脏数据：行为与改造前逐字相同 `serves: FR-1, FR-2`

**谁**：存量需求（立项时没走四问弹框）或历史脏数据。**条件**：`promptDifficulty` 缺省、或是 `'EXPERT'` / `' expert '` / `''` 这类非法值。

1. 插件侧：映射返回"未声明" → **不传** `declaredDifficulty`（不填 `undefined` 占位）。
2. 取词：只按文本推断（推不出 → 默认轻档）。
3. **看到**：`fragmentIds` 与改造前**逐字相同**；`difficultyReasons` 可以为空——不编造依据。

**边界**：不抛错、不猜档、不因为"读不懂"就提到重档（那会让纪律与事实脱钩）。

## UC-3 另两条注入路径：留痕与隔离上下文同口径 `serves: FR-3`

**谁**：dive 驱动器（采集半）与节点隔离/输入包。**条件**：同一条 expert 需求。

1. dive 采集半：用同一份 facts 取词 —— **只留痕、不投递**（性质不变），但档位与 UC-1 一致。
2. 节点隔离 / 输入包：调用方**显式**给的 `difficulty` 优先；没给时用声明难度映射值；
   两者都没有 → 不传（默认 light，与改造前一致）。
3. **看到**：三处入口对同一条需求取到**同一档**；留痕里不会出现"系统提示词说重档、采集半说轻档"这种自相矛盾。

**边界**：需求记录读不到时不阻断节点隔离（它是增强，不是门）——只是回落默认。

## 结果观感对照 `serves: FR-2, FR-4`

| 情形 | 注入的分片 | 留痕里看到什么 | 人/agent 的感受 |
|---|---|---|---|
| expert + 文本推不出（本需求自己） | `heavy*`（改造前 `light*`） | 「声明难度 expert → 取词档 heavy」 | 拿到的是与选择一致的完整清单 |
| simple + 文本推断重 | `heavy*`（**取重**） | 冲突说明 + 最终取值 | 宁可多给纪律，不少给 |
| 无声明 + 推断不出 | `light*`（与改造前逐字相同） | 无依据句（不编造） | 存量需求不受影响 |
