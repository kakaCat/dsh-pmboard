1. 三态并排对照

P1 · 服务条款 FR-7 · 页内锚点 #FR-7 · 每态 ≥3 条 chip，取自只读核对的真实读数口径 （本仓若干 / dsh-notice-webhook 6 条 / quantsys-v2 1 条 / 归属未知 3 条）
A本仓态（根 == 当前工作区根）

第三条是 data-status="canceled"：既有删除线规则保留，来源标记不干扰它。

渲染规则：root === currentWorkspaceRoot → 标 本仓（10px、--dsw-text-secondary、opacity .75，非胶囊、无边框）。
为什么这么轻：本仓是绝大多数（37 条里 27 条），信息量为零；给它浓标记＝把噪声当信号，会挤掉 B/C 态的可辨识度。
B在别处态（根 ≠ 当前工作区根）
渲染规则：rootOfRequirement 给出的根 ≠ 当前工作区根 → 标 在别处 · <项目名>。 项目名取项目条目的目录基名（basename(root)），不新造名字映射表。
为什么显眼：这是「点开一片空白」的唯一解药——名字进 chip 本体（等宽、可扫），颜色只是二次强化。
C归属未知态（无 projectId 且无 workspaceRoot）
渲染规则：rootOfRequirement() === undefined → 标 归属未知（警示色 --pm-c-warn、虚线边框、非等宽）。
为什么必须是警示色而不是灰：灰色＝「没什么可说的」，会被读成「本仓默认」——正犯了 F-1/D-6 要禁的「冒充本仓」。 虚线边框是「这里有个待补的洞」的非颜色编码，色盲用户同样可辨。
三态的区分手段不靠颜色，而靠可读文本：本仓＝纯文字「本仓」（最轻）、在别处＝胶囊内「别处·项目名」（等宽名可扫）、 归属未知＝「归属未知」虚线胶囊。颜色只在第二层做强化（accent / warn），任一条 chip 去掉颜色后语义不丢 ——满足「不靠颜色单独传达信息」。chip 行仍是一行一条、不换行（实测 chip 高 24px、无折行）， 37 条密度不因新增标注而膨胀。
一处为可读空间做的收缩：REQ id 从 11px 降到 10px 等宽（新增 .dsh-pm-archived-id）。 原因：11px 等宽下 id 单占 150px，加上标题与计数已达约 320px，再加来源标注就会折行； 降 1px 省约 20px，且 id 是定长可扫串，可读性不受影响。这是本页唯一的「既有 chip 内字号变更」， 实现时若不接受该变更，替代方案是保留 11px 但把标题截断上限压到 120px。

2. chip 的紧凑态与 hover 展开态

日常（紧凑）不给来源留白；只有需要判断「去哪找文件」时才展开细节。第三行是「点开后」的落地形态。

① 紧凑态（默认）

无来源标记的旧 chip 与本行对比时，唯一差异是 chip 尾部多出的 5–8 字符标注；chip 高度、圆角、字号、间距逐字未改。

② hover 态（既有规则：background: rgba(74,125,255,.12) + accent 前景，来源标注不变）

hover 是既有规则原样（本页第二行把该视觉固化成静态样例；真实交互仍由 CSS :hover 承担）。 来源标注在 hover 时不消失、不位移——避免 hover 造成的行宽跳动（CLS / 误点）。

5. 相对现状的改动面（供实现对齐）

FR-7 边界 2：样式沿用既有 dsh-pm-archived-chip 分片，新增态用既有设计令牌。
  • DOM：chip 内追加 <span class="dsh-pm-archived-src" data-src="local|elsewhere|unknown">； 标题文本包一层 <span class="dsh-pm-archived-text">（为 nowrap + 省略号）。 既有 data-action / data-req / data-status / title 属性逐字保留。
  • CSS 新增选择器：仅 .dsh-pm-archived-src[data-src="…"] 三条 + .dsh-pm-archived-text 一条； 全部只用既有令牌（--dsw-accent / --dsw-text-secondary / --pm-c-warn / --pm-radius-sm / --pm-bg-soft / --pm-line-strong），无新色值、无新字体族。
  • 样式复用：提示块走既有面板语汇（卡片 1px 线 + 6px 圆角 + 3px 左侧色条）；归档材料的「存在 / 不存在」小标复用既有 .dsh-pm-artifact-chip.confirmed / .missing；机器产物折叠复用 <details> 折法（与既有 .dsh-pm-archived-fold 同构）。
  • 判据单一来源：三态一律由 rootOfRequirement() 的结果派生（undefined → C；sameProjectRoot(root, current) → A；否则 B）， 不新增路径字符串比较型判定（D-4）。
  • 可访问性：三态皆有可读文本（不靠颜色单独传达）；title 保留全值披露； hover 无位移、无布局跳动；沿用既有焦点描边（不删 focus ring）。
