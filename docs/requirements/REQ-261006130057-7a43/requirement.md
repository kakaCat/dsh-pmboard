# 需求说明（REQ-261006130057-7a43 PM 插件需求详情页 UI 优化（原型先行））

> 本文档面向：产品、开发、测试、用户——**写给人看，不是写给代码看**。
> 本轮**原型先行**：先在 `prototypes/detail.html` 上做可视评审，人点头的方向才进设计/实施。

## TL;DR

- **这是什么**：对看板「需求详情页」（常驻头部 + 状态带三格 + 六个同级 Tab 的工作汇报壳，
  `src/client/views/report-tabs.ts`）再做一轮 UI 优化。
- **为什么现在做**：上一轮（REQ-261005155003-f32f）解决了可访问性达标与视觉语言收敛，
  但**信息层级与版面效率**仍有问题：头部 meta 一行平铺到底、状态带三格等大导致「缺口」
  权重不足、最近评论纵向占地大、汇报 Tab 模块留白多一屏只见一两个模块。
- **做完得到什么**：一份经人确认的优化原型（`prototypes/detail.html`，INDEX 标 authoritative），
  以及按原型落到 `src/client` 的实施（设计/拆分阶段定）。

## 边界

```
  需求详情页（工作汇报壳，src/client/views/report-tabs.ts）
  |
  +-- 常驻头部 ......... FR-1 信息分层 + 操作区聚类 + 闸门提示条
  +-- 状态带三格 ....... FR-2 缺口强化为视觉焦点，结果占位折叠
  +-- 最近评论 ......... FR-3 单行紧凑 + 长日志收纳
  +-- 进度带 + Tab 栏 .. FR-4 收敛（Tab 6 → 7）
  +-- Tab 面板
       +-- 汇报 ....... FR-5 模块网格排版
       +-- 文档 ....... FR-6 紧凑分节（验收单节提出 → FR-8）
       +-- DAG ........ FR-7 沿用画布，只做容器/工具行适配
       +-- 对话 ....... FR-6 三色身份时间线
       +-- 验收 ....... FR-8 新增：逐项表 + 材料 + 历史 + 空态
       +-- Token ...... FR-6 汇总卡 + 节点表
       +-- 提示词 ..... FR-6 注入 chips + 片段列表
```

- **原型先行**：本轮先交原型给人评审；评审意见逐条进 D-x 后才进 design。
- 默认**不改取数、不改写路径**（沿用上一轮冻结口径）；信息架构是否可动由原型评审裁定（挂 D-x）。
- 接口/数据契约：本轮无新增或变更字段；若原型评审要求结构调整，进 design 时补契约。

## 产品定义

看板需求详情页是「人审一条需求」的主界面。本轮优化的判定标准：
首屏信息层级一眼能分出「这条需求是什么 / 卡在哪 / 要我做什么」，且常用操作与关键缺口
不被次要信息稀释。

## 用户与角色

- **人（owner/评审者）**：打开详情页做阶段裁决（批准计划 / 验收 / 退回），需要快速定位缺口与操作。
- **窗口 agent（worker/observer）**：通过同一页面回看进度与留痕。

## 功能点

- **FR-1: 头部信息分层与操作区聚类**——标识行（REQ-id / 状态 / 分类 / 难度）、标题、
  meta（停留/更新/创建）、席位 chips、操作按钮分区；主操作聚合到固定一侧，「需人工确认」
  类闸门提示有明确视觉锚点。
- **FR-2: 状态带三格视觉权重**——「做到哪了 / 缺口 / 结果与成效」不再等大平权；
  缺口（该有而没有）强化为视觉焦点，结果与成效占位态弱化。
- **FR-3: 最近评论区紧凑化**——长评论截断样式与收纳态统一，纵向占地收敛。
- **FR-4: 进度带与 Tab 栏紧凑化**——8 段进度带与 6 Tab 的间距/字阶收敛，激活态与计数徽章可读。
- **FR-5: 汇报 Tab 模块排版密度**——「为何做 / 解决什么」等模块的标题-正文-来源行排版收敛，
  减少无效留白。
- **FR-6: 文档 / 对话 / Token / 提示词 Tab 内容优化**——四个 Tab 的面板内容沿用 FR-4/FR-5
  同一套字阶与密度语言逐版优化（文档分节、Token 表格、注入片段）；**对话 Tab 按 D-5
  改聊天 App 形态**：气泡式消息（人/窗口/agent 身份色）、分页加载、正序展示
  （旧→新，最新在底部，向上翻更早）；**只读历史记录，无发送输入条**（D-6）。
- **FR-7: DAG Tab 沿用现有画布并适配新版式**——DAG 画布组件不重做；做容器宽度、缩放、
  空态与新版式的适配。
- **FR-8: 新增「验收」Tab**——现状验收单埋在「文档」Tab 的核验节里、无独立落点；
  新增同级「验收」Tab，**主视图为 RTM 验收追踪列表**（D-8：每 FR 一行——覆盖链
  设计/任务/测试状态 + 验收状态 pending/passed/failed/unverified + 证据与意见，
  行可展开看逐项实际结果）；辅以验收材料摘要、历史版本；无验收单时给解释性空态；
  验收阶段有待裁决项时 Tab 给徽标。

## 验收（草案）

- 原型评审：人对着 `prototypes/detail.html` 逐区块点头/给意见（意见落 D-x）。
- 实施后：复用既有截图脚本出 before/after 对照图（1280/900 × 在途/终态），人评审通过。
