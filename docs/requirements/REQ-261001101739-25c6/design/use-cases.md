# REQ-261001101739-25c6 用例设计 · 谁在什么时机受影响 `serves: FR-1, FR-2, FR-3, FR-4`

> 本需求没有新交互；「用例」是**样式表被装卸的四种时机**下用户看到什么。
> 每个用例给出：触发 → 修复前 → 修复后 → 观测点。

## UC-1 · 用户刷新 / 长时间挂着会话（原始故障场景）`serves: FR-1, FR-2, FR-4`

| 项 | 内容 |
|---|---|
| 触发 | 用户在会话里刷新页面（⌘R），或开着窗口几小时、期间别的插件经历装卸 |
| 修复前 | 页面加载后本表被下一个 materialize 的别的插件认领；那个插件一被替换，本表被连带删除 → **流程图竖排成一列裸文字**，且不会恢复（用户只能反复刷新撞时机） |
| 修复后 | 本表带归属章 → 别的插件认领不走 → 删除永不发生；即便被任何来源删除，在屏组件 ≤15s 内自愈 |
| 观测点 | `.dsh-pm-flow` 的 `display` 恒为 `flex`；圆点四态配色/连线在 |

## UC-2 · 开发者重建 client bundle（HMR 替换本插件）`serves: FR-3`

| 项 | 内容 |
|---|---|
| 触发 | `pnpm build:client`（HMR 推送新 rev → 宿主 `replace(本插件)`） |
| 修复前 | `removeOwnedStyles(本插件)` **删不到**本表（表无主）→ 新旧两张表并存（样式表泄漏：旧 CSS 永久留在文档里）；同时新工厂不注入（注入在 `apply()`，且 `apply()` 因 `data-plugin-css` 守卫跳过）→ 用户看到的是**旧 CSS** |
| 修复后 | 宿主正确删除本表 → 新工厂执行期立即重建（实测 5 ms）→ 样式内容与归属一致，无空窗、无泄漏 |
| 观测点 | 生命周期日志：`remove` → 5 ms → `append`；表数量恒为 1；`textContent.length` 不变 |

## UC-3 · 别的插件装卸（与我们无关的第三方）`serves: FR-1`

| 项 | 内容 |
|---|---|
| 触发 | 用户启用/禁用任一别的 UI 插件，或那个插件触发热替换 |
| 修复前 | 那个插件的 `materialize` 会认领本表，它的 `removeOwnedStyles` 会删掉本表 → **我们被别人的装卸流程连带伤害** |
| 修复后 | 本表已有归属，`claimStyles` 第一轮循环跳过 → 与别的插件生命周期完全解耦 |
| 观测点 | 复刻片段（`test-cases.md` T-4）执行后本表仍在、流程图仍横向 |

## UC-4 · 存量文档里残留旧无主表（升级路径）`serves: FR-2`

| 项 | 内容 |
|---|---|
| 触发 | 用户窗口里已有一张修复前注入的无主表，随后加载了新 bundle |
| 修复前 | 新 `injectStyles()` 只查 `data-plugin-css` → 认为「表已在」直接返回 → 旧表**保持无主**，仍会被别的插件带走 |
| 修复后 | 查到既有表但归属不符 → **就地纠正**为本插件（不重复插表）；旧表从此有主，并可被本插件自己的替换流程正确重建 |
| 观测点 | 表数量恒为 1；`data-plugin` 由 `null` 变 `"dsh-pmboard"` |

## UC-5 · 无 `document` 环境（host 半 / node 单测）`serves: FR-3`

| 项 | 内容 |
|---|---|
| 触发 | 单测（node 环境）或任何非浏览器上下文求值到本模块 |
| 修复前 | 同样静默（`typeof document === 'undefined'` 早退），无差异 |
| 修复后 | 行为不变：静默 no-op，不抛错；**模块求值期调用**也必须遵守这条（单测 T-1 的最后一条锁定） |
| 观测点 | `injectStyles()` 不抛 |
