# 架构设计 · REQ-261001203710-0fbf <!-- serves: FR-1, FR-2 -->

> 一句话：**给数据加「项目」维度，并让每条取路径的操作按该条记录自己的项目解析**；共享的 `cwd` 与可变根指针只作兜底。

## TL;DR <!-- serves: FR-1 -->

根因不在路径，而在**数据层没有项目维度**：一份 profile 级台账装 4 个工作区的 25 条需求，遍历时取「全部 id」、用「同一个 cwd」逐条处理；记录里虽有 `workspaceRoot`，却不拿它做分区键。路径错乱只是它的症状（已由 REQ-260930193929-897b 在读侧打了补丁）。

## 现状：数据无项目维度，处理却是"一个项目" <!-- serves: FR-1 -->

```
   ~/.dsh/dsh-reqboard.json      一份平铺文件
     requirements[]              25 条 ← 4 个工作区混在一个数组
            │ 载入
            ▼
   store.snapshot()              内存快照：没有「项目」维度
            │
   syncAllReqArtifacts(store, cwd)
     ids = snapshot.requirements.map(r => r.id)     ← 取【全部项目】
     for (id of ids) scan(id, cwd)                  ← 用【同一个 cwd】
```

**两处错配同时存在**：**遍历不分区**（把别人的记录也拿来处理）＋ **路径不按记录解析**（用调用方的 cwd 去解析别人的记录）。

## 改动设计：分区键 + 逐记录解析 <!-- serves: FR-1 -->

```
   处理入口（看板 / 工具 / 用例）
        │  拿到目标记录（或记录集）
        ▼
   projectRootOf(req, fallback)          ← 新增纯函数：记录的项目根
        │  req.workspaceRoot 非空 → 用它
        │  否则 → fallback（调用方上下文）+【标注未归属】
        ▼
   ├─ 遍历类：只遍历 workspaceRoot === 本次项目 的记录（其余跳过并计数回报）
   ├─ 取路径类：按 projectRootOf 解析（扫描 / 落盘 / 读取）
   └─ 写盘前校验：解析出的根 ≠ 记录声明的 workspaceRoot → 响亮失败（两个绝对路径）
```

| 维度 | 现状 | 改后 |
|---|---|---|
| 遍历 | 全部项目的 id | 只遍历本次项目的记录（其余跳过 + 计数） |
| 路径解析依据 | 调用方的 `cwd` / 共享可变根 | **该条记录自己的 `workspaceRoot`** |
| 错配时 | 静默写到别处 / 静默读空 | 响亮失败 + 打印两个绝对路径 |
| 未归属记录（无 `workspaceRoot`） | 静默当成当前项目 | 按兜底根处理并**标注** |

## 点名的调用点（逐记录解析的接线面） <!-- serves: FR-2 -->

| 环节 | 位置 | 现状 | 改后 |
|---|---|---|---|
| 看板产物扫描 | `src/adapters/ArtifactSync.ts` `syncAllReqArtifacts` | 全部 id × 单一 cwd | 逐记录用 `projectRootOf`；非本项目跳过并计数 |
| 计划落库 | `src/application/internal/plan-landing.ts` `landPlanTasks` | 用共享根指针 | 落盘前按记录根校验；错配即拒 |
| 立项建档 | `src/application/use-cases/CaptureRequirement.ts` / `CreateRequirement.ts` | 建档写盘沿用共享根 | 按记录根写；返回体带 `usedProjectRoot` |
| RTM 写入 | `src/application/internal/rtm-yaml.ts` | 沿用共享根 | 按记录根写 |
| 知识层检索 | kb 工具读取处 | 按共享根读；读不到 → 「未初始化」 | 按**当前项目**根读；读不到区分「本项目未生成」与「空间错配」 |
| 读侧闸门 | 已归档 897b 的 7 处 | 已按需求根校正（补丁） | 复用同一 `projectRootOf`，口径统一 |

## 为什么不做「拆存储」（明确边界） <!-- serves: FR-2 -->

- 拆成「每项目一份台账文件」或「每项目一个仓储实例」会牵动组合根、全部调用点与迁移，属**存储与装配重设计**，已列入需求「边界」不做，出现即按 L3 单向升级信号停手另立重档。
- 本设计只做**在既有字段上补分区 + 逐记录解析**：台账文件格式不变、ports/适配器契约不变、不新增子系统。

## 可观测性（顺手解决"看不见"） <!-- serves: FR-2 -->

「根不对」之所以能潜很久，是因为没有任何地方如实说「我这次用的是哪个项目根」。设计上加两处：

- 立项 / 落库的返回体带 `usedProjectRoot`（绝对路径）。
- 错配拒绝文案里同时给「记录声明的根」与「实际会写的根」。

## 风险与回滚 <!-- serves: FR-2 -->

- **风险**：`syncAllReqArtifacts` 改为逐记录解析后，跨项目的历史产物不再被「顺带扫描」——这是**预期行为**（本来就不该扫别人家），但会让原本靠误扫而"自动补登"的条目不再自动补登。回滚方式：还原该函数。
- **风险**：未归属记录（3 条无 `workspaceRoot`）的口径若选错，会让它们无法被处理。设计取「按调用方兜底根 + 标注」，保证仍可处理、只是显式标注。
- **无数据迁移**：不新增字段、不改文件格式，回滚 = 还原源文件。
