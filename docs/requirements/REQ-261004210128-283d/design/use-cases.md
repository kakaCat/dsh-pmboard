# 用例设计：看板会话运行中指示（REQ-261004210128-283d） `serves: FR-2, FR-3, FR-4, FR-5, FR-6, FR-7`

> 本文写「人在什么场景下看到什么」。每条用例的**可观测结果**都可在浏览器里直接看到，
> 或由 `test-cases.md` 的自动化用例证伪。

## UC-1 盯盘：一眼看出哪条需求在跑 `serves: FR-3, FR-4`

- **角色 / 场景**：同时开着 3～5 个窗口推进不同需求的人，打开看板想知道「现在谁在动」。
- **前置**：至少一条需求绑定了在线窗口（有 `sourceSessionId` 或 `seats`）。
- **主流程**：
  1. 打开侧栏「项目看板」（泳道视图）；
  2. 找到正在跑回合的那条需求；
  3. 观察卡面窗口 chip 行 → 出现转圈指示；同泳道其它卡无指示；
  4. 点右上「列表」切到列表视图 → 同一需求所在行标题列出现同款指示。
- **异常 / 分支**：
  - 需求卡在 `blocked` / `paused` / `done` 态：指示**独立呈现**，不被置灰 / 态标记吃掉（不是「运行时才显示」的开关）；
  - 切换泳道↔列表：两处同时出现、同时消失（同一判据）。
- **可观测结果**：`[data-running="true"]` 在泳道卡与列表行**同时**命中，且仅命中在跑的需求。

## UC-2 回合结束：指示即熄（不刷新页面） `serves: FR-5`

- **场景**：用户盯着看板，等某个窗口干完活。
- **前置**：该需求绑定窗口正在跑（UC-1 状态）。
- **主流程**：
  1. 什么都不做，看着看板；
  2. 该窗口的回合结束（生成完毕 / 被中止）；
  3. ≤2s 内卡面转圈自动消失，无需点「刷新」、无需切页。
- **异常 / 分支**：
  - 期间**别的**窗口在动：看板不得整体重绘（滚动位置不跳、展开态不丢）。
- **可观测结果**：指示自动消失（`data-running` 属性消失或元素移除）；看板滚动位置不变。

## UC-3 多席位需求：任一在跑即算在跑 `serves: FR-2`

- **场景**：一条需求 owner 窗口空闲、worker 窗口正在领卡干活。
- **前置**：需求含 `seats = [owner, worker]`。
- **主流程**：打开看板 → 该需求卡出现转圈。
- **异常 / 分支**：
  - 只有 owner 在跑 → 同样出现（任一即可）；
  - 全部空闲 → 不出现。
- **可观测结果**：真值表（`data-model.md`）逐行成立；映射函数对同输入幂等。

## UC-4 读数不可得：不显示，也不撒谎 `serves: FR-6`

- **场景**：旧版客户端（无 `sessions.list`）/ 服务未注入 / 会话尚未拉取到列表。
- **前置**：构造 `sessions` 服务缺失，或 `byId` 中无目标会话。
- **主流程**：打开看板 → 看板正常渲染，无指示。
- **异常 / 分支**：
  - 不允许出现灰点、「未知」、「可能在进行」这类占位文案；
  - 不允许用 `updatedAt` / `autoRun` 近似推断出指示；
  - 控制台无 `error`（降级不是失败）。
- **可观测结果**：零 `[data-running="true"]`；控制台干净。

## UC-5 人工建卡：无窗口即无指示 `serves: FR-2`

- **场景**：从看板人工创建的需求（无 `sourceSessionId`，无 `seats`）。
- **主流程**：打开看板 → 该卡不出现转圈，也不出现空壳；其余字段渲染与今天一致。
- **可观测结果**：该卡 DOM 与改动前逐字节一致（回归断言）。

## UC-6 动效偏好与读屏 `serves: FR-7`

- **场景 A（动效偏好）**：系统开启「减少动态效果」→ 指示为静态半环（不旋转），仍在位。
- **场景 B（读屏 / 悬停）**：聚焦或悬停指示 → `aria-label` / `title` 说明「会话进行中（绑定窗口正在执行回合）」。
- **场景 C（暗色主题）**：切换暗色主题 → 指示可辨（`currentColor` 跟随主题）。
- **可观测结果**：`prefers-reduced-motion` 下无旋转动画；`aria-label` 非空；暗色下肉眼可辨（截图入 evidence）。
