## 三、共性教训

1. **生成物与源文件同批写时，顺序会咬人**：`--write` 先算后写 → 新条目在清单里停在 `(缺)`，下次门禁立刻报漂移。规则：**先落源、再按源重算派生**。
2. **vendor 镜像档不能当普通片段改**：`heavy.md` 是 vendor SKILL 的逐字节副本，门禁会拦；要加本仓规则必须走 `heavy/overrides.md`。
3. **门禁要按作用域划分**：一个页面里两类条目用两套要素时，检查器必须显式声明自己管哪一节，否则"加门禁"会变成"误伤老规范"。
4. **演练不是仪式**：t7 演练抓出了 t2 的时序缺陷与证据备份缺口——两条都不是靠读代码能发现的。
