# 复盘（REQ-261004110201-f253）

## 一句话

实施链从「跑得对」进到「跑得省、看得见、排得清」——而且**不配置就等于没改过**。

## 交付了什么（四个功能点）

| # | 能力 | 一句话 |
|---|---|---|
| FR-1 | 阶段模型路由 | 按子卡阶段（可细分到难度档）指定 provider/model；没配就不注入，脚本逐字节与改造前相同 |
| FR-2 | 阶段遥测 | 每次子卡执行留下"干了多少活"（产出条目数 + 零产出标记），status 回执按阶段给出时长/产出/白跑次数 |
| FR-3 | 零产出告警 | 同一阶段连着白跑达阈值 → 台账一条结构化告警；**不自动改模板**，只把问题摆到人面前 |
| FR-4 | 优先级与在制上限 | 多需求并行时高优先级先跑；全局在制条数可设上限，超限不投递并如实说清在跑的是谁 |

## 重大设计决策（值得留档的三条）

1. **遥测不落第二个桶**：既有 `tokenUsage.byStage` 按 **prompt 阶段** keyed 且只装 token，
   而本次要的是**子卡阶段**的时长与产出。语义不同 → 遥测做成 `executions` 的**只读派生投影**，
   避免"同一事实两份、两个口径互相说谎"。
2. **在制判据 = 新鲜推进锁**，不是「autoRun 为真」：后者会把"已武装但还在排队"的需求也算在制，
   上限一开就自我堵死。
3. **未配置即现状**写进验收：三条等价面 + 一条"不回填历史数据"的诚实边界集中成一份用例，
   让"我们没改动老行为"这句话可复核而不是靠声明。

## 过程中的三次"踩到才发现"

| 现象 | 真相 | 留下的防线 |
|---|---|---|
| 在制判据读不到锁 | 摘要投影（`RequirementSummary`）没有 `lockAt`——排序/判定发生在投影之后 | 把 `priority`/`advanceLockAt` 两个**有界标量**加进摘要并进 `SUMMARY_KEYS`（出口形状检查会守） |
| 条款接收状态全红（FR-1~FR-4 未被接收） | 接收状态只认**计划文档里的覆盖对照表**，而本次计划用的是任务表 `serves` 列 | 补覆盖对照表；记下"两通道并存"这条契约（任务表 refs + 文档覆盖表） |
| `pnpm run kb:check` 报 2 处漂移 | 新增两个源文件后知识层生成物陈旧 | 按工程规范 `pnpm run kb:build` 重生成，自检 11/11 |

## 方法论

- **配置类能力的验收 = 「配置后生效」+「不配置不变」两面都要**；只有前者等于把风险留给下一个不配置的人。
- **未知 ≠ 0**：老记录没有产出计数，就当"未知"（不计入零产出、streak 在它那里断），宁可少报一次也不冤枉一段。
- **去重要可推导**：告警去重不用内存状态，而用 `floor(streak/threshold) > 已有告警数`——重放安全、多进程安全。
