# REQ-261002153446-c600 用例 `serves: FR-1, FR-2, FR-3, FR-4`

## UC-1 · 从看板回到已归档窗口 `serves: FR-1, FR-3`

- **角色**：看板使用者（人）。
- **前置**：某需求/任务卡的 chip 指向的会话已被归档（chip 灰态、title 提示「点击取消归档并打开」）。
- **主流程**：
  1. 人点击 chip；
  2. 插件调用 `workspaces.unarchiveSession(sid)`；
  3. 宿主把该会话移出归档集合（回到原侧栏位置）；
  4. 插件收面板（`selectPanel(null)`）并打开会话（`openSession(sid)`）；
  5. 人看到目标会话的对话。
- **后置**：会话在侧栏重新可见；看板下次重绘时 chip 不再灰。

## UC-2 · 恢复失败（动作抛错） `serves: FR-2`

- **前置**：会话已归档，客户端具备取消归档能力。
- **主流程**：点击 chip → `unarchiveSession` 抛错 → 返回 `restore-failed` → 弹框「取消归档失败（…）：未跳转，可到侧栏手动恢复后重试」。
- **不变式**：**不调用 `openSession`**——不制造「以为跳过去了」的错觉。

## UC-3 · 客户端不支持取消归档 `serves: FR-2`

- **前置**：运行在未提供 `unarchiveSession` 的客户端上。
- **主流程**：点击 chip → 不发起任何调用 → 返回 `archived` → 提示「该会话已归档，且当前客户端不支持取消归档」。
- **说明**：这是**旧语义的保留路径**，不是新失败；升级客户端后自动获得 UC-1 的能力。

## 非目标（本需求不做） `serves: FR-4`

| 不做的事 | 理由 |
|---|---|
| 跳转前先切换工作区 | 会话 id 全局唯一，宿主 `openSession` 已能定位；加一层只会引入新的失败面 |
| 新增二次确认 | 点击意图就是打开；恢复幂等且可逆，多一次点击不值得 |
| 在看板里做「会话管理」（批量归档/恢复） | 属宿主侧栏能力，看板只做「回到该窗口」这一件事 |
| 改动需求的归档状态与材料流程 | 本需求只涉及**会话（DSH session）**的归档，与需求 `archived` 状态无关 |
