# 架构（REQ-261008004324-81df）

> 本需求是 bug 档「红测试收口」，**没有产品面与接口面**；本文件记录的是**改动面架构**：
> 改动落在哪三层、层与层的边界是什么、为什么不碰生产代码。

## 改动面三层与边界 <!-- serves: BUG-1, BUG-2, BUG-3, BUG-4, BUG-5, BUG-6 -->

```
            ┌──────────────────────────────────────────────┐
pnpm test ─▶│ L1 测试层 tests/**（夹具 / 断言）              │─▶ 绿
            │   · 夹具面：把「已提交的新语义」如实建出来      │
            │   · 断言面：跟到新语义的回执键 / 文案 / 状态读数 │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
仓库门    ─▶│ L2 环境层（探针 / 依赖 / 打包资产）            │─▶ 绿
pnpm kb:check│   · 缺失宿主包 → 显式跳过（依据可读）          │
            │   · 守护对象消失 → 退休并留依据                │
            │   · 环境产物 → 清理 + 排除                    │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
            │ L3 基线层 docs/knowledge · docs/reviews        │─▶ 集合差
            │   · 生成物重生成、基线按结构判据 + 集合差       │
            └──────────────────────────────────────────────┘
```

- **为什么分三层**：三层的**修法不同**（改测试 / 改环境 / 改基线），而「红的表象」相同。
  按成因分层拆卡，才能让「为绿而绿」无处藏身（改断言属于 L1 的方法，但对 L2/L3 的条目是禁术）。
- **层间唯一耦合**：L3 的用例断言的是 L1/L2 的读数（如 kb-generate 断言库内行与 `src/` 同源），
  故 L3 的重生成必须先跑、再改断言；顺序在 `design/fix-design.md` 里写死。

## 与生产模块的关系（为什么不改 src/） <!-- serves: BUG-7, BUG-10 -->

| 生产模块 | 与本需求的关系 | 本需求的处置 |
|---|---|---|
| `src/application/internal/content-gate-wiring.ts` 等门禁 | 它是「新语义」的事实源 | 只读它、把夹具对齐它，**不改** |
| `src/repositories/QueueRepository.ts` | 读侧宽容与告警的事实源 | 只读，断言按它现形态跟进 |
| `src/index.ts:567` | 组合根漏传 `store`（t9 取证发现） | **点名另案**，本需求不改（另案清单一第 8 条） |
| `src/**` 全部 | 生产语义 | 本需求 13 张卡 **零改动**（逐卡复核段留痕） |

## 失败与并发路径（本层的） <!-- serves: BUG-8, BUG-11 -->

- **重生成与在飞改动竞争**：`kb:build --write` 会把此刻 `src/` 的结构一起吸收 ⇒ 前置检查
  「无他窗正在改 `src/` 结构」，跑完看 `git diff` 属正常。
- **基线刷新与他窗并发**：`test-baseline.mts --refresh` 只写 `failures.txt` + `md`，
  而分诊不变量要求三份清单同源 ⇒ 单独 refresh 会引入 3 条新红，已按仓规回滚（读数见
  `docs/requirements/REQ-261008004324-81df/tests/closeout-readings.md`）。
- **打包含 `prepare` 钩子**：`pnpm pack` 会触发 `prepare → pnpm build` 重写 `dist/`、`lib/`
  ⇒ 验证真实 tarball 时必须加 `--config.ignore-scripts=true`（t11 取证）。

## 不做的事（架构级边界） <!-- serves: BUG-10 -->

- 不新建测试框架、不抽公共夹具、不重构门禁接线（真缺陷一律点名另案）。
- 不改任何 schema / 表 / 迁移（见 `design/data-model.md` 的「不适用」声明）。
- 不动 B 类 5 文件（层边界 / 消息卫生 / 尺寸门禁 / 写盘点 / 活卡单源）——它们要改生产代码结构。
