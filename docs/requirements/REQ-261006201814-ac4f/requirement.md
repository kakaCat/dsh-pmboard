## 产品定义

把「测试到底有没有在判」从一句主观判断，变成**可复现的读数 + 可失败的守卫 + 真能拦住越界的护栏**。

交付物落在 `tests/`、`vitest.config.ts`、`docs/reviews/test-baseline*` 与测试夹具；**src 一个字节不改**（D-3）。
四件事：① 把「错误码」口径定义成代码；② 给每个可触发码配「触发→断码」用例并防新增码漏配；
③ 把红基线分诊成两个不相交集合；④ **真拦住**测试对真实工作树的写入。

## 实施期实证（回退的直接原因，也是本版的增量）

第一版走到 implementing、2 张卡完成，换来四条**只能靠实做才知道**的事实：

1. **`FakeDocs` 必须同时学会绝对根**：根下的绝对路径要等价于相对路径，且「根自身」算存在的目录。
   返工后那 10 条回归清零，本需求已实测（见 t2 卡记录）。
2. **判据口径过窄会漏掉回归**：t2 原有验收只跑 2 个文件，全绿——而 A/B 对照立刻抓到 10 条回归。
   **故本版把「A/B 对照」升为硬判据（FR-10）**，任何「改了共享夹具/根」的卡都必须提供 A/B 证据。
3. **归因需要隔离手段**：本仓多窗口并发，全量失败集合会漂移（实测同一批 15 个文件：
   带改动 35 失败、回退 25 失败；但同一配对连跑 3×3，两侧失败数**逐次相同**）。
   故 FR-10 要求：**同一配置连跑 ≥2 次**，两侧逐条比集合，才能声称「不是本次引入」。
4. **权限模型真的能拦**（FR-5⑤ 的替代机制，实测）：
   `node --permission --allow-fs-read='*' --allow-fs-write=/tmp --allow-fs-write=/private/tmp`
   → 写 `/tmp` 允许；写仓库内路径 **`ERR_ACCESS_DENIED`**；仓库内零残留。
   注意：Node 25 已**不接受**逗号分隔的 `--allow-fs-write=a,b`（会告警并按无效处理），必须重复 flag；
   Node 20 上该开关名为 `--experimental-permission`（版本差异必须写进设计）。

### 码的口径（第一交付，必须冻结成代码）

**码 = 在 `src/**/*.ts` 中作为「独立字符串字面量」（引号紧贴）或「对象键」（`REQBOARD_X:`）出现的
`REQBOARD_X`**，且满足：① 左边界不是 `[A-Za-z0-9_]`（否则 `DSH_REQBOARD_NO_ITEM_RESULT` 的片段会被误当码）；
② 所在行不是注释；③ 所在文件不是 `*prompt*.ts` 或 `domain/prompt/generated/**`（文案不是产生点）；
④ 不是 R7 的 5 个噪声字样。

- **大写码**：上述口径抽出 127 个（实施期实测）。
- **小写码**：只认**两张已存在的登记表**，不猜正则——`domain/errors.ts` 的 `REQBOARD_ERROR_CODES`（16）
  与 `MoveRequirement.ts` 的 `TRANSPORT_CODE_BY_INTERNAL`（9），去重后 23。
  **只测大写码 = 只测了传输层，门禁本体（9 个小写内部码）没测**，故口径必须两侧都覆盖。
- **排除项恰好 5 条**（不是 6）：`REQBOARD_BRIDGE_NOT_READY` 是**注册死码**（无任何产生点），
  但它确实出现在 `src/http/envelope.ts:93` 的状态表里 → 它是**码**、`covered=true`，
  归**上报的缺口**（第一版文档曾要求它进排除项又进豁免，二者互斥，见 D-12）。

## 功能点

- **FR-1: 冻结「错误码」口径并产出带证据的码清单，守卫防漂移**
  在 `tests/` 侧扫描 `src` 产出**大小写两侧**的码清单（大写 + 23 个小写及其传输码映射）+ 逐码首个产生点
  （用「文件 + 行原文」抗行号漂移）；显式列出 5 个噪声字样与排除理由。
  守卫：口径内出现**新码**未进清单 → 红并**给出一条可跑的自助刷新命令**；
  小写→大写映射被改动/漏对 → 红；`unclassified`（刷新写入的临时态）未归零 → 红。
  读数一律**双形态**并报假阴性率。

- **FR-2: 错误码覆盖矩阵——每个可触发码 ≥1 条「触发 → 断码」用例**
  参数化、数据驱动；每条用例**真的触发**该码并断言到码本身（不是断中文文案）。
  目标：R8 的 **25 个真零覆盖**降到 **≤5**。可达性已逐码勘定：4 个 `direct`（几行即可）、
  6 个 `fault`（其中 3 个只需一个假端口）、15 个 `fixture`（约 11 个可复用已有同族夹具换字段）。
  三个高风险项须记账：`NOT_AUTORUN` / `REQ_NOT_FOUND`（工具层不可达）、`AWAITING_MANUAL`（造链成本高）。

- **FR-3: 不可触发码的豁免白名单（棘轮 + 逐条 reason）**
  双向钉死（白名单 ⊆ 未覆盖集合、未覆盖集合 ⊆ 白名单）+ 条目数**只减不增** + `reason`/`plan` 非空
  + `blocker` 命中受控枚举。刷新**只把红变可解，不把红变绿**。

- **FR-4: 红基线分诊——反向子集单列 + 逐条红因 + 只减不增**
  把 68 条拆成 `test-baseline.reverse.txt` 与 `test-baseline.other.txt` 两个**不相交**集合，
  并集恒等于现行基线；`reverse.notes.md` 逐条给红因（受控枚举）与红线内可达性。
  **禁止**用 `baseline:refresh` 把纪律门禁一起洗绿：refresh 只动基线文件，分类文件独立，
  于是「刷新引入了既不在 reverse 也不在 other 的新失败」立刻变红。

- **FR-5: hermetic——测试不写真实工作树（三层，机制已实测）**
  - **⑤-a 真拦（主判据）**：Node 权限模型——vitest worker 进程带
    `--permission --allow-fs-write=<临时目录>`（Node 25 需重复 flag，不接受逗号分隔；
    Node 20 名为 `--experimental-permission`，版本差异在设计中处理）。
    实测：写 `/tmp` 允许、写仓库内路径 `ERR_ACCESS_DENIED`。
  - **⑤-b 契约锚点（快速回归）**：所有 docs 替身的 `workspaceRoot()` 必须是**绝对临时根**，
    且**根下的绝对路径等价于相对路径**（`FakeDocs` 已按此返工，A/B 验证 10 条回归清零）。
  - **⑤-c 端到端对拍（隔离副本）**：在 `git worktree`/clone 里跑全量，前后逐文件内容哈希不变。
  - 一次性点位：`tests/unit/rtm-health.test.ts:16`（`<cwd>/.test-rtm-health`）、
    `tests/capture-hook.test.ts:44`、两个 `plan-footprint-*.test.ts` 对真实树的 `rmSync`。
  - **不得**再用「改写 fs 导出」与「全工作树哈希」两种已被证伪的机制（见边界表）。

- **FR-6: 41 处 `expect(...success).toBe(false)` 升级为错误码断言**
  现在靠中文正则兜底，文案一改就碎；改为断到 `REQBOARD_*` 码（只追加，不删改既有断言）。

- **FR-7: 按矩阵范式补越权 / 并发 / 空输入三类**
  矩阵 = 角色/条件 × 动作 × 断言（码 + 零写入 + 状态不变）；范式照抄
  `tests/seat-authorization.test.ts:71` 的「逐格钉死 + 计数断言防漏格」。

- **FR-8: 反向演练可复跑——临时改坏，判据必须红**
  复用到既有 `scripts/reverse-drill-matrix.mts` 的纪律（文件级备份 + sha256 + 并发写入检测 + 逐字节还原，
  **禁用按路径检出还原**）。证明矩阵「真的在判」，而不是测空气。

- **FR-9: 兼容性——存量、契约、前向三条都不许破（D-9）**
  ① **存量**：既有用例零语义变更（`expect` 删除数 0、`it` 标题改写数 0、基线集合差为空）；
  ② **契约**：口径覆盖双层码契约（大小写两侧 + 映射守卫），不收窄；
  ③ **前向**：守卫报红必给多窗口**可操作的自助修复命令**，刷新显式、留痕、只增不减。

- **FR-10: 回归归因判据——A/B 对照 + 同配置复跑（实施期新增，D-13）**
  任何改动**共享夹具 / 测试根 / 全局配置**的卡，验收必须附 **A/B 对照**证据：
  同一批测试文件在「带改动」与「回退改动」两侧各跑一次，**逐条比失败集合**；

## 验收判据（可证伪）

1. **两个可量读数给改前/改后**：反向 matcher 占比（R5 = 3.82%）、真零覆盖码数（R8 = 25）。
   两者**随附同刻工作树指纹**（HEAD 短哈希 + `git status --porcelain | wc -l`），否则读数不算数。
   读数口径**双形态**并给出假阴性率（R8b = 7）。
2. **反向演练**：临时改坏任一码的断码断言 → 矩阵必须**红**；还原后必须绿（备份 + sha256 复原）。
3. **基线不劣化**：`pnpm baseline:check` 的失败集合**不得比基线差**，且白名单外失败数下降；
   贴两次运行的失败集合差。
4. **FR-1 守卫可失败**：注入一个口径内的新码 → 守卫必红并点名 + 给自助命令；
   排除项恰 5 条且死码在码清单内。
5. **FR-3 棘轮双向可失败**：从白名单删一条 → 红；`frozenCount` 加 1 → 红。
6. **FR-5 三层各给证据**：⑤-a 权限模型下写仓被 `ERR_ACCESS_DENIED` 拒（实测命令与输出）；
   ⑤-b 把 `harness` 根改回 `'.'` → 锚点守卫必红；⑤-c 隔离副本内跑全量后逐文件哈希不变。
7. **零删断言 / 零放宽**：交付 diff 里 `tests/` 的 `expect` 删除数 = 0，基线条目数不增加。
8. **兼容性三条（FR-9）**：`pnpm baseline:check` 集合差为空；矩阵里同时存在大写码与其小写孪生用例；
   给出「新增一个错误码」的完整自助流程并实跑一遍（报红 → 一条命令刷新 → 分级 → 转绿）。
9. **FR-10 归因证据**：改了共享夹具/测试根/全局配置的卡，附 A/B 两侧失败集合逐条比对 +
