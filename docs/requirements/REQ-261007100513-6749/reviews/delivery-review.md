# 评审报告（REQ-261007100513-6749 PM 插件 token 与耗时治理）

> 本需求 7 张父卡各自带「复核」子卡，全部由**独立子代理**执行（只读、逐条对照设计、职责是挑错）。
> 其中 5 张卡的复核结论触发返工；1 张（t3）触发**架构级重构**；1 张（t6）为等价性交叉验证。

## 评审方式

- **链路**：研发（独立子代理，紧凑输入包、**不用 fork**）→ 复核（另一独立子代理，只读）→ 主窗口独立复跑验收命令 → 关卡。
- **对照基准**：`design/` 六份（architecture / interfaces / data-model / backend / test-cases / use-cases）+ requirement.md 的 D-1~D-3 裁定。
- **归属方法**（本仓多窗口共享工作树，必须做）：① 单独跑该套件；② 与仓内留底 `.dsh-data/baseline-test.txt`（10-06）**逐字同号**比对判定存量红；③ 权威差集 `npx tsx scripts/test-baseline.mts --check` 点名真新增；④ 本沙箱**禁止 child_process**，凡报 `Access to this API has been restricted` 记为环境性。
- **可证伪性**：t7 起要求**复核方自挑变异**（实现者自挑的变异不算证据），并把「改坏实现后用例必须变红」写进验收。

## 复核流程本身的三条发现（跨卡）

1. **「测试自己说没问题」不算证据**：t7 实现者自挑的 9 次变异全红，但复核自挑的 4 次里有 **3 次打空** ⇒ 变异测试的有效性取决于**变异选择权在谁手里**。已把「复核方自挑变异」写进流程。
2. **假形状夹具是本轮复发最多的测试缺陷**：`executions[].sessionId` 被两次写成运行期不存在的形状（t5 一次、t7 一次），两次都由**独立复核**发现，实现者自查均未发现。已把「夹具必须照真实数据形状」写进派单硬约束。
3. **设计前提要拿真实数据验，不能只验字段存在**：t5 的 P1 源于我只确认了 `sessionId` 字段存在、没确认它装的是什么；复核用 2202 条实测把它否决。
