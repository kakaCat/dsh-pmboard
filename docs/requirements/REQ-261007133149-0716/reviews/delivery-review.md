## 跨卡发现（都已处置或响亮报出）

1. **计划有一处依赖缺口**：t6 的验收要求 R-1~R-5 五条，但 R-3/R-4/R-5 依赖 t5 的面板契约，
   而计划里 t6 只依赖 t3/t4。处置：先做 t5（t-8afc8a），再回来做 t6 的五条演练。
2. **t3 的验收文本与卡图自相矛盾**（原文本要求「公共层含具体组件取值 0 处」，而该数字由 t4 决定、t4 又依赖 t3）：
   经人裁定（D-7，选「判据先行」）t3 只交判据 + 逐条登记的待归位基线；裁定已落账 D-7 并留痕。
3. **t4 过程事故与教训**（如实记）：偏移量剪贴会因区间重叠把文本接错位、把规则吞进注释；
   分片尾部有悬挂段落头，追加位置错了整批规则失效。两次把工作树改坏，都**退回校验过的基座**
   （判据一 0 差异 + 判据二 7/220 双查）再重跑，最终一版的读数是干净的。
4. **归位动了 CSS 文本的分布，一处结构断言随之下线**：`tests/report-tabs.test.ts` 的 FR-4 用例
   原本按「文本位置切片」断言，归位后 FR-4 的令牌与规则搬进 tabs 分片 → 改成
   「收敛项按全量 CSS 查在场 + 裸值纪律只看 FR-4 段」；同样把残留公共层的 FR-4 令牌块搬进 tabs 分片。
5. **面板契约的封装细节**：`PanelShape` 若带 `key: string`，`satisfies` 的上下文类型会把字面量键
   拓宽成 string（实测：各处 `switch (key)` 不再穷尽、typecheck 红）——最终用
   `PanelShape & { key: 'trunk' }` 把键钉成字面量，理由写在源码里。
