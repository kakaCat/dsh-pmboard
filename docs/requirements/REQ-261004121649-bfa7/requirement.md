# REQ-261004121649-bfa7 · 回退把需求埋了：重做卡递归膨胀且没有撤销入口

> **TL;DR**
> **是什么**：把需求退回上游阶段（回退）会顺手把任务台账炸成一堆重复卡——实测 **17 张 → 73 张**，并且**没有撤销入口**。
> **为什么**：一次回退就能让需求**永远进不了验收**（46 张垃圾 todo 挡在汇总前面），而真正该落的新卡反而没落上。
> **得到什么**：回退只动物化该动的卡（子卡不升格）、带幂等与数量上限（超限整次拒绝）、并支持**一次批量清理**。

```
一次回退的现状
   17 张卡 ──回退──▶ 取消 17 + 物化 56（其中 50 张源自「子卡」）
                              │
                              └─ 新卡一开工又展开子链 ──▶ …·研发·研发（名字递归）
   结果：46 张 todo 挡住汇总 ──▶ 需求永远进不了验收

一次回退的期望
   17 张卡 ──回退──▶ 取消该取消的 + 只物化「顶层父卡」的重做卡（子卡原地复位）
                              ├─ 不自动展开子卡链
                              └─ 幂等 + 数量上限（超限即整次拒绝、不落库）+ 可批量清理
```

## 产品定义

**回退**（把需求退回上游阶段，如实施中发现描述不对 → 退回设计）是给人用的逃生门。它现在会**把任务台账炸成一堆重复的无意义卡片**，且**没有任何撤销入口**——一次回退就足以让一张需求再也推进不到验收。

现状实测（2026-10-03 一次真实操作，需求 REQ-261001203710-0fbf）：

| 指标 | 数值 |
|---|---|
| 回退前任务数 | 17 |
| 回退后任务数 | **73**（其中 `[重做]` 卡 **56** 张） |
| 56 张里源自**原父卡** | 6 |
| 56 张里源自**原子卡** | **50** |
| 名字已递归（`…·研发·研发` 等 ≥2 层后缀） | 16 |
| 已被当父卡并展开新子链 | 10 |
| 结果 | 46 张 todo 挡在 rollup 前 → 需求**永远进不了验收**；当次计划批准要落的两张新卡反而**没落上** |

## 用户与角色

- **窗口 agent**：执行回退的人。回退后需要台账仍然可用，而不是被垃圾卡淹没。
- **人工决策者**：要在看板上清理时，需要「一次清掉误物化的卡」的手段，而不是逐张点。
- **后续维护者**：需要能从台账看出「这次回退动了什么」，而不是只看到一大堆同名卡。

## 边界

**做**（三条）：
1. 回退**只对顶层父卡**物化重做卡；子卡要么原地复位、要么随父卡一起重新展开；
2. 新物化的重做卡**不自动展开子卡链**（是否重走子卡链交给人/计划决定）；
3. 加**幂等 + 数量上限**（超限即响亮失败、不落库），并提供**批量清理/撤销入口**。

**不做**（三条）：
1. 不改「哪些阶段转移算回退」的语义（那是另一件事，已有 RollbackSpec）；
2. 不动 Dive 自动链与自动开跑；
3. 不重写队列存储格式与台账 schema。

## 功能点

- **FR-1: 回退只物化顶层父卡的重做卡，子卡不得变成父卡**
  子卡必须保留子卡身份（`parentId` / `stageKind`），或原地复位为 todo；不得因为被回退就升格成顶层卡。

- **FR-2: 新物化的重做卡不自动展开子卡链**
  当前行为是：新卡一开工就按默认模板再展开一遍子链，于是出现 `…·研发·研发`。期望：物化即终态（或显式标 `stages: []`）。

- **FR-3: 回退物化必须幂等，且有数量上限，超限响亮失败不落库**
  同一 (requirementId, taskId, 回退序号) 只物化一次；单次回退物化数超过阈值（建议 20）时**整次拒绝并报出明细**，而不是先落库再让人发现。

- **FR-4: 提供批量清理/撤销入口，让人能一次清掉误物化的卡**
  现状：只能逐张人工取消（本次需清 53 张）。期望：给定一次回退的标识，能批量把该次物化的卡置为 canceled，并恢复被误伤的父子关系。

## 验收口径（可跑）

1. `npx vitest run tests/rollback-materialize.test.ts -t "只物化顶层"` → 全绿：子卡不升格、`parentId`/`stageKind` 保留；
2. 同一回退重复执行两次 → 第二次物化数为 0（幂等）；
3. 构造一次会物化 > 20 张卡的回退 → **抛错且队列零新增**（响亮失败，不落库）；
4. `npx vitest run tests/rollback-materialize.test.ts -t "批量清理"` → 全绿：清理后该需求任务数回到回退前的量级，且被误伤的父子关系恢复。
