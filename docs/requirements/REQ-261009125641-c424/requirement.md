# Dive 升级为 DriveEngine（参考 goal 通用回合驱动器）

> 状态：需求分析（brainstorming） · 类型：spike · 宣布路径：**Spike**（问题是"能不能分层、代价多大"，产出是答案不是代码）
> 时间盒：**3 天** —— 到期没答完也必须出结论（哪怕结论是"未答完，需要下一轮"）；没有时间盒的 spike 会变成无限期调研。

## TL;DR

- 用户给的机制图，原生实现在 `deepseek-harness/packages/goal/goal-round-driver/src/index.ts`（456 行）；
  pm 侧 `src/application/dive/round-driver.ts`（819 行）是它的**逐条重实现**——图上 13 个环节全部对位（前置/后置双栅栏、stale 让位、准入计数、撤销后重调度、`startsRequestSeries` 一字不差）。
- 升级为 DriveEngine 的**真正价值不是"再抄一遍"**，而是**分层**：把「回合驱动纪律」与「需求流水线业务」拆开，
  让驱动内核零业务依赖（现在二者长在同一个 819 行文件里）；顺手补上原生有、pm 缺的**内容不变式**与**计数权威**。
- 本次 spike 只出答案（SP-1…SP-6 结论 + 目标结构 + 迁移路径）；**实施另立 refactor 需求**，本需求不落代码。

### 为什么不够用（升级动机，可证伪）

1. **纪律与业务长在一起**：`round-driver.ts` 819 行里同时有「预留→认领→准入栅栏」（通用）与「人工门 / 弹框在途 / 预算闸 / 实施阶段自动恢复 / 阶段上限」（需求流水线专属）。通用纪律想被第二条业务复用（或独立单测）**没有接缝**。
2. **两处已知缺口**（上表 ②）：缺纯函数不变式；计数写失败会让**同一回合号重发一次**（不会双计，有 `>= round` 守卫）。
3. **状态迁移未单点**：`disarm`/`terminalBlock` 走 `transitionDive` 纯函数，但 `pauseAborted`（:418）**直接改 `r.dive.phase`**，绕过单一来源——原生侧不存在这种旁路。

## 结论

> 以下为本次 spike 的答案（含置信度与适用边界）；被证伪的假设单列在本节末尾。

### 目标结构（方向级；接口签名属 design 节点）

```
application/drive/          ← 新增：通用回合驱动内核（零业务依赖、零框架依赖）
  内核只回答四件事：什么时候可以起轮 · 预留与认领的相位 · 双重栅栏 · 停下来以后怎么办
  它不知道"需求""阶段""人工门"，这些一律经业务侧注入

application/dive/           ← 收窄为：DriveSource 的第一个实现（需求台账适配器）
  保留：阶段上限 / 人工门 / 弹框在途 / 预算闸 / 归属校验 / 实施阶段自动恢复 / 阶段化提示词渲染
adapters/ReqboardDiveManager.ts ← 不变（订阅持有者）
```

- 结论｜**SP-1**（置信度 高）**：接缝切在「**判定所需的只读事实**」与「**动作出口**」两侧。
  内核必须知道的不超过 6 项：① 当前相位与计数（含上限）② 预留身份（业务主键 + revision + round）
  ③ 是否武装/可驱动 ④ 活体与空闲判据 ⑤ 投递出口 ⑥ 停手/终态出口。**业务专属的 4 个收手点
  （人工门/弹框/预算/自动恢复）不进内核**——它们已经是"构造 attempt 之前"的独立判据，
  由业务侧在起轮前串接（现状即如此，搬动即可，无需新机制）。
  自证：删掉任一业务回调，内核仍能跑完"预留→投递→栅栏→让位"整条链。
- 结论｜**SP-2**（置信度 中）**：**推荐 fail-closed**，理由：原生把计数放在可重放的纯函数 fold 里，
  等价物在本仓成本过高（提示词动态、台账是唯一权威）；而"写失败 → 起轮前闭锁"能一次性消掉
  "同号回合重发"，代价是**一次 I/O 抖动会停手等人**——对抗手段是复用既有 `DriverLatch` +
  `writable` 语义（写回执翻真），不新造机制。**否掉**"改为从产物折叠推导"：那要求产物簿成为
  全序事件源，属另一个量级改造。
- 结论｜**SP-3**（置信度 中）**：可做到**弱不变式**——同 `(需求, round, revision)` 的回合正文指纹
  （内容哈希）在准入时落盘，pre-step 与自检探针比对；**强不变式（原生那种"内容可由纯函数重建"）
  不可达**，因为正文含阶段与快照（`renderDiveRoundText` 依赖 `status`）。能拦：旧消息混入、
  驱动器重复投递同号不同文、历史被篡改；拦不住：**同一 status 下渲染器的语义漂移**（改了文案但哈希
  一致地重算）——这一类只能靠测试钉住。
- 结论｜**SP-4**（置信度 中高）**：**两者都要，且必须显式二选一写在 DriveEngine 的策略位上**，
  不允许隐式默认。原生的 disarm-all 是为了"不继承隐藏自动授权"（加载即假设没有人授权过）；
  现状的自动重武装服务于"基础设施误伤自愈"（生产实测每次重启把需求打成手动）。
  两者不矛盾但**面向不同的授权来源**：建议取「加载不授予自动权 + 对**本插件自己造成的**
  异常停手位提供一次性自愈」，即把重武装的范围从"任何 `disarmed+active`"收窄到
  "driverHealth 的 reason 属于本插件自产类别"。**须人点头**（影响生产行为）。
- 结论｜**SP-5**（置信度 高 · 已实测）**：全仓**只有 1 处**状态机字段直写——
  `round-driver.ts:418` 的 `r.dive.phase = 'paused'`（在 `pauseAborted` 内），而 `transitionDive`
  已有 8 个文件 / 10 处调用点。整改面因此**很小且明确**：把这 1 处改走 `transitionDive`（复用既有
  `pause-runtime` 事件即可，`disarm`/`terminalBlock` 已这么写），`phase`/`activation` 即达成单点写。
  另有一类"数据字段"直写**不属状态机**、建议并入统一写入口而非改纯函数：`roundsInStage`/
  `lastActiveAt`（`round-driver.ts:397-398`）、`driverHealth`/`lastWakeAt`（`wake-heartbeat.ts:197-222`、
  `awaiting-confirm.ts:168-176,241-250`）——它们由多个模块各写各的，是本条真正待收口的面。
- 结论｜**SP-6**（置信度 中）**：**不同源，本期不统一**。三项对比：驱动点（回合驱动 = agent idle；
  job 驱动 = 后台队列）、生命周期（回合驱动随 agent 生命周期；job 有独立 job id 与重试）、
  失败语义（回合驱动 = 让位/退避/熔断；job = 暂停告警等人处置）三项皆不同。
  **再议信号**：若实施链出现"需要在 agent 回合内与模型协作推进多步"的需求，再评估。
- **迁移路径（G2）**：① 抽出内核 + 现有用例转测（行为基线零变化，判据 = 现有 dive 用例集全绿）
  ② Dive 改为第一个 DriveSource（判据 = 同上用例集全绿 + `round-driver.ts` 行数下降）
  ③ 补 SP-2 / SP-3 两处缺口（判据 = 各带一条新用例；后者含一条"停手后可恢复"用例）
  ④ SP-4 策略位落地（判据 = 策略两侧各一条用例 + 人确认）。每阶段的回滚位 = 上一阶段的全绿状态
  （阶段间各自可独立回滚，不做一次性大爆炸）。

### 被证伪 / 被否掉的假设

| 假设 | 结论 | 依据 |
|---|---|---|
| "pm 缺了图上不少环节" | **证伪** | 13 环节全部对位，第 6/7/9/10/12 环节近乎逐字相同 |
| "直接照抄原生即可" | **证伪** | 二者宿主不同（goal 服务 vs 需求台账），分歧①③④是**有意为之**，抄过来会丢掉健康位分离与自愈面 |
| "把计数改成纯函数 fold" | **否掉** | 要求产物簿成为全序事件源，超出本次量级（SP-2） |
| "强内容不变式可复刻" | **否掉** | 正文含动态阶段与快照，不可纯函数重建（SP-3） |

## 失败与并发路径

- **本需求自身失败**：3 天内答不完 → 按时间盒规则出"未答完"结论，**不得**以半成品文档冒充结论；
  SP-x 有任一未答即在结论节显式列出，不写"基本答完"。
- **并发（其它窗口在途）**：本需求**零文件写入**（除本文档），与其它窗口的 262 个在途改动不冲突；
  读数表若与实施时不一致（行数变化）以实施时复算为准，不改结论方向只改数字。
- **实施侧迁移的并发风险（写给下一个需求）**：抽取期间若其它窗口在同一文件上改动，必须先合并再抽，
  禁止"边抽边改语义"；阶段①的判据（现有用例全绿）就是防这条的闸。
- **状态机非法迁移**：本需求不引入状态；SP-5 的整改方向正是"消灭绕过纯函数的直改字段"，
  整改后非法迁移应被 `transitionDive` 拒绝而非静默写入。

## 关键决策与取舍

| 取舍点 | 否掉了什么 | 为什么 |
|---|---|---|
| 立项类型取 spike 而非 refactor | 直接开工改代码 | 问题是"该怎么拆、值不值得"，先要答案；实施另立卡，避免边调研边改 |
| 只答"切在哪"，不写接口 | 预写类/接口签名 | 需求阶段写设计 = 越界（本仓纪律，实测返工）；签名属 design 节点 |
| 保留 pm 的分歧③（health+pause 两档） | 抄原生的单一 `block` 出口 | pm 缺 blocked 相位；且"运行时故障"与"人的手动模式"必须分开，否则重启即打成手动 |
| SP-2 取 fail-closed 而非纯函数 fold | 一次到位的"事件源改造" | 代价量级不符（要求产物簿成为全序事件源），本期取小步 |
| 不统一 job 驱动（SP-6） | 提前统一两套驱动 | 三项驱动语义皆不同，统一是投机抽象（YAGNI） |
