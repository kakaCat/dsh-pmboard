FR-3 不达标仍拦住

优先级 P0 · 状态：草图 · 通道：同一处事实形态判据（hasHumanFact），不另立第二份词表

三种不达标：一律不放行（与今天逐字一致）

场景人的输入系统回应台账
该项没有 agent result 输入框留空 + 勾通过 unverified　回执：v2-19 缺事实——请写你看到的现象 + 证据路径 unverifiedReason: "blank_pass"
该项 result = "PASS"（无观察词） 输入框留空 + 勾通过 unverified　采纳路径不成立（事实形态判据不过） unverifiedReason: "blank_pass"
该项无事实文本 人原样手打 通过 当场拒：人工核对项 v2-19 的结论太薄（"通过"）…（opinion_required） 状态不变（零改动）

状态机（人发起 = 唯一的 passed 来源）

pending ──通过 + 有事实文本 + 人留空──▶ passed  opinionSource=agent     [FR-1]
pending ──通过 + 人自填事实文本──────▶ passed  opinionSource=human     [FR-2]
pending ──通过 + 谁都没写事实────────▶ unverified(blank_pass)          [FR-3]
pending ──通过 + 人自填太薄──────────▶ ✗ 拒（opinion_required）· 台账不变 [FR-3]
unverified ──补写事实后重交──────────▶ passed，清 unverifiedReason
D-2 红线：任何路径下 passed 都由人发起的裁决产生；agent 侧没有把状态改成 passed 的通路。本需求取消的是「重抄」，不是「人工门」。
单点纪律：事实形态判据沿用同一处 hasHumanFact；来源判定、开关读取各只允许一处。畸形 agent 文本（超长 / 纯空白 / 只 emoji / 纯命令无观察词）→ 判不过，落回「要人写」，不崩、不静默通过。
交互路径：1. 人点通过。2. 系统判「该项是否带 agent 事实文本」——判据单点。3. 反馈：合格 → 采纳（FR-1）；不合格 → unverified(blank_pass) 或当场拒绝并点名。
分支：① 人写了但太薄 → 拒绝文案给可照抄样例（不看 agent 有没有写）；② 人写了合格事实 → 以人写的为准，即使 agent 也写了。

开关取值人工项是否吃 agent result 兜底报错文案受影响的路径
（未设）吃（FR-1 采纳路径）与今天一致（仅不达标时出现）本需求新增的两条路径
=0 / =false吃同上同上
=1（非空且非 0/false）不吃 → 落 unverified(blank_pass)逐字退回上线前（含「结论太薄」原文）同上

纪律：只动本需求新增的两条路径

① 开关读取单点：调用方只读一次、把布尔值往下传（与既有 itemResultBindingEnabled 同款式）。② 不动既有 DSH_REQBOARD_NO_ITEM_RESULT 语义。③ 两个开关互不覆盖：一个管「普通项的 result 绑定」，一个管「人工项的代写兜底」。
grep -rn "DSH_REQBOARD_NO_HUMAN_PROXY" src/ 只命中开关判据一处定义；grep -rn "opinionSource" src/ 只命中判据/写入实现一处。
交互路径：1. 设 DSH_REQBOARD_NO_HUMAN_PROXY=1。2. 重跑同一条验收路径（不必回滚版本）。3. 反馈：人工项一律不吃 agent result 兜底，行为与上线前逐字一致。
分支：① 未设该开关 → 断言 passed + opinionSource="agent"（与开关态互斥）；② 取消开关（去掉环境变量）→ 立即恢复代写口径。
