# 需求说明（REQ-261007191737-0eb5）

> 本文档面向：产品、开发、测试、用户——**写给人看，不是写给代码看**。
> 排版纪律：段落不超过 4 行；并列项用列表或表格；图一律 ASCII，禁用 mermaid。

## TL;DR

- **现象**：需求只要有权威原型，验收单就自动多出一条「只能人看」的原型对照项；人点「通过」必须**亲手重抄**一遍现象与证据，只写「通过」两字就被拒。
- **代价**：裁决是整批原子的——一项不合格，本批 10 项**全部零落库**。实测连点 3 次、批批白点。
- **做完得到**：agent 已写下的对照事实**可以直接被人采纳**（人零输入点通过即成立），台账如实标明「agent 代写（人已确认）」。

```
                        提交前就地补问 → 不整批回滚重来（FR-4） · 开关退回今天（FR-5）
```

## 产品定义

一句话：把人工项从「逼人重抄」改成「请人确认」。

- **是什么**：调整验收单里 `needsHuman` 项的裁决口径——该项已带 agent 写下的**事实文本**（现象 / 差异 / 证据路径）时，人点「通过」即采纳该文本，不必再手打一遍。
- **核心价值**：**判断仍由人做，记录不该由人做第二遍**。视觉是否一致只有人能看，但「agent 已经做完的对照」不该被当成不存在，逼人为 agent 的产出补录入。
- **与现状的区别**：现在判的是「人写没写」；改后判的是「文本够不够事实形态」+「人有没有确认」——人仍必须显式点通过，只是不再被逼打字。

### FR-1：人工项采纳 agent 事实文本

**功能描述**：人对已带事实文本的人工项点「通过」，零输入即记 `passed`。

**详细说明**：

- **使用场景**：验收单里的原型对照项（`needsHuman=true`）已由 agent 在 `result` 写清对照结论；人看过真机后只想确认。
- **操作流程**：
  1. agent 提交 `kind=verification`，该人工项带 `result`（含现象词 / 差异 / 证据路径）。
  2. 人在弹框第 1 问选「通过」、第 2 问**留空**提交（看板同理：勾通过、输入框留空）。
  3. 系统取该项 `result` 代写 `opinion`，落 `status=passed`。
- **预期结果**：
  - 该项零输入通过；本批其余项正常落库，不再因为这一项整批回滚。
  - 回执与验收单显示该结论来自 agent 代写（FR-2）。
- **边界条件**：
  - 该项**没有** `result`，或 `result` 不过事实形态判据（无观察词 / 太短）→ 按 FR-3 仍要人写。
  - 人在第 2 问**写了字** → 以人写的为准；人写的自己不合格照样拒（FR-3）。

**验收标准**（可证伪）：

1. 构造 `needsHuman=true` 且 `result="与原型一致；差异：格子尺寸 208×n vs 234px"` 的项 → 零输入点通过 → `status=passed` 且 `opinion` 等于该 `result`。
2. 同一项在 `DSH_REQBOARD_NO_HUMAN_PROXY=1` 下重跑 → 回到 `unverified`（明确取值，回滚读数）。
3. 回归：`npx vitest run tests/accept-sheet-zero-input.test.ts tests/acceptance-criteria.test.ts` 退出码 0。

### FR-2：代写留痕可辨

**功能描述**：代写时台账标来源为 agent 代写（人已确认），看板与验收文档如实渲染。

**详细说明**：

- **使用场景**：事后复盘「这条结论是谁写的」——现状只有 `opinion` 一段文本，两种来源不可分。
- **操作流程**：
  1. FR-1 的采纳路径在写 `opinion` 的同时写来源标记（新增可选字段 `opinionSource`）。
  2. 看板验收单与 `verification.md` 对代写项渲染「agent 代写（人已确认）」标注；人自己写的项不标。
- **预期结果**：
  - 台账里一眼分辨两种来源，不出现「agent 文本冒充人写的观察事实」。
  - 新增字段**可选**：老台账无该字段按「人写 / 未知」渲染，读取路径不报错。
- **边界条件**：
  - 人自填文本的来源取值（记 `human` 或维持不写）在设计阶段定死一处，不得两处判。

**验收标准**（可证伪）：

1. `grep -rn "opinionSource" src/` 只命中**一处**判据/写入实现（判据单点）。
2. FR-1 采纳路径落库后该项 `opinionSource === "agent"`；人自填路径该字段不等于 `"agent"`。
3. 看板渲染用例：含代写项的验收单 HTML 在该项出现「代写」字样（`npx vitest run tests/<看板渲染用例>` 退出码 0）。

### FR-3：不达标仍拦住

**功能描述**：agent 无事实文本 / 文本太薄时不放行，人仍须自己写，不许 agent 置通过。

**详细说明**：

- **使用场景**：本需求只取消「重抄」，**不取消人的判断**——防止被读成「取消人工门」。
- **操作流程**：
  1. 人工项无 `result`，或 `result` 不含观察事实 → 采纳路径不成立。
  2. 人零输入点通过 → 记 `unverified` 且 `unverifiedReason="blank_pass"`（与今天一致），回执说明要补什么。
  3. 人自填太薄（如 `通过`）→ 与今天一致：当场拒绝并给可照抄样例。
- **预期结果**：
  - 任何路径下 `passed` 都由**人发起**的裁决产生；agent 侧没有把状态改成 `passed` 的通路。
  - 不合格**响亮报错**，不静默放行。
- **边界条件**：
  - 事实形态判据**复用同一处**（`hasHumanFact`），不得为代写另写第二份词表。

**验收标准**（可证伪）：

1. `needsHuman=true` 且无 `result` 的项零输入点通过 → `status=unverified`、`unverifiedReason="blank_pass"`。
2. `needsHuman=true` 且 `result="PASS"`（无观察词）→ 零输入点通过仍 `unverified`；人原样手打 `通过` → 报错文本含 `opinion_required`。
3. `grep -c "HUMAN_FACT" src/domain/workflow/AcceptanceSheetSpec.ts` 的命中数与实现一致（词表单点）。

### FR-4：提交前就地补问

**功能描述**：人工项没人写事实时当场补问并给可照抄样例，不再整批回滚重来。

**详细说明**：

- **使用场景**：实测 3 次批批回滚——错误在提交**之后**才报，人不知道自己错在哪，agent 只能反复重弹同一批。
- **操作流程**：
  1. 弹框收集完本批作答、**调用应用层之前**，检出「既无 agent 事实文本、人也没写」的人工项。
  2. 就这些项**就地补问一轮**，题干给出 itemId 与一句可照抄样例；人补写后整批照常落库。
  3. 人未补写 → 本批零落库，回执点名是哪几项、差什么。
- **预期结果**：
  - 人在同一个回合内知道「差什么、怎么补」，不必等整批被拒后猜。
  - 看板通道同理：既有前端点名从「请写你看到的事实」升级为「差什么 + 样例」。
- **边界条件**：
  - **不改 `applyVerdicts` 的整批原子性**（「拒绝 = 台账零改动」是刻意纪律）；预校验只把错误提前。
  - 弹框通道不可用时回落看板（`fallback=board`），与今天一致。

**验收标准**（可证伪）：

1. 弹框路径：本批含「无文本人工项 + 人留空」→ 触发**一轮补问**（而非直接记录），补问题干含该项 itemId 与样例；人补写后整批落 `passed`。
2. 人拒绝补写 → 本批**零落库**：裁决前后 `verification.json` 的 `sheet.items[].status` 逐项不变（读数：零改动）。
3. 回归：`npx vitest run tests/accept-verdicts-snapshot.test.ts` 退出码 0（原子性快照不变）。

### FR-5：一行回滚开关

**功能描述**：`DSH_REQBOARD_NO_HUMAN_PROXY=1` 退回今天行为。

**详细说明**：

- **使用场景**：上线后发现代写口径不合预期时，一行配置退回，不必回滚版本。
- **操作流程**：
  1. 设 `DSH_REQBOARD_NO_HUMAN_PROXY=1`（非空且非 `0`/`false`）。
  2. 重跑同一条验收路径 → 人工项一律不吃 agent `result` 兜底。
- **预期结果**：
  - 开关生效时，行为与本需求上线前**逐字一致**（含报错文案）。
  - 开关只影响本需求新增的两条路径，不动既有 `DSH_REQBOARD_NO_ITEM_RESULT` 语义。
- **边界条件**：
  - 开关读取**单点**（与既有 `itemResultBindingEnabled` 同款式：调用方只读一次、把布尔值往下传）。

**验收标准**（可证伪）：

1. `DSH_REQBOARD_NO_HUMAN_PROXY=1 npx vitest run tests/<本需求用例>`：代写路径断言全部落到旧口径（`unverified`）。
2. 未设该开关时同一用例断言 `passed` + `opinionSource="agent"`（明确取值，二者互斥）。
3. `grep -rn "DSH_REQBOARD_NO_HUMAN_PROXY" src/` 只命中开关判据**一处**定义。

## 失败与并发路径

- **失败路径（判据/渲染故障）**：事实形态判据是纯函数，抛错即**不改台账**并如实报错（不吞成「未复核」）；看板渲染失败不回滚已落库裁决，只降级为无标注。
- **失败路径（畸形 agent 文本）**：`result` 超长 / 纯空白 / 只 emoji / 纯命令无观察词 → 判据判不过，落回「要人写」，不崩、不静默通过。
- **并发与重复**：两处同时裁决同一张验收单 → 沿用既有乐观锁（`status` + `sheet.version` 必须仍是计算时那份），后到者被拒并报 `REQBOARD_STORE_INCONSISTENT`，台账零改动；弹框与看板同时对同一人工项确认，由同一把锁收敛。
- **状态机**：

| 起始状态 | 事件 | 结果 | 非法迁移的响应 |
|---|---|---|---|
| `pending` | 人点通过 + agent 事实文本 + 人留空 | `passed` + `opinionSource="agent"` | — |
| `pending` | 人点通过 + 人自填事实文本 | `passed`（来源按 D-4 口径） | — |
| `pending` | 人点通过 + 谁都没写事实 | `unverified(blank_pass)` | — |
| `pending` | 人点通过 + 人自填太薄 | 拒绝，状态不变 | 报错点名 + 样例，不改台账 |
| `unverified` | 补写事实后重交 | `passed`，清 `unverifiedReason` | — |
| `failed` | 重新裁决 | 按新裁决覆盖 | — |

- **写路径**：`opinion`、`opinionSource`、`status` 在同一次 `mutate` 内写，写失败整体回滚（不留「状态已通过、来源缺失」的半成品）；`verification.md` 回填失败不阻断裁决落库。

## 边界（不做什么）

- **不取消人工门**：`passed` 必须由人发起的裁决产生；agent 侧无自动通过通路（FR-3 的验收标准就是这条的探针）。
- **不做视觉自动判定**：不做截图比对 / 像素 diff；「是否一致」永远由人看。
- **不改原型对照项的生成条件**：需求有权威原型就仍自动出现这条 `needsHuman` 项。
- **不改 `applyVerdicts` 整批原子性**：FR-4 用「提交前补问」替代「半批落库」。
- **不改 `hasHumanFact` 词表松紧**：本轮改的是「谁写的事实算数」，不是「什么算事实」；改词表需台账数据支撑，属另一条需求。
- **不回填存量验收单**：已落库的 `unverified` 与旧 `opinion` 保持原样。
- **不新增第二份判据**：事实形态判据、来源判定、开关读取各只允许一处。

## 非功能需求

- **向后兼容**：新增字段可选、只增不改；老台账 / 老验收单读取路径不变。
- **判据单点**：事实形态判据沿用 `hasHumanFact`；来源判定、开关读取各一处。
- **可回归**：FR-1~FR-3 各至少一个单元用例；整体回归用一张含「有事实文本人工项 / 无文本人工项 / 普通项」的验收单跑通。
- **可回滚**：`DSH_REQBOARD_NO_HUMAN_PROXY=1` 逐字退回今天行为（与 `DSH_REQBOARD_NO_ITEM_RESULT` 同款式）。

## 验收标准（整体）

1. 造一张含 `needsHuman` 项的验收单，该项带事实文本 → 该项零输入点通过 → `passed` 且 `opinionSource="agent"`。
2. 同单另一 `needsHuman` 项无 `result` → 零输入点通过 → `unverified(blank_pass)`，回执说明补什么。
3. 人对无事实文本的人工项原样手打 `通过` → **当场被拒**且报错含 `opinion_required` 与该项 id。
4. 本批含待补人工项时 → 提交前就地补问（含 itemId + 样例）；人补写后整批落库，人未补写则**台账零改动**。
5. `DSH_REQBOARD_NO_HUMAN_PROXY=1` 下重跑第 1 条 → 回到 `unverified`（开关逐字回旧）。
