# REQ-261002105242-a3fb 用例设计 · 人要回看时，一步就能看到 `serves: FR-1, FR-2, FR-3, FR-4, FR-5`

> 本需求只有一个真实动机：**归档之后想回看**。三个用例分别覆盖「怎么看」「换个视图怎么看」「别再被骗着点」。

## 角色与前置 `serves: FR-1, FR-2`

| 项 | 内容 |
|----|------|
| 主要角色 | 需求方 / 看板使用者（想看"当时怎么拆的"） |
| 次要角色 | 窗口 agent（本需求不新增任何面向 agent 的接口；`reqboard_*` 工具面零变化） |
| 前置条件 | 看板已加载 `state`（含终态需求与全量任务）；至少一条 `status ∈ {archived, canceled}` 的需求 |
| 数据前提 | `docs/requirements/<REQ>/queue.json` 仍在（归档不删），因此详情页的 DAG 与任务表**有内容可画** |
| 非前置 | 不需要重启、不需要重新登记产物、不需要迁移数据 |

## UC-1 回看已归档需求的 DAG（主用例） `serves: FR-1, FR-2, FR-5`

```
人：打开看板（泳道视图，默认）
  |
  v
看板底部：🗄 已归档 21  ·  点击展开
  |
  | 展开
  v
REQ-261001213924-1441 · 修复唤醒链… · 39/39
  |
  | 点击条目（data-action="open-req"）
  v
需求详情（只读）
  ├─ 头：状态胶囊「归档」、8 态进度点全绿
  ├─ 操作条：**不渲染**（没有可点的动作）
  └─ 执行 Tab：统计卡（总任务 39 / 已完成 39）+ DAG 画布 + 任务表 39 行
```

| 步骤 | 系统行为 | 判据 |
|------|---------|------|
| 1 | 泳道只渲染进行中需求；归档/取消需求进底部归档条 | A1-2：归档 id 出现在归档条段、不出现在泳道段 |
| 2 | 归档条默认折叠，展开后逐条列出（按最近更新降序） | A1-1：`<details>` 无 `open`；A1-3：超限提示 |
| 3 | 点条目 → 复用既有 `open-req` 委托 → `mode = { kind:'req', reqId }` | `interfaces.md` 第 6 节（零新事件） |
| 4 | 详情页照常装配：`buildReqDetail(req, state.tasks.filter(requirementId === req.id))` | A2：含 `dsh-pm-dag-panel` 与任务行 |
| 5 | 终态不渲染操作条 | A3：五种动作钩子一个都没有 |
| 6 | 任务计数与详情统计同源 | A6-④：`totalCount` = 真实任务数 |

**后置**：用户看到与归档前**同一份**数据渲染的同一张 DAG（不是快照、不是副本）。
**失败模式**：若某需求 `queue.json` 为空（从未真拆分过），详情照常打开并显示「暂无任务」空态——**不报错、不隐藏 Tab**（诚实空态）。

## UC-2 在列表视图里看已完成/已归档 `serves: FR-3`

| 步骤 | 系统行为 | 判据 |
|------|---------|------|
| 1 | 切到「列表」视图 | 表格按 `active → finished` 分组拼接，进行中永远在前 |
| 2 | 滚到「已完成 / 已归档 N」组 | 该组含 `done` **与** `archived` / `canceled` 行 |
| 3 | 归档行 | 状态列「归档」，`is-archived` 置灰（既有样式），操作列为空（`cardActions` 对终态本就返回 `''`） |
| 4 | 排序 / 分页 | 沿用既有比较器与每页条数；终态行参与同一次排序，**不再被上游投影吃掉** |

**与归档条的分工**：泳道视图看"入口"，列表视图看"全表"；同一视图不重复给两个入口（列表视图不追加归档条）。
**修前对照**：A4 在修前必红——`finished` 分组实际只剩 `done`，archived 永远进不来。

## UC-3 不再遇到点了必失败的归档按钮 `serves: FR-4`

| 步骤 | 改造前 | 改造后 |
|------|--------|--------|
| 打开一条 legacy `done` + 材料已备的需求详情 | 操作条给「归档」按钮（`archive-req`） | 无操作条 |
| 点它 | `POST /req/archive` 404 → `window.alert` 报错 | 点不到（按钮不存在） |
| 归档 Tab 的提示 | 「请在详情头『本阶段操作』条点『归档』」——把人指向不存在的端点 | 陈述事实：历史遗留 `done` 由窗口 agent 走 `reqboard_submit(kind=archive)` 补齐材料 |
| 代码面 | `api.archiveReq` + `case 'archive-req'` + 渲染分支三处残留 | 三处全部删除（A5） |

**语义纪律**：删除入口**不新增**状态机边——`done` 是 legacy 死态（`RequirementStatus.ts:67` `done: []`），
不因"少了个按钮"就给它开新出口；归档的正路始终是 `accepting → archived`（REQ-9f4a44 自动完成）。

## 异常与空态 `serves: FR-1, FR-2`

| 场景 | 期望行为 |
|------|---------|
| 没有任何终态需求 | 归档条不渲染（返回 `''`），页面与改造前逐字节无关差异之外完全一致 |
| 终态需求 > 100 条 | 只渲染前 100 条 + 「另有 N 条未显示」（不静默截断） |
| 归档需求的任务为 0 | 详情打开，执行 Tab 显示既有「暂无任务」空态 |
| 陈旧深链（需求 id 不在 state） | 走 `board-mount` 既有未命中路径（不新增错误码） |
| state 来自旧版服务端 | 只依赖 `status`/`title`/`updatedAt`/任务计数，旧字段缺失不致命 |
| 归档条与泳道同时为空 | 泳道各自的「暂无需求」空态照常；归档条不出现空壳 |

## 非目标 `serves: FR-2, FR-4`

| 非目标 | 为什么不做 |
|--------|-----------|
| 独立「归档」页签 / 第三个视图 | 动视图框架（切换器、分页、焦点、深链全要重做），属重档；归档条折叠态已够用 |
| 归档条分页 / 搜索 / 按分类过滤 | 条目数受 `ARCHIVED_CHIPS_MAX` 约束；真到需要时另立需求（避免本轮范围膨胀） |
| 归档快照落盘 | 直接违反「数据本来就在」的前提，且会制造两份真相 |
| `canceled → archived` 的人工入口 | 状态机允许但全站无 UI（既有缺口，非本需求引入）；本轮不新增后端或前端路径 |
| 会话节点面板默认节点行为 | 归档会话默认显示归档材料是现状且可用（点「实施」节点仍能看 DAG）；本需求只补看板侧入口 |
| 复活 `POST /req/archive` | 归档已由验收通过自动完成（REQ-9f4a44），复活等于开倒车 |
| 归档需求详情里"能不能改" | 终态就是只读；要改先由人走状态机（`canceled → draft` 等既有边），不在本需求 |
