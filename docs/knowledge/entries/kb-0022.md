## 结论
DSH 的插槽机制对**非 chain** 席位是这样处理的：某个占用者只要在渲染时抛过一次异常，该条目就被**退役**（abdicate），席位从此渲染成一块空白（`div[data-slot-error]`）——**界面上看不出任何报错**，用户只能看到「控件不见了」。

因此「控件点一下就消失」这类反馈，第一反应不该是猜谁顶替了席位，而应判定：**是这个席位自己的组件崩了**。

判别归属的关键三分法：
- `Slots.listSubTree` 里该席位的 `occupants[].registrant` 是谁（本仓 = `dsh-pmboard/client`；DSH 自带 = `mf`）；
- `active` 是不是 `false`（单条目席位只有"崩溃退役"这一种解释）；
- 崩溃原文指向的组件，是哪个包的。

2026-10-04 的实例：会话编辑器模型选择器一点开就空白消失。`conversation.input.model` 唯一占用者是 DSH 自带的 `ui-model-selection`，它渲染菜单时要用 `primitives.MenuGroup`，而安装包里的 `ui-primitives` 没有该导出 → `undefined` → React `#130` → 席位退役。**与本仓插件无关**。
第二轮取证（用户反馈 `/model` 也不好使后）查明：安装版 `ui-primitives` 与该机 checkout 的本地构建**逐字节相同**、且带**官方两版都没有**的本地新增符号（`IconBellOutlineRegular`）——即**本机手工把单个本地构建塞进了 `app.asar`**，与官方新版 `ui-model-selection` 混装。修复：**用官方安装包重装/更新**；要改客户端请整包重建，不要部分覆盖。

## 适用条件
- 用户报「某控件点一下就没了 / 消失了 / 变空白」；
- 或 `cordis_inspect_query(client, Slots, listSubTree, {root:'<席位>'})` 的 `occupants[].active === false`。

## 三步判别法（先判归属，再谈修复）
1. **看席位**：`Slots.listSubTree(root='<席位键>')` → 记 `occupants[].registrant` 与 `active`。
   `active:false` 且单条目 = 已退役（崩过）；`registrant` 指认归属。
2. **取原文**：复现一次，在控制台找 `slot entry crashed in '<席位>': <error>` 与其堆栈（DSH 的 `SlotErrorBoundary.componentDidCatch` 打的）。
   React `#130` = 元素类型为 `undefined`（典型：某组件某个 API/导出在运行时不存在）。
3. **对标安装**：怀疑"装歪了"时，从 `app.asar` 提取使用方与提供方所在文件，和 npm 发布版逐符号对标：
   `node <需求目录>/evidence/extract-asar.mjs --local <本机 checkout 里同名文件的构建产物>`；输出三段：
   ① 使用方要、安装版没有 = 缺符号；② 发布版有 = 安装自相矛盾；③ **官方两版都没有、安装版却有的符号 = 被本地构建覆盖**（`--local` 还会做逐字节对照）。
   本实例：安装版缺 `MenuGroup`，发布版 rc.2 有 7 处，且安装版带官方没有的 `IconBellOutlineRegular` → 本地补丁坐实。

## 证据
- 缺陷报告（含全部命令与哈希）：`docs/requirements/REQ-261004095621-c167/evidence/dsh-model-seat-crash.md`
- 关键哈希：安装版 `ui-primitives/lib/index.js` sha256 `74d730cf…`（缺符号）；发布版 rc.2 `6b551f00…`（有符号）
- 同款自伤实例：本仓知识库侧栏图标曾返回裸对象元素 → 同样被退役（`pmboard-knowledge` 曾 `active:false`）→ 已改 `createElement` 并加 `$$typeof` 断言（`tests/kb-client-page.test.ts`）

## 失效条件
DSH 插槽机制不再"崩溃即退役"（改为保留错误占位或自动重试），或本仓不再注册任何席位时。
