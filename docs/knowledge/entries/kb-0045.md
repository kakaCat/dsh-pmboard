## 结论
写盘根判定重定：写入的根由「这条需求记录自己声明的 workspaceRoot」决定（按需求 id 定位记录），进程共享根降级为缓存——写前校正，只有声明根不可用或校正失效才拒绝；立项两条路径的守卫前置到建档之前，多窗口并行不再产生「记录已建却报立项失败」的假失败，也不再出现「计划已批准但任务卡没落库」。
