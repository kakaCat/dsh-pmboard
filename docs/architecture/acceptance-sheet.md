# 验收单机制（L2 领域篇）

> **TL;DR**：验收单由 `reqboard_submit(kind=verification)` 那一刻**由运行中的代码**生成，逐项列出
> 「这张卡/这条需求要确认什么」。它有三条硬不变量——**只收顶层父卡**、**编号连续无空洞**、
> **需求级项标题按缺口类型区分**；另有六类**系统项**把"人看不见的缺口"变成可见项（不阻断提交）。
> 两条裁决通道（看板 / 会话弹框）同口径：**通过也必须填实际结果**。

## 一张验收单长什么样

```
submit(kind=verification)
        │
        ├─ ① 任务项：队列任务里**只收顶层父卡**（parentId === undefined）
        │     └─ 子卡的验收由父卡项覆盖（同一交付不重复占验收位）
        ├─ ② 需求级项：交付结论可复核（证据齐全 / 与设计一致 / 无范围蔓延）
        └─ ③ 系统项（有则追加，全部 pending、全部不阻断提交）
              孤儿用例 · 不可照着验 · E2E 覆盖 · 三方一致性 · 锚点失效 · FR 追溯断链
                        │
                        ▼
        编号一次性连续分配：v<version>-1 … v<version>-N
        （顺序锁定：任务项 → 需求级 → 孤儿 → 不可照验 → E2E → 三方一致性 → 锚点失效 → 追溯断链）
```

## 三条硬不变量（改坏了会被测试当场抓住）

| 不变量 | 为什么 | 守卫 |
|---|---|---|
| **只收顶层父卡** | 否则一个 6 父 + 23 子的交付会产出 29 个任务项，同一交付被重复验收 | 投影单点 `toSheetTasks` 必须**透传 `parentId`**；domain 侧 `buildSheet` 再过滤一次（双保险）。测试：`tests/sheet-projection.test.ts`（删掉透传即变红） |
| **编号连续 `v<ver>-1..N`** | 编号是人对验收项的引用键；跳号（如 `v1-7 → v1-9`）让人以为丢项 | `buildSheet` 先组装草稿再一次性分配编号；不再使用 `taskCount+N` 预留位。测试：`tests/sheet-items-format.test.ts` |
| **需求级项标题按缺口类型区分** | 三行同名「需求级验收」时，人分不清哪行在说什么 | 标题单点 `requirementItemTitle(criterion, gapKind)`，**三处消费点共用**（渲染 / 裁决后回填 / 弹框 header）。测试：同上（标题去重后数量 === 项数） |

## 六类系统项（缺口可见化）

| 系统项 | 触发条件 | `gapKind` | 阻断提交？ | 通过时 |
|---|---|---|---|---|
| 孤儿用例 | 设计点名、文件头未声明覆盖的测试文件 | `orphan` | 否 | 须写处置方式 |
| 不可照着验 | 验收项没写「怎么验」（历史/直种数据） | — | 否 | 须有人看过并决定 |
| E2E 覆盖 | 需求文档有测试策略表且声明无 E2E | 缺口时 `e2e` | 否 | 缺口项通过须写理由 |
| 三方一致性 | 做什么 × 怎么做 × 实际做了什么对不上 | `consistency` | 否 | 须写处置方式 |
| **锚点失效** | 验收标准引用的 `tests/*.{test,spec}.*` **在工作区不存在**（护栏：连 `tests/` 目录都没有时整段跳过） | `consistency` | 否 | 须写处置方式 |
| FR 追溯断链 | `rtm-accepting.yml` 里某 FR 的 `fr_to_tests` 为空 | `traceability` | 否 | 须补标注或说明 |

> 设计原则：**"靠人记得"不算机制**。缺口必须成为验收面上可见的一项，但不阻断流程——是否放行由人裁决。

## 两条通道与「通过必须填实际结果」

| 通道 | 入口 | 意见/实际结果 | 备注 |
|---|---|---|---|
| 看板 | 需求 → 验收页逐项勾选 | **必填**（域门强制）；前端留空会被当场点名，不再把原始 400 甩给用户 | 输入框提示为「通过填实际结果 / 不通过填意见（均必填）」 |
| 会话弹框 | `reqboard_accept_sheet` | 同上；但本机弹框是「选项 **或** 自定义输入」二选一——选了点选项拿不到 custom，故通过时写入显式兜底文案「未附实际结果…待补复核」 | 兜底文案如实标注"没附结果"，不伪装成已复核 |

**最终归档**：所有项裁决完（或人显式覆盖）后，人点「验收通过并归档」——agent 不能自行归档。

## 变更须知（改这些地方会连带破坏什么）

- **动 `SubmitVerification` 的任务投影** → 必须保持 `parentId` 透传，否则 domain 过滤变死代码（历史事故）。
- **动 `buildSheet` 的项顺序或编号** → 同步更新 `tests/sheet-items-format.test.ts` 的顺序断言；编号是读侧**不透明键**，存量单据不回填。
- **新增缺口类系统项** → 复用既有 `gapKind` 枚举值并用 criterion 前缀区分标题，别新增 protocol 枚举（要迁移评审）。
- **改动验收项文案** → 同步 `requirementItemTitle` 的前缀常量，否则标题会退化回同名。
