# 活卡口径单点与六类「假绿」（L2 领域篇）

> **TL;DR**：**「已取消的卡不该出现在视图与统计里」这件事，判据全仓只有一个定义**——
> `src/domain/status/Predicates.ts` 的 `live*` 家族（`isLiveTask` / `liveTasksOf` / `liveCountOf` /
> `liveLayers` / `liveReadyTasks` / `isDependencySatisfied` / `splitDependencyEdges` / `isReadyTask` /
> `layerInputOf`）。真正难的不是"过滤掉取消卡"，而是**六类不会报错的退化**：
> 登记口径（没登记也算交）、字段搬运（写了落不了盘）、渲染通道（文案扫描抓不到的泄漏）、
> 快照陈旧（逐字读的旁路数据）、读侧判死（派生值陈旧把整队列判成 0 张）、自相矛盾（重算值与未剪的边）。
> 每一类都给「怎么发现 + 怎么锁」。来源：REQ-261005193546-1b1a（13 张卡 / 14 条逆验证矩阵）。

## 1. 为什么必须是「单点」

同一条口径曾在本仓有**四份实现、两种行为**：`QueryDag` 与 `QueryDocs` 各自手写过滤、`QueryStageDetail`
漏了、`syncRTMYaml` 那条链路也漏了。后果不是"显示不完美"，而是**同一份台账在不同页面给出不同的数**
（132 vs 106）——人看到两个数，谁也不知道哪个是真的。

单点落点选**既有模块**而非新建：`domain/status/Predicates.ts`（`isCanceled` 就在里面）。
`domain` 层不许 import `shared`，故入参一律结构化 `{ status: string }` + 泛型保类型。

**依赖边语义（同一条口径的另一半）**：活卡的 `dependsOn` 指向已取消卡时，该边按**已满足**处理
（`isDependencySatisfied`：`undefined` 悬空 / `done` / `canceled` = 满足）。
不这么做的后果是**活卡被永久卡死**：已取消的卡永远不会完成，把它当"未满足"就等于给下游焊死。

## 2. 消费点清单（改一处不够，漏一处等于开后门）

| 面 | 收敛落点 | 本次修掉的形态 |
|---|---|---|
| 阶段详情（含看板「DAG 层级」） | **基类 `assemble()` 一次收敛**（8 个 body 全覆盖） | `QueryStageDetail` 曾经完全没过滤 |
| 依赖图 + 层号 | `queryDag` 内喂活卡；层号由 `liveLayers` **现算** | 曾把全量喂 `buildDagNodes`，且层号转发落盘旧值 |
| API 边界 | `handleState` 一处（tasks / ready / 摘要计数 / 会话面板） | 甘特、DAG 画布、卡面计数都吃这份响应 |
| 客户端 | `toCard` 分母兜底；`topoLevels` **剪边落进函数内部** | `topoLevels` 曾把不在集合里的前置当 `lv=0` 计入 max（幽灵前置 ⇒ 活卡凭空多一层） |
| RTM（覆盖度分母） | **两个公开入口**（`syncRTMYaml` + `syncRTMYamlWithSnapshot`） | http 三条路由直调后者，只接前者会漏三条路径 |
| 其他投影 | 文档面板 / 报表 / 状态面 / 验收单 / 追溯 / 验收文档 / 回填 | 各自手写 filter |

## 3. 六类「假绿」（本仓实测，每类都真的发生过）

| # | 退化 | 为什么测试抓不到 | 锁法（本次实证） |
|---|---|---|---|
| 1 | **登记口径**：文件在盘上就算"交了" | 产物自动发现会把落盘骨架补登成产物 ⇒ 只落骨架、人一个字没填也全绿 | 存在门**只认显式登记**（`autoDiscovered !== true`）；并修掉配套死结（自动发现条目被显式登记时就地升级） |
| 2 | **字段搬运**：新字段被调用方**白名单静默丢弃** | 三个批量取消点是纯函数返回整卡副本，调用方只拷 `status/revisions/updatedAt` ⇒ 代码写了、库里没有、测试还过 | 三处白名单逐键补全 + 每条各一条端到端断言（删 3 键 → 必红）；并**穷尽排查**确认全仓仅此三处 |
| 3 | **渲染通道**：泄漏不以关键字形式出现 | 追溯链把取消卡产物渲染成「任务卡（t-gNNN）」节点，标签里没有 `canceled`/`已取消` ⇒ 文案扫描永远绿 | 断言"**渲染条数**"与"**产物投影条数**"（t8 用例 17 → 22 条）；逆验证证明：换回不过滤 → 新增 5 条必红而既有 17 条全绿 |
| 4 | **快照陈旧**：旁路数据逐字读 | 追溯面板逐字读 `rtm-*.yml`，回退晚于最后一次 RTM 时会显示取消卡节点 | 分两形态断言（从没触发 → 0 行；陈旧快照 → 如实声明 + 只断"不泄漏进其余面"）；**不回填不重写**，下次触发即自愈 |
| 5 | **读侧判死**：陈旧派生值把整队列判成 0 张 | 校验失败 ⇒ `return undefined` ⇒ 上层摊成 `[]` ⇒ **看板空白**（存量只读需求被打爆） | **读宽容 / 写严格**：读路径降级为告警 + 继续返回（派生值内存重算，**一个字节不写盘**）；写路径照旧 fail-closed |
| 6 | **自相矛盾**：重算值与未剪的边打架 | 层号按活卡压实成 0，但 `dependsOn` 仍指向已取消卡 ⇒ 被自己的 V-4 判红（侧信道噪声，容易当成"正常告警"忽略） | 重算时**连同剪边**（`dependsOn` 只留指向活卡的边）；探针对照：磁盘视图 1 条 V-4（陈旧可见）/ 重算后视图 0 条（自洽） |

## 4. 两类问题要分开处置（第 5 类的口径）

**校验的目的是拦住「写坏」，不是让「派生值陈旧」把存量需求判成没有任务。**

| 校验项 | 性质 | 处置 |
|---|---|---|
| **漏就绪**（`ready[]` 少了本该就绪的卡） | 可自愈的**陈旧派生值** | 降为 warning，**不拦**（下次写路径自然归一） |
| **假就绪**（没就绪却被标 ready） | **真写坏** | 仍是 issue，`save` 照旧拦死 |
| 非对象根 / 任务条目非对象 | 会打崩下游（`structuredClone(null)`） | 仍按不可用处理（**"读成 0 张"可接受，"读成崩溃"不可接受**） |

## 5. 防漂移网（单点会被人无意破坏）

- **基线清单**：`tests/fixtures/canceled-literal-baseline.json`（39 条 / 25 文件），每条带 reason 与行原文；
- **双向断言**：`hits ⊆ baseline`（**新增即红**）**且** `baseline ⊆ hits ∪ collected`（**删条目即红**）。
  单向 `⊆` 会让"删条目"这条逆验证**永远绿**——这是实测过的坑；
- **不含字面量的退化也要拦**：把复用改回手写 `doneIds.has(dep)` **不含任何 canceled 字面量**，
  故对四处就绪实现额外禁"白名单外的 `.has(`"与"`status` 比较 `'done'`"；
- **范围自检**：清单文件必须读到内容且含 `status` 字样（路径写错即红，防假绿）；
- **不挂进本就红的用例**（`layer-boundary` 当前基线即红）——挂进去等于把新网埋在已知失败里。

## 6. 已知边界（如实声明，不是"应该没问题"）

1. **追溯面板逐字读 RTM 快照**：回退晚于最后一次 RTM 时会显示取消卡节点；不回填、不重写，**下次触发 RTM 即自愈**。
2. **落盘 `layer` 与 `liveLayers` 允许不一致**（刻意差异）：落盘值是历史派生值，读路径一律现算。
3. **token 读数保留全量**：它衡量**实际消耗**（审计口径），不是"该完成的卡"的分母；剔除会低报真实消耗。
4. **`dag-view` 的 ready 推导回落**仍是旧口径（`ready` 键缺失时，唯一前置已取消的活卡不显示绿点）。

## 7. 一条命令复现全部逆验证

```bash
npx tsx scripts/reverse-drill-matrix.mts --group canceled   # 14 条：真改坏 → 必红 → 逐字节还原 + sha256 核对
npx tsx scripts/reverse-drill-matrix.mts --group canceled --json
npx vitest run tests/canceled-reverse-drill-coverage.test.ts   # 结构断言：条目数 14 / target 恰 9 文件 / 无 git checkout 还原
```

14 条里 **12 条是行为断言**、**2 条是源码锚点**（行为等价、只有锚点会红）——
**引用时不得把源码锚点当成"行为断言守住了收敛点"**。
