# 运行设置与存储后端切换（L2 领域篇）

> **TL;DR**：看板「⚙ 设置」把三件事从代码里搬到了界面上——**每个需求阶段还能自动跑多少回合**、
> **台账数据存文件还是存 SQLite 库**、**这台机器上发生过什么**。三条硬口径值得先记住：
> ① 上限的权威读取口是**同步内存快照**（设置文件 > 插件配置 > 环境变量 > 内置默认），**改小不掐断在跑的那一轮**；
> ② 换存储后端**必须过人工确认门**，票据**一次性**且**否定作答不可消费**（两道防线，删任一道对应用例必红）；
> ③ 迁移**先备份、再建库、校验不过整个作废**，源分片目录全程只读。

**来源**：REQ-261004103330-005f（2026-10-04，15 张卡 + 两轮返工）。

## 一、上限配置链（「节点执行次数上限」）

| 层 | 作用 | 落点 |
|---|---|---|
| 内置默认 | 代码里的值，**不写进设置文件** | `src/application/dive/stage-configs.ts` 的 `STAGE_CONFIGS` |
| 环境变量 | 运维覆盖 | `parseStageRoundsEnv` |
| 插件配置 | 装配期传入 | `src/plugin-config.ts` |
| **设置文件** | 人在看板上改的值（惰性创建） | `~/.dsh/dsh-reqboard-settings.json` |

**权威读取口只有一处**：`src/application/dive/round-state.ts` 的 `roundLimitFor()`——**同步**读模块级内存快照。
为什么必须同步：判定发生在 mutate 临界区里，插不进 `await`。装配期用三路刷新灌快照：
① 启动加载 ② `PATCH /settings` 成功后广播 ③ 文件 mtime 轮询（覆盖"人手改文件"）。

**三条容易踩的口径**：

1. **默认值必须留在代码里**，不能抄进设置文件——否则日后调默认值，用户拿到的还是被抄下来的旧值（默认值冻结）。
2. **改小不掐断在跑的那一轮**：下调只影响**下一个判定点**，绝不中断已开始的回合（有断言撑着）。
3. **内置默认下限 5**（人裁定 2026-10-04）：`1` 会被读成"这个阶段只能跑一轮"；四个不自动跑的阶段
   （立项/已完成/已归档/已取消）抬到 5 只改表里的值，**不改变行为**（它们 `autoExecute: false`）。
   守卫：`tests/stage-defaults-floor.test.ts`。

## 二、存储后端切换与人工确认门

**切换只发生在装配期**：绝不半途换存储实现（做一半会丢写）。所以开关的语义是"写设置文件 + 重启生效"。

**唯一的合法路径**：`POST /settings/storage/request` 取票（**同时推出正式确认框**）→ 人作答 →
`POST /settings/storage/switch` 带票执行。票据一次性、过期即拒、重放拒绝、**否定作答不可消费**。

**两道防线（同一纪律的两层，不许只剩一道）**：

| 层 | 判据 | 位置 |
|---|---|---|
| 源头 | `consume()` 遇 `confirmed !== true` → `denied`，**不消费、不置位** | `src/adapters/PendingConfirmRegistry.ts` |
| 路由 | `consumed.confirmed !== true` → 403，不写任何文件 | `src/http/routers/settings.ts` |

反向演练实测：删掉源头那道 → 源头两条用例必红、**路由层 34 条仍全绿**（证明两层各自独立）。

**两个体验口径**（都是实测逼出来的）：
- **面板不是"那个同意"**：真正的同意在作答通道；若把落章挪进路由让面板"点一下即生效"，
  这个门就可被任何能打接口的人伪造。
- **切到"当前已在用"的后端 → 400 且不烧票据**：这条判断必须放在消费票据**之前**，
  否则一次"没有可做之事"的请求会把合法票据烧掉。

## 三、一次性迁移（八步）

脚本 `scripts/migrate-ledger-to-sqlite.ts`（退出码 `0` 成功 / `2` 预检不过 / `3` 校验不过 / `4` IO 失败）：

```
① 预检（含陈旧库检测） → ② 备份源分片目录 → ③ 旧库先备份再重建 → ④ 建暂存库
→ ⑤ 单事务导入 → ⑥ 条数/集合/抽样逐字段校验 → ⑦ 仅通过且显式要求才写设置 → ⑧ 暂存库顶上目标库
```

**为什么用「暂存库 + 顶上」而不是"事务内校验再回滚"**：端口 `replaceAll` 的事务在返回时**已提交**、
没暴露"提交前回调"，脚本**无法在事务内校验**；暂存库让校验作用在"**将要成为目标库的那份字节**"上，
失败时目标库**从头到尾没被碰过**，还少一类"回滚本身失败"的风险。

**两条纪律**：源分片目录**全程只读**（结构保证：全文唯一的写调用作用在暂存库上）；`--dry-run` 承诺
"不写任何文件"，**档案也算写盘**，故它连系统记录事件都不写。

**留痕**：迁移结束（成功或失败）写一条 `migration` 事件。**修法选在最外层包一层**——脚本内部有 8 处
返回路径，逐处补写必然漏一处。

## 四、系统记录（事实档案）

`~/.dsh/dsh-reqboard-system.json`：**启动时自动创建**（幂等，已存在只追加不覆盖），记录
路径档案 / 后端使用史 / 迁移与回滚 / 升级事件 / 丢事件计数 / 插件版本与库版本。

- **路径档案每次启动刷新**（否则数据搬家后档案里仍是旧路径——那屏就在骗人）；写失败降级不阻断启动。
- **档案损坏不 500**：返回 `200 { ok:false, invalid:true, ... }` 并红字呈现，其余屏不受影响，**不自动重建**。
- **两个丢事件计数分开展示、永不相加**：进程内 = "现在还在丢"，已落盘 = 历史累计。
- **版本一致性**：`compat` 不一致时给「重建库」指引并写明**不得硬读旧表**。
- **陈旧库**：库条数少于分片 → 红字「库已陈旧：重启前请重跑迁移」，**页面不提供任何合并入口**。

  **一条视觉结构断言都没有**。补上 `tests/prototype-parity.test.ts` 后，其中"四屏共有形态"一条
  当场抓出「记录屏正常态漏屏标题」的真 bug。**把口径变成会红的东西**，而不是写在文档里靠自觉。

  因为**改完没跑 `tsc`/测试**，是后续卡才发现的；同类失误在有守卫断言时几秒内就被抓住。
