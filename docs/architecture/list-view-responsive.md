# 列表视图自适应（L2 领域篇）

> **TL;DR**：项目看板「列表」视图是 8 列宽表格，**列宽不由内容决定、而由显式契约决定**——
> 宽度够就全显示，不够就按档让出次要列，再不够就整表横向滚动。
> 三条硬约束：**关键列永不换行**、**操作列按钮永不被压缩**、**markup 恒输出 8 列（隐藏只由 CSS 承担）**。

## 为什么需要它（根因备忘）

| 失效点 | 机理 | 症状 |
|--------|------|------|
| 无列宽下限 | HTML 表格自动算法按 min-content 压列 | 列被压成「一个字一列」 |
| 中文/连字符可断 | CJK 任意字符间、`REQ-xxx-yyy` 连字符处都可断行 | `功能` 竖排、ID 断成 3 行 |
| 操作列可压缩 | 内层按钮组默认可收缩 | `取消` 与 `会话` 叠字 |

触发条件不只是窄窗口：**2x 高分屏下截图宽度 1680px 等价 CSS 宽度仅约 840px**，同样命中。

## 宽度档位契约

```
可用宽度    ≥1180px        880~1179px      720~879px       <720px
          ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────────┐
列        │ 全部 8 列 │   │ 5 列     │   │ 4 列     │   │ 同 4 列 +    │
          │          │   │          │   │          │   │ 整表横向滚动 │
          └──────────┘   └──────────┘   └──────────┘   └──────────────┘
```

| 列（列序） | 类名 | ≥1180 | 880~1179 | <880 |
|---|---|---|---|---|
| 1 ID | —（关键列） | ✓ | ✓ | ✓ |
| 2 标题 | `.dsh-pm-td-title` | ✓ | ✓（解除 380px 上限） | ✓ |
| 3 分类 | `.dsh-pm-col-cat` | ✓ | 隐藏 | 隐藏 |
| 4 状态 | —（关键列） | ✓ | ✓ | ✓ |
| 5 进度 | `.dsh-pm-col-progress` | ✓ | ✓ | 隐藏 |
| 6 负责人 | `.dsh-pm-col-owner` | ✓ | 隐藏 | 隐藏 |
| 7 更新时间 | `.dsh-pm-col-when` | ✓ | 隐藏 | 隐藏 |
| 8 操作 | —（关键列） | ✓ | ✓ | ✓ |

**关键列**（ID / 标题 / 状态 / 操作）在任何宽度都不隐藏。

## 三条不变量

1. **关键列单行**：ID、状态徽章、可见的分类芯片行盒数恒为 1（`white-space: nowrap`，标题列例外）
2. **操作列不被压缩**：按钮组 `flex: none` + `min-width: max-content`，`取消` 与 `会话` 并排或整体让位，**绝不叠字**
3. **markup 恒 8 列**：隐藏由 CSS 断点承担；分组头 `colspan="8"` 不变。好处是宽窄共用同一份 HTML，不需要 JS 监听宽度

## 回归门（改这里前后都要跑）

```bash
# ① 静态断言（秒级，Node 环境）
./node_modules/.bin/vitest run tests/list-responsive.test.ts     # 期望 5 passed

# ② 真实渲染探针（headless Chrome，五档宽度）
npx tsx scripts/list-responsive-probe.mts                        # 期望末行 PROBE PASS，退出码 0
```

探针判定的六件事：关键列行盒数、按钮包围盒相交、操作列是否被压缩、各档可见列数、横向滚动是否只在 <720px 出现、宽档（1680px）是否仍是 8 列且标题列 ≥500px。**改坏保底宽度会让它立刻红**（`PROBE FAIL` + 退出码 1）。

## 与泳道视图的关系

泳道视图早在 2026-09-24 就定了同一条原则——**面板容不下时横向滚动，不把列压扁**。列表视图本次补齐的正是同一条原则：先让位、再滚动，永不压列。
