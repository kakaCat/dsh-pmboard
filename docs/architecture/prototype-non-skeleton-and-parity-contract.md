> 来源：**REQ-261006201649-cc89**（2026-10-06 立项）。上一版契约见
> [原型产物门禁与裁定落账](prototype-gate-and-decision-log.md)（REQ-261005105032-3b02）——
> 本文是它的**续篇**：那一版把「原型有没有交 / 哪一版算数 / 锚点齐不齐」立成了门，
> 本文补上被漏掉的**两问**。
>
> 本文只写**会被别的需求引用**的契约与口径；执行期的裁决与偏差记录留在该需求的
> `design/` 与 `tasks/` 下。

## 0. 为什么要有续篇：三道门都量不到的那两问

上一版契约自己写下过这个警告（[§3](prototype-gate-and-decision-log.md)）：

> **门自己绿了**：产物自动发现（「落进需求目录即产物」）会把落盘骨架补登为 `kind=prototype`。
> 存在门若只按 `kind` 过滤，则**只落骨架、人一个字没填也会全绿**。

当时的补救是**登记口径**（只认显式登记）——它修的是"这份文件算不算交"，
**没有修"交的内容是不是空的"**。实测结果（2026-10-06，全仓 21 份原型逐份比对）：

| 读数 | 值 |
|---|---|
| 与模板 `templates/brainstorming/prototype.html` 行重合率 | 骨架档 **0.957**；真稿档 **0.217–0.391**；中间**无样本** |
| 占据 `authoritative` 位置的空骨架 | **9 条**需求（另有 1 份骨架未被标权威，故不计） |
| 这些骨架当前过锚点门的情况 | **100% 放行**（反向演练实测 `PASS`） |

**为什么骨架必然全绿**：模板自带的示例区块用的是**通用的 `id="FR-1"`**，而 INDEX 骨架
给「服务条款」列填的也正是 **`FR-1`**——任何"只声明了 FR-1"的需求都能靠模板自带的示例区块
通过锚点门。**模板自己给自己发了合格证。**

同一时期的第二个读数：10 条有原型的需求里只有 4 条在验收单上真的对照过——
对照项当时是**按产出条件化**组装的，于是「压根没交原型」与「交了但没人对照」长得一样。

## 1. 三道门不变，锚点门**多两问**

上一版的三门（[§2](prototype-gate-and-decision-log.md)）职责**一字未改**，本文只在
**锚点门**上加两问。判定顺序（顺序本身是判据的一部分）：

```
权威原型文件不存在          → prototype_anchor_missing（点名路径）
  ↓ 存在
① 非骨架判据（本文 §2）      → 命中 ⇒ prototype_placeholder
  ↓ 未命中（或基线不可得）
geometry 块数 ≠ 1 / JSON 坏 → prototype_anchor_missing
  ↓ 恰好一块
serves 列声明的 FR 覆盖      → 缺 ⇒ prototype_anchor_missing
  ↓ 覆盖齐
阈值字段命中（D-10）         → prototype_anchor_missing
  ↓ 无
② 几何量证据（本文 §4）      → invalid ⇒ prototype_geometry_unverified
  ↓ collected / unverified
PASS
```

**为什么非骨架必须最先判**：骨架自带示例 `FR-1` 与示例 geometry 块，天然"锚点齐、块恰好一块"。
放在后面判，人只会看到「锚点缺失」这类**误导性**的码——病因写错了，补救动作也就跟着错。

**为什么合进锚点门而不是新开第四道门**：它回答的仍是「**权威那一份**合格吗」，
与锚点、几何量同属一问；另开一道门会让"同一份文件的不合格"分散到两个码上，
违反「同一处坏只报一次」。

**早退纪律不变**：INDEX 缺失 / 有解析缺口 / `authoritative` 条数 ≠ 1 时，两问都返回
`undefined`（那处坏由版本门报一次）。

| 新码 | HTTP | 中文类别名 | 会话侧传输码 |
|---|---|---|---|
| `prototype_placeholder` | 400 | 原型仍是空骨架 | `REQBOARD_PROTOTYPE_PLACEHOLDER` |
| `prototype_geometry_unverified` | 400 | 几何量读数无法复核 | `REQBOARD_PROTOTYPE_GEOMETRY_UNVERIFIED` |

**新码必须三处齐**（判据 / `http/envelope.ts` 的 `STATUS_BY_CODE` /
`client/toolviews/shared.ts` 的 `ERROR_CATEGORY` + `MoveRequirement` 的传输码表）。
缺 HTTP 状态会**如实落 500**（看板把"流程没满足"显示成"服务器坏了"）；
缺类别名不崩——**降级是沉默**，面板显示英文码原文。

## 2. 非骨架判据：两条独立命中口径

**判据**：`prototypePlaceholderOf(html, skeletonTemplate)`（纯函数，零 IO 零依赖）。
两条判据**任一命中即命中**，且**分开报**（两条坏法的补法不同）：

| 判据 | 口径 |
|---|---|
| ① 占位标记 | 正文含 `SKELETON_PLACEHOLDERS` 任一项（逐字取自骨架正文：`（功能点名）`、`（界面草图区`、`（分支：若…则…）`、`按功能点数量照抄改号`） |
| ② 相似度 | 骨架**去重后的非空行**被本文覆盖的比例 **> 0.90**（严格大于；`=== 0.90` 不命中） |

**归一**：两侧都把 `{{TITLE}}` / `{{REQ_ID}}` / `{{DATE}}` 替换为 `X`、按行 `trim()`、
丢空行后再比。归一必须**两侧同做**，否则"只归一了一边"会得到假的低重合率。

**阈值 0.90 的依据**：实测分布是**双峰**（骨架 0.957 / 真稿 0.217–0.391，中间无样本），
阈值落在峰谷里——**不靠调参**。

**基线不可得时不判**：模板读不出（空串）→ 返回 `undefined`，门放行。
理由是本仓既有口径「读数未知不判」：绝不因为"我没拿到基线"就假红一条需求。

### 已知边界（如实记录，不掩盖）

占位标记只占骨架的少数行。人若把**每一处**标记字面都换掉、行数与缩进照抄，重合率会掉到
**0.870**（阈值之下）而漏过。该读数由 `tests/prototype-placeholder.test.ts` 的一条专门用例锁死：
将来调阈值或改模板时它会先红，逼人重新标定，而不是让边界悄悄漂走。

### 判据不许越界

- 只判**权威那一份**（INDEX 唯一 `authoritative` 行）；`superseded` 旧稿是历史证据，不判；
- 只判"是不是骨架"，**不判**"写得好不好"——内容质量属人的评审，机器不评分；
- **禁止由实现反推原型**（见 [项目说明书](project-manual.md) 机制备忘）：判据量的是
  「实现 == 设计契约」，不是「照实现补一份原型」。

## 3. 对照项是**硬判据**，不再是"有产出才组装"

**变更前**：`prototype-compare` 项按**产出条件化**组装（台账里有已登记 `.html` 原型产物才组装）。
**变更后**：只要 `prototypes/INDEX.md` 有唯一 `authoritative` 行，验收单**必出**该项。

取数口径也随之改变：从「台账里 `.html` 产物按字典序取首项」改为
**读 INDEX 的唯一 `authoritative` 行**——版本门已经保证了"恰好一条"，
验收侧**消费**那条结论，而不是自己再猜一版（同一个事实两处判定必然漂移）。

**降级如实标注**：INDEX 读不出（或缺权威行）时退回台账取数，并在该项的 `criterion` 上写明
「⚠️ 降级读数：未能从 … 取到唯一 authoritative 行」。评审人必须知道这个路径不是从权威清单来的。

**豁免口径一字未动**：`prototype_exempt` 理由非空 **且** requirement 产物已落章 ⇒
仍渲染豁免说明行、**不阻塞**提交。

**⚠️ 顺序上的硬约束（回滚安全性）**：本文 §2 必须先上线，§3 才能上线。
若 §3 先上线，会给「权威原型是骨架」的需求强制生成对照项——**人只能对着骨架打勾**，
那正是本需求要消灭的形态。

## 4. 几何量读数的证据：实测值 + 截图 + 截图 sha256

`StageArtifact.prototypeMeta.geometry[]` 每条观测量**新增两个加性可选键**：
`shot`（截图路径，工作区相对）与 `shotSha256`（该文件内容的 sha256）。

| `shot` | `shotSha256` | 文件存在 | 摘要匹配 | 结论 |
|---|---|---|---|---|
| 缺 | 缺 | — | — | `unverified` —— **放行**（存量口径：历史读数没有截图） |
| 有 | 缺 | — | — | `invalid`（缺 sha256，无法复核） |
| 缺 | 有 | — | — | `invalid`（缺截图路径） |
| 有 | 有 | 否 | — | `invalid`（点名路径） |
| 有 | 有 | 是 | 否 | `invalid`（给期望与实际前 12 位） |
| 有 | 有 | 是 | 是 | `collected` |

**为什么缺两键放行、给一键就严**：一律判违规＝**追溯存量**（本仓有 66 个台账号片、
15 条有原型的历史需求会当场全变红）。存量不追溯是既有纪律；而"新写的读数必须可复核"
是本次要立的规矩。两者用一个判定表同时满足。

**sha256 形态口径**：64 位**十六进制**（大小写都收，比较时统一转小写）。
把大写判成"形态不合法"是格式洁癖冒充判据——它拦不住任何真问题，
只会让照 `shasum` 输出粘贴的人白返工一次。

**端口未装配时不判**：读不到摘要 → `unverified`，不把"我读不到"当"你错了"。

**`needsHuman` 项的理由必须是事实性文本**：含可核对锚点之一（路径 / 截图名 / 命令 / 界面位置）。
纯态度词（`不好看` / `不一致` / `视觉上不对`）→ 拒。判据只回答"有没有给事实"，
**不判**理由是否成立——那是人的事。

## 5. 实现对照判据：从"某条需求的靶子"到"可参数化的通用判据"

`src/domain/prototype/ParityContracts.ts` 的 `prototypeParityViolations(原型HTML, 实现HTML, 契约, 原型引用)`
是通用判据（纯函数），三组契约：

| 契约 | 判据 | 写法 |
|---|---|---|
| `classes` | 每个类名必须在实现 HTML 里出现 | `'dsh-pm-card'`，或 `['契约名', '记号']` |
| `dataAttrs` | 属性名存在；带 `=值域` 时取值必须落在域内 | `'data-result-src=agent\|human\|none'`，或 `['契约名', '记号']` |
| `order` | 按数组顺序做**单调递增**定位 | `['屏标题', 'dsh-pm-set-pane-title']`（两元形态） |

**每条违规必带原型锚点**（`prototypes/<name>.html#FR-N`）——没有锚点的违规等于让人自己猜去哪看。
**一次给全违规**、不是首个即停——改一条又冒一条是"反复返工"的经典成因。
**顺序项找不到 = 违规**，不许静默跳过：跳过会让"顺序"这一维在部件缺失时假装通过。

**配置放被检需求的 `tests/` 侧，不进 `src/`**：判据只许"读原型、量实现"，
配置里要 import 实现侧渲染函数，那是测试的职责；放进 `src/` 会让生产构建带上
"读原型文件"的路径依赖。

**契约不是照原型抄**：原型与实现的命名体系可以不同（本仓实例：原型用裸类名
`agent-box` / `badge`，实现用 `dsh-pm-set-*` 前缀）。契约写的是「实现必须有的形态」，
抄原型字面量只会得到一堆假红——该偏差应**如实记录为待裁定**，而不是让判据假装对齐。

## 6. 反向演练（两条元判据，命令可照抄）

这两条验的**不是功能，而是"判据有没有在量东西"**。改不红 = 判据没接上。

```bash
# 演练 A：骨架占权威位必红 → 换真稿必绿 → 基线不可得则不判
npx vitest run tests/prototype-placeholder-gate.test.ts
#   期望：① 真实骨架三份文件 → code === 'prototype_placeholder'，gaps 点名该路径
#         ② 换成填过的原型     → gate === undefined（放行）
#         ③ 不注入模板基线     → gate === undefined（不判、不假红）

# 演练 B：对照项生成分支退化成旧条件化 → 必须有测试变红
npx vitest run tests/verification-prototype-compare-required.test.ts
#   期望：验收单的 prototypePath === INDEX 权威行（与台账登记路径**故意不同**，
#         退回"按台账字典序取首项"这条断言必红）

# 主判据（含非骨架判据、证据三态、对齐判据）
npx vitest run tests/prototype-*.test.ts tests/plan-prototype-anchor-gate.test.ts
```

## 7. 存量不追溯（本次最大的兼容承诺）

`createdAt < DOC_QUALITY_RULES_SINCE`（`2026-10-06 12:00 UTC`）的需求：

- 非骨架判据与几何量证据**整段不判**（复用既有常量，**不另立日期**）；
- 验收单的对照项取数走**原路**且**不标降级**（"降级"这个标注本身就是新增行为）；
- 既有锚点/几何量判据照旧——**在旧口径下的行为逐字不变**。

已归档的 9 条骨架原型需求**不回填、不重开、不判不健康**：
它们的价值是**证据**（证明这道门此前形同虚设），不是**待办**。

`shot` / `shotSha256` 是**加性可选键**：旧分片缺键 = 未采集 → **不补齐、不改写、无迁移脚本**。
