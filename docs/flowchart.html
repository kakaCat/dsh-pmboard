所有需求流水线推进都经由 pm-goal-round-driver 决策与驱动：八步闸 → goal 相位分支 → 六态动作 → 预留投递准入

① 总览：pm-goal-round-driver 是唯一驱动点

所有触发源（idle / requirement-moved / 心跳 / inbox / turn-end / pre-step）汇入驱动，由它统一决策"该不该跑、跑什么"，避免双驱动双倍投递。

③ drive 分支：预留 → 投递 → 准入（回合子循环）

④ 需求状态机 × goal 驱动：每个阶段一轮 goal 生命周期

一条需求一个当前 goal（挂需求，不挂卡）。每进入一个新阶段，goal 从零开始建 → active 跑回合 → 达成后弹框请人裁决 → 人落章推进到下一阶段。

⑥ goal 生命周期：驱动管相位，人管 resume/done

goal 是全流程管理单元（挂需求，不挂卡）。相位由工具面（reqboard_goal_update）与驱动共同维护；resume 与 stage_goal_done 是真人专属。

⑦ 工具面 × 驱动协作：驱动投回合，工具面收尾

驱动负责"起轮"（投提示词）与"决策"（该不该跑）；工具面负责"收尾注入"（回合结束时 goal 变终态 → deferContext()）。收尾不归驱动（用户裁定 2026-10-10）。

⑧ 故障语义：内存闭锁 + 落盘 block（双保险）

内存闭锁只撑本进程（重启失忆）；落盘 block 让失败人可见、可裁决（resume 是人专属）。两类故障各有归属，不互相覆盖。
