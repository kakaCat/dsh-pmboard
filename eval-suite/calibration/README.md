# 校准样本（calibration/）规范

> `serves: FR-1, FR-3` ｜ 对应设计：design/interfaces.md I-3 节（LLM 评审规程）
> 适用 rubric：task-table / task-report / verification-evidence / archive-truth / kb-citation 五份共用本目录。

## 校准样本的作用

1. **锚定评审 LLM**：每次 LLM 评审时注入 ≥3 条同类样本（好/中/差各至少 1 条），让评审模型对「1 分长什么样、5 分长什么样」有具体参照，避免全凭感觉打分；
2. **检测偏差**：用人工评分做基准，量化评审 LLM 的系统性偏差（偏松/偏紧），为 rubric 回炉提供依据。

## 样本数量与来源

- **总量 ≥10 条**，且**每份 rubric ≥3 条**（评审注入的最低要求），好/中/差分数段都有覆盖；
- **来源**：首轮测评时，人工评审（第三层校准）对产物类用例抽样复核时**顺带产出**——人工给出的评分与理由直接沉淀为样本，不额外增加评审轮次；
- 后续每场测评的人工裁定争议项也可追加进本目录（样本只增不删，回炉后旧样本重新标注或标记作废）。

## 样本格式约定

每条样本一个文件：`calibration/<rubric名>/<序号>-<分数档>.md`（如 `task-table/01-good.md`、`verification-evidence/03-bad.md`），内容四要素：

```markdown
---
rubric: task-table          # 适用 rubric 文件名（不带 .md）
case: C5                    # 来源用例
run_id: run-2026-10-02-01   # 来源测评场次
score_band: good            # good | mid | bad
---

## 产物摘录
（产物的关键片段，≤500 字；全文放 reports/<run-id>/snapshots/ 指针）

## 人工评分
{ "可证伪性": 4, "粒度合理性": 3, "依赖正确性": 5, "说人话": 3, "完整性": 4 }

## 评分理由
（人工评审的判定理由，≤100 字，要点名锚点依据，如"acceptance 缺命令锚点 → 可证伪性 3 分"）
```

- 「人工评分」的维度名与分值必须对应该 rubric 的维度表（1-5 整数）；
- 「评分理由」必须引用 rubric 锚点表述，便于回炉时对照修订；
- 注入评审 prompt 时按 rubric 过滤同目录样本，优先选取与被评产物分数档不同的样本（形成对照）。

## 回炉规则

```
  每场测评后，对每份 rubric：
    偏差 = |LLM 评审均值 − 人工抽样评分均值|
    偏差 > 1 分 → 该 rubric 回炉
```

回炉动作（按序）：

1. **定位偏差方向**：逐维度对比 LLM 分与人工分，找出偏差 >1 的具体维度；
2. **修订锚点表述**：改写该维度的 1/3/5 分锚点，使其更具体可判（常见修法：把形容词换成可观察行为、补正反例、收紧边界条件），修订记录写进该 rubric 文件尾部「修订记录」节；
3. **重新校准**：用本目录现有样本重跑修订后的 rubric，LLM 对样本的评分与人工评分偏差 ≤1 分才算校准完成；
4. **样本回流**：本场新增的人工裁定样本按格式沉淀进本目录。

未回炉的 rubric 若连续两场偏差 ≤1 分，视为稳定，纳入常规使用；回炉后的 rubric 下一场测评必须加大人工抽样比例（≥40%）验证校准效果。
